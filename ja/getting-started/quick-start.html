クイックスタート

削除の前に、安全装置を確認し、スキャンを見て、選んだモードをプレビューしてください。 取り戻せる容量は、このマシンにあるパスとファイルによって変わります。

手順 1 と 2 は飛ばさないでください

かかるのは 2 分ほどですが、自分で把握したうえでのクリーンアップになるか、あとから気づくクリーンアップになるかの分かれ目です。このツールは完全に削除します。

手順 1 — インストールを確認する​

npx linux-cleanup --version
npx linux-cleanup --self-test

--version で手元のビルドを確認します。--self-test は依存関係とシェルの構文を確かめ、安全装置が実際に働くことを検証します。問題がなければ成功メッセージで終わります。失敗が 1 つでもあれば 0 以外の終了コードになるので、そこで止めてください。

手順 2 — 何も削除せずに確認する​

npx linux-cleanup --scan

--scan は読み取り専用です。キャッシュのルートと現在のサイズ、そのほかの候補やシステムの所見を一覧にします。削除はせず、JSON のセッションレポートも書き出しません。

先に進む前にパスを読んでください。キャッシュのルートのサイズは、そのディレクトリ全体が削除対象だという意味ではありません。見覚えのないパスと個人ファイルの候補は、それぞれ確認してください。

手順 3 — クリーンアップをプレビューする​

npx linux-cleanup --all-safe --dry-run

ファイルを削除せず設定も変えずに、完全安全のキャッシュモードをたどります。予定の操作を読んでから、実行するかどうかを決めてください。本番の削除は元に戻せません。

手順 4 — ガイド付きの手順を実行する​

npx linux-cleanup

フラグを付けなければガイド付きの手順になります。10 の手順があり、それぞれ実行前に確認し、取り戻したバイト数の合計を表示します。

各手順では 3 つの選択肢があります。

キー動作
aこの手順を実行（既定。Enter キーで選択）
sこの手順をスキップ
qすぐに手順を終了

手順の中では、対象ごとに [Y/n] の確認があります。つまり、カテゴリーごとスキップするか、カテゴリーは受け入れて個別の項目を断るか、2 段階で選べます。

10 の手順は次の順です。

  1. パッケージマネージャーのキャッシュ
  2. アプリケーションのキャッシュ
  3. 開発ツールのデータ
  4. エディターの古い拡張機能
  5. 使われていない node_modules
  6. 途中の・持ち主のないダウンロード
  7. 使われていない個人ファイル
  8. システムのクリーンアップ（sudo）
  9. 最終的なサイズの確認
  10. 読みやすいレポートの作成
手順 6 と 7 はゆっくり進めてください

それより前のものはすべて再生成できます。途中のダウンロードと使われていない個人ファイルはそうではありません。まとめて受け入れず、候補を 1 件ずつ読んでください。あとで別に見直したい場合は、初回は両方を s でスキップしてもかまいません。

Ctrl-C で手順はコード 130 で止まります。それまでに行った削除は元に戻りません。中断の前にどの手順が実行されたかはログで確認してください。

手順 5 — レポートを読む​

セッションの最後に、ログと（作成された場合は）レポートの場所を示す要約が表示されます。インストール方法ごとに場所が決まっていると思い込まず、自分の実行で表示されたパスを読んでください。

ガイド付きの手順は、--no-report か --dry-run を付けない限り JSON レポートを書き出します。既存のレポートを読みやすい形式や保管用に変換するには、jq をインストールして次を実行します。

linux-cleanup --export both latest   # JSON の隣に Markdown と HTML
linux-cleanup --reports              # 対話式のレポート管理

レポートを参照。

手順 6 — 信頼できたら自動化する​

満足のいく手動実行のあとに限って：

linux-cleanup --install-alias   # どこからでも `cleanup` と入力
linux-cleanup --install-cron    # 毎週日曜 03:00 に --all-safe -y

cron のジョブは --all-safe -y を実行し、再生成できるキャッシュだけを自動で承認します。個人ファイルには触れられません。それらのモードは --yes を無視します。

それぞれが何を書き込み、どう取り除くかはエイリアスと cronを参照してください。

ここまででわかったこと​

考え方詳しく
読み取り専用のモードは削除しない削除前のプレビュー
ガイド付きの手順は各手順の前に確認するガイド付きの手順
許可リストは Documents、.ssh、.config を拒否する安全装置
既定では 100 日以上使われていないファイルだけを間引くアイドルしきい値
個人データのモードは対話式のみ使われていない個人ファイル
ツールから復元できるものはない削除は元に戻せない

  • 「必要なものが消された」 → 復旧
