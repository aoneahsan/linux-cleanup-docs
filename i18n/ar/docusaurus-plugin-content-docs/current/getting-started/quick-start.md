# بداية سريعة

**قبل الحذف: التحقق من الضمانات، ومراجعة الفحص، ومعاينة الوضع المختار.** المساحة المستعادة تتوقف على المسارات والملفات في هذا الجهاز.

:::caution لا تُتخطَّ الخطوتان 1 و2
تستغرقان دقيقتين، وهما الفرق بين تنظيف تحت السيطرة وتنظيف تُكتشف نتائجه لاحقًا. هذه الأداة [تحذف حذفًا دائمًا](../safety/irreversibility.md).
:::

## الخطوة 1 — التحقق من التثبيت {#step-1--verify-the-install}

```bash
npx linux-cleanup --version
npx linux-cleanup --self-test
```

يؤكد `--version` البنية الموجودة. ويفحص `--self-test` الاعتماديات وصياغة الصدفة، ويتحقق من أن الضمانات تعمل فعلًا. ينتهي التشغيل الناجح برسالة نجاح، وأي تحقق فاشل ينتهي برمز غير صفري، وعندها يجب التوقف.

## الخطوة 2 — فحص دون حذف أي شيء {#step-2--audit-deleting-nothing}

```bash
npx linux-cleanup --scan
```

`--scan` للقراءة فقط. يسرد جذور ذاكرة التخزين المؤقت وأحجامها الحالية، مع مرشحات أخرى وملاحظات عن النظام. ولا يحذف ولا يكتب تقرير جلسة بصيغة JSON.

تُقرأ المسارات قبل المتابعة. حجم جذر ذاكرة التخزين المؤقت لا يعني أن المجلد كله مؤهل للحذف. ويُفحص كل مسار غير متوقع وكل ملف شخصي مرشح على حدة.

## الخطوة 3 — معاينة التنظيف {#step-3--preview-the-cleanup}

```bash
npx linux-cleanup --all-safe --dry-run
```

يمر هذا بوضع ذاكرة التخزين المؤقت الآمن بالكامل دون حذف ملفات أو تغيير إعدادات. تُقرأ الإجراءات المقترحة، ثم يُقرَّر التشغيل أو عدمه. ولا تراجع عن الحذف الفعلي.

## الخطوة 4 — تشغيل الجولة الموجّهة {#step-4--run-the-guided-walkthrough}

```bash
npx linux-cleanup
```

دون خيارات تبدأ [الجولة الموجّهة](../modes/walkthrough.md): عشر خطوات، تسأل كل منها قبل أن تفعل شيئًا، مع مجموع متراكم للبايتات المستعادة.

في كل خطوة ثلاثة خيارات:

| المفتاح | الأثر |
|---|---|
| `a` | تشغيل هذه الخطوة (الافتراضي — الضغط على Enter يختاره) |
| `s` | تخطي هذه الخطوة |
| `q` | إنهاء الجولة الآن |

داخل الخطوة، لكل هدف تأكيد `[Y/n]` خاص به. فهناك مستويان: تخطي فئة كاملة، أو قبول الفئة ورفض عناصر بعينها.

الخطوات العشر بالترتيب:

1. ذاكرة مديري الحزم
2. ذاكرة التطبيقات
3. بيانات أدوات المطورين
4. إضافات المحررات القديمة
5. مجلدات `node_modules` المهملة
6. التنزيلات غير المكتملة أو المتروكة
7. الملفات الشخصية المهملة
8. تنظيف النظام (sudo)
9. فحص الحجم النهائي
10. إنشاء تقرير مقروء

:::tip الخطوتان 6 و7 تستحقان التمهل
كل ما قبلهما قابل لإعادة الإنشاء. أما التنزيلات غير المكتملة والملفات الشخصية المهملة فلا — يُقرأ كل مرشح بدلًا من قبول الدفعة كلها. ويمكن تخطي الاثنتين بـ `s` في أول تشغيل لمراجعتهما منفصلتين لاحقًا.
:::

يوقف `Ctrl-C` الجولة بالرمز `130`. وأي حذف سابق يبقى دائمًا. يُقرأ السجل لمعرفة الخطوات التي اكتملت قبل المقاطعة.

## الخطوة 5 — قراءة التقرير {#step-5--read-the-report}

تنتهي الجلسة بملخص يذكر سجلها، وتقريرها إن أُنشئ. تُقرأ المسارات الظاهرة في التشغيل نفسه بدلًا من افتراض موقع ثابت لكل طريقة تثبيت.

تكتب الجولة الموجّهة تقرير JSON ما لم يُمرَّر `--no-report` أو `--dry-run`. ولتحويل تقرير موجود للقراءة أو الأرشفة، يُثبَّت `jq` ويُشغَّل:

```bash
linux-cleanup --export both latest   # Markdown وHTML بجانب ملف JSON
linux-cleanup --reports              # مدير التقارير التفاعلي
```

انظر [التقارير](../modes/reports.md).

## الخطوة 6 — الأتمتة بعد الثقة {#step-6--automate-it-once-you-trust-it}

فقط بعد تشغيل يدوي مُرضٍ:

```bash
linux-cleanup --install-alias   # كتابة `cleanup` من أي مكان
linux-cleanup --install-cron    # --all-safe -y أسبوعيًا، الأحد الساعة 03:00
```

تشغّل مهمة cron الأمر `--all-safe -y`، الذي يؤكد تلقائيًا **ذاكرة التخزين المؤقت القابلة لإعادة الإنشاء فقط**. ولا يستطيع لمس الملفات الشخصية، [فتلك الأوضاع تتجاهل `--yes`](../safety/guards.md#guard-3--personal-data-is-interactive-only).

انظر [الاسم المستعار وcron](../guides/alias-and-cron.md) لمعرفة ما يكتبه كل منهما بالضبط وكيفية إزالته.
