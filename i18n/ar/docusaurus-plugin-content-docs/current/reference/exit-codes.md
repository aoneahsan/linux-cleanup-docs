# رموز الخروج

**يتبع linux-cleanup عُرف Unix: `0` نجاح، وأي شيء آخر مشكلة.** وبعض الرموز غير الصفرية متوقعة ولا تُعامل عن قصد على أنها انهيار.

## الرموز {#codes}

| الرمز | المعنى | حزمة انهيار |
|---|---|---|
| `0` | تشغيل سليم. اكتمل كل إجراء مطلوب أو رُفض | لا |
| `1` | إخفاق عام — خُرق شرط ثابت. نادر | نعم |
| `2` | خطأ في تحليل الوسائط. تُطبع المساعدة | لا |
| `3` | يتطلب سجل الإصدارات العام تحديثًا | لا |
| `127` | الأمر غير موجود — اعتمادية مطلوبة مفقودة | نعم |
| `130` | أُوقف بـ `Ctrl-C` (SIGINT) | لا |
| `137` | قُتل بـ SIGKILL — غالبًا OOM killer أو `kill -9` | نعم |
| `139` | خطأ تجزئة. لا ينبغي أن يحدث في bash الخالص | نعم |
| `143` | أُنهي بـ SIGTERM | لا |
| أي رمز غير صفري آخر | إخفاق داخلي غير متوقع | نعم |

يخرج الخيار غير المعروف بالرمز `2` قبل التنظيف. و`--dry-run` مدعوم؛ فهو يمر بالوضع المختار دون حذف ملفات. انظر [المعاينة قبل الحذف](../safety/preview-first.md).

## كيف يقرر فخ الانهيار {#how-the-crash-trap-decides}

يقيّم فخ EXIT المضاف في [1.3.0](../changelog.md#130--2026-05-10) بهذا الترتيب:

1. رمز الخروج `0`، **أو** ضبط البرنامج النصي علامة الاكتمال الداخلية ← لا حزمة
2. رمز الخروج `130` (`Ctrl-C`) أو `143` (SIGTERM) ← لا حزمة. فالإيقاف الذي يبدأه المستخدم ليس انهيارًا
3. رمز الخروج `2` (تحليل الوسائط) ← لا حزمة. فقد طبع البرنامج النصي المساعدة وتوقف عن قصد
4. أي شيء آخر ← كتابة `crash-<timestamp>.tar.gz` في `~/.linux-cleanup/feedback/`

تحتوي الحزمة على سجل الجلسة النشط وأحدث سجل JSON وبيان نظام قصير. وتبقى على الجهاز — **لا يُرسل شيء**. وتطبع الأداة المسار لمراجعته وتقرير إرساله بالبريد أو لا.

انظر [إرسال تقرير خلل](../guides/send-a-bug-report.md).

## التفرّع حسب الرمز {#branching-on-the-code}

```bash
if linux-cleanup --scan; then
  echo "نجح الفحص"
else
  case $? in
    2)   echo "خيار خاطئ" ;;
    127) echo "اعتمادية مفقودة — شغّل --self-test" ;;
    130) echo "أوقفه المستخدم" ;;
    *)   echo "إخفاق غير متوقع — راجع ~/.linux-cleanup/feedback/" ;;
  esac
fi
```

## في cron {#in-cron}

```bash
linux-cleanup --all-safe -y --no-report --cleanup-logs >>~/.linux-cleanup/logs/cron.log 2>&1 || \
  echo "linux-cleanup exited $?" | mail -s "cleanup failed on $(hostname)" you@example.com
```

يعني الرمز `127` من مهمة cron في الغالب أن crontab استخدم اسم الأمر دون مسار، ولم يجده `PATH` المختصر في cron. يُستخدم مسار مطلق — انظر [استكشاف الأخطاء](../troubleshooting.md#cron-entry-runs-but-does-nothing).

## تشخيص رمز غير متوقع من حزمة انهيار {#diagnosing-an-unexpected-code-from-a-crash-bundle}

يسجّل بيان الحزمة رمز الخروج. والأكثر شيوعًا:

| الرمز | السبب المعتاد |
|---|---|
| `137` | OOM killer عند نفاد الذاكرة. غالبًا أمر `find` على شجرة ضخمة |
| `141` | SIGPIPE — أُغلق أنبوب مبكرًا، غالبًا بخروج `tee` أو أداة تصفح |
| `139` | خطأ تجزئة — لا ينبغي أن يحدث هنا أبدًا؛ يُبلَّغ عنه |
| `127` | اعتمادية مفقودة. يُشغَّل `--self-test` لمعرفتها |
