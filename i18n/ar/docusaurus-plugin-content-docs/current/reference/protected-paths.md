# المسارات المحمية

**هذه هي المسارات التي يرفض linux-cleanup حذفها.** والرفض غير مشروط — لا خيار يتجاوزه، ولا حتى `--purge-all`.

يُحل كل مسار مرشح بـ `realpath` قبل الفحص، فيُرفض الرابط الرمزي الذي يشير إلى مجلد محمي بحسب المسار المحلول لا بحسب الرابط.

:::tip يُتحقق من التثبيت الفعلي بدل الوثوق بهذه الصفحة
تتغير القوائم بين الإصدارات، وتنتشر أوصاف منقولة لهذه الأداة تذكر مجلدات **ليست** محمية فعلًا.

```bash
linux-cleanup --list-targets   # القوائم كما يراها إصدارك
linux-cleanup --self-test      # يتأكد أن الحاجز يعمل على مسارات معروفة
```
:::

## ثلاث قوائم منفصلة {#three-separate-lists}

يتكوّن الحاجز من ثلاث قوائم بقواعد مطابقة مختلفة. والفرق مهم — فهو ما يسمح بتنظيف `~/.npm/_cacache` بينما يبقى `~/.npm` نفسه بعيدًا عن المساس.

| القائمة | تطابق | الغرض |
|---|---|---|
| المسارات المحمية | المسار **وكل ما تحته** | البيانات الشخصية وبيانات الاعتماد والإعدادات |
| المحمية حرفيًا | **ذلك المسار بعينه فقط** | جذور تثبيت مديري الحزم |
| الأسماء المحمية | **أي ملف بهذا الاسم، في أي مكان** | ملفات تهيئة الصدفة والسجل |

## جذور النظام {#system-roots}

تُرفض بوصفها مسارًا أو أي عنصر تحته، إلا حيث يُذكر غير ذلك.

| المسار | يُرفض ما تحته أيضًا |
|---|---|
| `/` | — (الجذر نفسه) |
| `/home` | لا — المسار بعينه فقط |
| `/root` | لا — المسار بعينه فقط |
| `/etc` | **نعم** |
| `/boot` | **نعم** |
| `/usr` | **نعم** |
| `/var` | لا — المسار بعينه فقط |
| `/lib` | لا — المسار بعينه فقط |
| `/sbin` | لا — المسار بعينه فقط |
| `/bin` | لا — المسار بعينه فقط |
| `$HOME` | لا — جذر المجلد الرئيسي نفسه، كي لا يُمسح `$HOME` المجرد أبدًا |

:::note `/proc` و`/sys` ليسا في هذه القائمة
لا يقترب منهما أي هدف تنظيف، لكن القائمة المسموح بها لا تسمّيهما صراحة. وتزعم بعض الأوصاف لهذه الأداة أنها تفعل. وهي لا تفعل.
:::

## المجلدات الشخصية {#personal-directories}

تُرفض مع كل ما بداخلها.

| المسار | يحتوي |
|---|---|
| `~/Documents` | المستندات |
| `~/Pictures` | الصور |
| `~/Music` | الصوت |
| `~/Videos` | الفيديو |
| `~/Desktop` | محتويات سطح المكتب |
| `~/Public` | الملفات المشتركة |
| `~/Templates` | قوالب المستندات |

:::caution `~/Downloads` غير محمي عن قصد
ولا يمكن أن يكون — فتنظيف الملفات الكبيرة الخاملة منذ زمن هناك ميزة ([الملفات الشخصية المهملة](../modes/personal-stale-files.md)). وما يحميه بدلًا من ذلك هو [الحاجز 3](../safety/guards.md#guard-3--personal-data-is-interactive-only): تفاعلي فقط، وتأكيد لكل ملف، وتجاهل `--yes`.

إن كان في `~/Downloads` ما لا يُعوَّض، فيُنقل إلى مجلد محمي. فذلك هو الحل الدائم.
:::

## بيانات الاعتماد والإعدادات وحالة الوكلاء {#credentials-configuration-and-agent-state}

| المسار | يحتوي |
|---|---|
| `~/.ssh` | مفاتيح SSH والمضيفون المعروفون |
| `~/.gnupg` | حلقة مفاتيح GPG |
| `~/.config` | إعدادات التطبيقات (واسعة جدًا) |
| `~/.gnome` | إعدادات GNOME |
| `~/.mozilla` | ملفات تعريف Firefox |
| `~/.thunderbird` | ملفات تعريف Thunderbird |
| `~/.claude` | حالة Claude Code |
| `~/.local/share/claude` | بيانات Claude Code |

:::danger مساران يُدّعى كثيرًا أنهما محميان وهما ليسا كذلك
**`~/.password-store`** (pass) و**`~/.aws`** (بيانات اعتماد AWS) **غير** موجودين في القائمة المحمية في الشيفرة. وتذكر بعض الكتابات عن هذه الأداة أنهما فيها.

عمليًا لا يشير أي هدف تنظيف إلى أيٍّ منهما، فلا خطر عليهما في الاستخدام العادي — لكن لا يُعتمد على القائمة المسموح بها لحمايتهما. ومن يريد هذا الضمان يتحقق أولًا بـ `--list-targets` على تثبيته.
:::

ويُلاحظ أن حماية `~/.mozilla` لا تمنع تنظيف ذاكرة Firefox المؤقتة: فهي في `~/.cache/mozilla`، وهي شجرة أخرى.

## المسارات المحمية بالمطابقة الحرفية {#exact-match-protected-paths}

تُطابق **حرفيًا** — ويبقى ما تحتها قابلًا للتنظيف. وهذا ما يحفظ الحزم المثبّتة عامًا مع السماح بتقليم الذاكرة المؤقتة القابلة للتوليد داخل كل جذر تثبيت.

| المنظومة | المسارات |
|---|---|
| pnpm | `~/.local/share/pnpm` ومجلداته `global`, `bin`, `nodejs` |
| npm | `~/.npm`, `~/.npm-global`, `~/.npm-global/lib`, `~/.npm-global/lib/node_modules` |
| yarn | `~/.yarn`, `~/.config/yarn/global` |
| bun | `~/.bun`, `~/.bun/install`, `~/.bun/install/global` ومجلده `node_modules`, `~/.bun/bin` |
| deno | `~/.deno`, `~/.deno/bin` |
| مديرو إصدارات Node | `~/.volta`, `~/.volta/bin`, `~/.nvm`, `~/.nvm/versions`, `~/.fnm` |
| Rust | `~/.cargo`, `~/.cargo/bin`, `~/.rustup` |
| Go | `~/go`, `~/go/bin` |

توجد هذه القائمة بسبب خلل حقيقي: قبل [1.1.0](../changelog.md#110--2026-05-10) استهدف تنظيف pnpm المسار `~/.local/share/pnpm` — جذر التثبيت — فحذف الحزم المثبّتة عامًا مع ملف `pnpm` التنفيذي نفسه. وضيّق الإصلاح الهدف إلى `~/.local/share/pnpm/store` وأضاف هذه القائمة كي لا يتكرر الخطأ.

ويتحقق [`--all-safe`](../modes/all-safe.md) كذلك عند البدء من أن أيًّا منها لا يظهر في قائمة أهدافه أبدًا، ويتوقف برسالة `BUG:` إن ظهر.

## أسماء الملفات المحمية {#protected-basenames}

تُرفض **بحسب اسم الملف، في أي موضع**، أيًّا كان المسار المؤدي إليه:

`.bashrc` · `.bash_profile` · `.bash_login` · `.profile` · `.bash_logout` · `.zshrc` · `.zshenv` ·
`.zprofile` · `.zlogin` · `.zlogout` · `.bash_aliases` · `.bash_history` · `.zsh_history` · `.inputrc` ·
`.dircolors` · `.config` · `.local`

هذا حاجز أخير. وهو موجود كي لا يستطيع خلل مستقبلي أدخل بطريقة ما ملف تهيئة صدفة في قائمة الأهداف أن يحذفه.

## كيف يبدو الرفض {#what-a-refusal-looks-like}

```text
✗ REFUSE: protected path: /home/you/Documents/notes
✗ REFUSE: unsafe path: '/home/you'
✗ REFUSE: shell-init / history file: /home/you/.bashrc
```

الرفض سلوك صحيح، لا خطأ يُلتف عليه. وإن رُفضت ذاكرة مؤقتة يُراد تنظيفها، فالسبب في الغالب رابط رمزي ينتهي في موضع محمي — يُصلح الرابط لا الأداة. انظر [استكشاف الأخطاء](../troubleshooting.md#refuse-protected-path).
