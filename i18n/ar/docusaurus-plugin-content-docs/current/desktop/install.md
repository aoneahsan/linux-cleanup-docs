# التثبيت والتحديث

يُنزَّل الإصدار الحالي من [صفحة التنزيل](https://linux-cleanup.aoneahsan.com/download)؛ وكل إصدار موجود أيضًا على [GitHub Releases](https://github.com/aoneahsan/linux-cleanup/releases) تحت وسم `desktop-v<version>`. ويحمل كل إصدار مثبّتين:

| الملف | مناسب لـ |
|---|---|
| `linux-cleanup_<version>_amd64.AppImage` | أي توزيعة فيها جلسة سطح مكتب. يُجعل قابلًا للتنفيذ ثم يُشغَّل |
| `linux-cleanup_<version>_amd64.deb` | Debian وUbuntu ومشتقاتهما (`sudo apt install ./linux-cleanup_<version>_amd64.deb`) |

```bash
chmod +x linux-cleanup_*_amd64.AppImage
./linux-cleanup_*_amd64.AppImage
```

منذ الإصدار 1.0.4 يضيف ملف AppImage نفسه إلى قائمة التطبيقات عند أول تشغيل: يكتب `~/.local/share/applications/linux-cleanup-desktop.desktop` وأيقونته تحت `~/.local/share/icons/hicolor/`، ويجعل المدخل يشير إلى مكان الملف أينما كان. وإن نُقل الملف، يكفي تشغيله مرة من مكانه الجديد ليتبعه المدخل. أما `.deb` فيثبّت مدخل القائمة الخاص به.

يحتاج تطبيق سطح المكتب إلى WebKitGTK 4.1 وGTK 3، وهما متوفران في توزيعات سطح المكتب الحالية. ويعلنهما `.deb` اعتمادياتٍ له.

## كيف يتحدث {#how-it-updates}

يحدّث التطبيق نفسه. فهو يبحث عن تحديث موقّع عند البدء، وحين تعود نافذته إلى الظهور، ولحظة نشر إصدار جديد. ومع تفعيل **تثبيت التحديثات تلقائيًا** (الافتراضي) ينزّل التحديث ويتحقق من توقيعه ويعيد التشغيل في لحظة هادئة، لا أثناء تشغيل جارٍ أبدًا.

يُستبدل ملف **AppImage** في مكانه. أما تثبيت **`.deb`** فيتحدث عبر `dpkg`، فيطلب سطح المكتب أولًا كلمة مرور المسؤول (النافذة الرسومية المعتادة)، وإلغاؤها يُبقي الإصدار الحالي عاملًا.

ويمكن أيضًا وسم إصدار بأنه **إلزامي**:

- الإصدار **العاجل** يوقف التطبيق فورًا ويذكر السبب ويعرض زرًا واحدًا: **تحديث**؛
- الإصدار **العادي** يذكر توفر إصدار جديد، ويصبح إلزاميًا من التشغيل التالي.

وإن كان التطبيق دون اتصال عند الفحص فإنه يستمر؛ ولا يمنع فحص فاشل أي تشغيل أبدًا.
