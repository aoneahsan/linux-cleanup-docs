# إرسال تقرير خلل

**أمران يُنتجان كل ما يحتاجه القائم على الصيانة.** لا يُرسل شيء تلقائيًا؛ فالحزمة تُراجَع وتُرسل يدويًا.

```bash
linux-cleanup --debug-bundle    # حزم أحدث سجل وسجل جلسة
linux-cleanup --feedback        # تعليمات ومسودة mailto اختيارية
```

## الطريق السريع {#the-quick-path}

```bash
linux-cleanup --debug-bundle
```

يكتب `~/.linux-cleanup/feedback/debug-bundle-<timestamp>.tar.gz`، ويحتوي على:

- أحدث سجل جلسة
- أحدث سجل جلسة بصيغة JSON، إن وُجد
- ملف `MANIFEST.txt` فيه التوزيعة والنواة وإصدار bash ومخرجات الاختبار الذاتي

ثم:

```bash
linux-cleanup --feedback
```

يذكر ما يُضمَّن، ويعرض فتح مسودة `mailto:` مملوءة مسبقًا بمعلومات النظام.

## مراجعة الحزمة قبل إرسالها {#review-the-bundle-before-sending-it}

:::caution تحتوي الحزمة على مسارات من الجهاز
لا محتوى الملفات، لكن السجل يسمّي كل مسار لُمس، أي أسماء المجلدات والمشاريع، وأحيانًا أسماء ملفات من `~/Downloads`.

تُفحص أولًا:

```bash
tar -tzf ~/.linux-cleanup/feedback/debug-bundle-*.tar.gz     # سرد المحتوى
tar -xzOf ~/.linux-cleanup/feedback/debug-bundle-*.tar.gz    # قراءته كاملًا
```

إن كان فيها شيء حساس، تُستخرج الحزمة ويُحذف الملف أو يُحجب ثم يُعاد ضغطها، أو يُرسل البيان مع الأسطر المهمة فقط.
:::

## حزم الانهيار {#crash-bundles}

منذ [1.3.0](../changelog.md#130--2026-05-10) يكتب الخروج غير المتوقع برمز غير صفري تلقائيًا `crash-<timestamp>.tar.gz` في المجلد نفسه، ويطبع مساره.

وتضم السجل النشط، وأحدث سجل جلسة، وبيانًا للنظام يشمل رمز الخروج.

**لا تُرفع الحزمة إلى أي مكان.** يقرأ فحص الإصدارات ملفًا نصيًا عامًا، لكنه لا يرسل حزمة ولا مسارات محلية. وتبقى الحزمة على القرص إلى أن يُقرر مشاركتها أو لا.

**لا** تُكتب حزم انهيار عند الخروج المتوقع: فالرموز `0` و`130` (`Ctrl-C`) و`143` (SIGTERM) و`2` (خطأ في الوسائط) كلها مستثناة. انظر [رموز الخروج](../reference/exit-codes.md#how-the-crash-trap-decides).

## ما يُضمَّن {#what-to-include}

التقرير الجيد قصير ومحدد:

| يُضمَّن | مثال |
|---|---|
| التوزيعة وإصدارها | `lsb_release -d` |
| إصدار Bash | `bash --version \| head -1` |
| إصدار الأداة | `linux-cleanup --version` |
| الأمر بالضبط | `linux-cleanup --all-safe -y -d 30` |
| المتوقع مقابل ما حدث | «كان المتوقع الإبقاء على Gradle wrapper، لكنه حُذف» |
| الحزمة | إرفاق ملف tar.gz |

أثمن سطر هو **المتوقع مقابل ما حدث**. فالسجل وحده يبيّن ما جرى، لا سبب اعتباره خطأ.

## أخطاء تستحق الإبلاغ فورًا {#bugs-worth-reporting-immediately}

كل ما يخالف نموذج الأمان الموثق:

- حذف داخل [مسار محمي](../reference/protected-paths.md)
- حذف الإصدار *الحالي* لإضافة محرر، لا إصدار قديم فحسب
- حذف ملف أحدث من `--days` دون `--purge-all`
- وضع بيانات شخصية يعمل دون تأكيد
- طلب شبكة يرسل مسارات تنظيف محلية أو تقارير

كل واحد من هذه خرق لنموذج الأمان، لا مجرد إزعاج.

## الخصوصية: ما الذي يغادر الجهاز {#privacy-what-leaves-your-machine}

:::note فحص الإصدارات والتقارير المحلية
عند البدء يقرأ linux-cleanup سجل إصدارات عامًا عبر HTTPS إن توفر الاتصال. ولا يرفع نتائج الفحص أو السجلات أو حزم الانهيار. ويستخدم تثبيت نسخة أو تحديثها npm أو GitHub.

للتحقق على نسخة مستنسخة:

```bash
grep -rE 'curl|wget|http://|https://' cleanup.sh lib/ modules/ bin/
```

يُقرأ `modules/update_check.sh` لمعرفة طلب الإصدارات والأمر المقترح لنسخة أحدث.
:::

السجلات وحزم التصحيح ملفات محلية. ولا يستطيع القائم على الصيانة رؤيتها ولا دفع إصلاح إلى الجهاز؛ فالإصدار الجديد لا يصل إلا عند إعادة تشغيل `npx` أو الترقية.
