# الطبيب

**يعثر `--doctor` على بيئات تشغيل موجودة على القرص لكنها غير موصولة بإعدادات الصدفة، ويعرض إضافة كتلة التهيئة الناقصة.** أُضيف في [1.1.0](../changelog.md#110--2026-05-10).

```bash
linux-cleanup --doctor
```

هذا هو الوضع المناسب حين تظهر `pnpm: command not found` مع أن pnpm مثبت فعلًا.

## إضافة فقط {#additive-only}

:::note لا يحذف Doctor سطرًا موجودًا ولا يعدّله أبدًا
إنه **يضيف** كتلة تهيئة معتمدة، وبعد التأكيد فقط. ولا يعدّل أي شيء موجود في إعدادات الصدفة أو يعيد ترتيبه أو يحذفه.

وملفات تهيئة الصدفة محمية كذلك في طبقة الحذف: يرفض `safe_rm` أي مسار يكون اسم ملفه `.bashrc` أو `.zshrc` أو `.profile` أو `.bash_aliases` أو ما يشبهها، أينما كان. انظر [المسارات المحمية](../reference/protected-paths.md#protected-basenames).
:::

## ما الذي يفحصه {#what-it-checks}

| بيئة التشغيل | يكتشف | يضيف |
|---|---|---|
| `nvm` | وجود `~/.nvm` دون تهيئة `NVM_DIR` | كتلة تحميل nvm المعتمدة |
| `pnpm` | وجود `~/.local/share/pnpm` خارج `PATH` | تصدير `PNPM_HOME` وإضافته إلى `PATH` |
| `bun` | وجود `~/.bun` خارج `PATH` | كتلة تهيئة Bun |
| `deno` | وجود `~/.deno` خارج `PATH` | إضافة Deno إلى `PATH` |
| `cargo` | وجود `~/.cargo` خارج `PATH` | `. "$HOME/.cargo/env"` |

## كيف يحدث هذا عادة {#how-this-usually-happens}

يكتب المثبّت كتلة التهيئة في ملف لا تقرؤه الصدفة. فـ `~/.profile` لا تقرؤه إلا صدفات تسجيل الدخول، ويحجبه `~/.bash_profile` إن وُجد، وتعديل `~/.bashrc` لا يصل أبدًا إلى جلسة `zsh`. فتُثبَّت بيئة التشغيل بنجاح ثم تبدو كأنها اختفت.

ويحدث كذلك بعد نقل مستودع ملفات الإعداد بين الأجهزة، أو بعد تغيير صدفة تسجيل الدخول.

## بعد ذلك {#afterwards}

تُعاد تحميل الصدفة، وإلا فسيبدو أن التغيير لم ينجح:

```bash
source ~/.bashrc     # أو ~/.zshrc
```

ثم يُتحقق:

```bash
command -v pnpm && pnpm --version
```

## علاقته بفحص الحزم العامة {#its-relationship-to-the-globals-audit}

يعمل [`--globals`](./globals-audit.md) حتى حين يغيب مدير الحزم عن `PATH`، إذ يعود إلى فحص نظام الملفات. فإن سرد الفحص حزمًا عامة لـ pnpm بينما لا يوجد `pnpm` نفسه، فالحل هو `--doctor`.
