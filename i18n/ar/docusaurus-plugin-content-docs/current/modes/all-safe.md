# الآمن بالكامل (دفعة واحدة)

**ينظف `--all-safe` كل ذاكرة تخزين مؤقت قابلة لإعادة الإنشاء في مرور واحد.** إنه وضع الصيانة دون إشراف، والوضع الوحيد الذي ينطبق عليه `--yes`.

```bash
linux-cleanup --all-safe        # تأكيد واحد للدفعة كلها
linux-cleanup --all-safe -y     # بلا أسئلة — صيغة cron
```

## ما معنى «آمن» هنا {#what-safe-means-here}

آمن يعني **قابل لإعادة الإنشاء**: ذاكرة مديري الحزم، وذاكرة المتصفحات والتطبيقات، وبيانات أدوات المطورين المهملة. و**لا** يعني بلا مخاطر، ولا قابلًا للتراجع؛ فالحذف ما يزال [دائمًا](../safety/irreversibility.md).

ما لن يلمسه `--all-safe` أبدًا، مع `--yes` أو دونه:

- الملفات الشخصية في `~/Downloads` أو `~/Desktop` أو أي مكان آخر
- التنزيلات غير المكتملة
- مجلدات `node_modules`
- أي شيء في [قائمة المسارات المحمية](../reference/protected-paths.md)
- الحزم المثبتة عالميًا وملفات تهيئة الصدفة

هذه الفئات [تفاعلية فقط بالتصميم](../safety/guards.md#guard-3--personal-data-is-interactive-only)، وليست جزءًا من هذا الوضع أصلًا. ولهذا يكون `--all-safe -y` مقبولًا في مهمة cron.

ومنذ 1.1.0 يشغّل الوضع أيضًا **تحققًا عند البدء** يوقفه برسالة `BUG:` إن تسرّب أي مجلد بيئة تشغيل محمي إلى قائمة أهدافه، فيفشل أي تراجع مستقبلي علنًا بدلًا من حذف ما لا ينبغي.

## `--yes` وحدوده {#--yes-and-its-limits}

يؤكد `-y` / `--yes` حذف ذاكرة التخزين المؤقت تلقائيًا. ولا يصح إلا مع `--all-safe`، وتتجاهله الأوضاع التفاعلية بحكم السياسة.

```bash
linux-cleanup --all-safe -y
```

:::caution مع `-y` لا تظهر القرارات إلا بعد التنفيذ
تبقى قائمة المسارات المسموحة وبوابة الخمول سارية، لكن السجل لا يُراجَع إلا بعد التشغيل. ولا يكتب تشغيل الوضع الآمن بالكامل وحده تقرير جلسة JSON الخاص بالجولة الموجّهة. وفي أول تشغيل يُراجَع أولًا [`--scan`](./scan.md) و`--all-safe --dry-run`.
:::

## التقليم وما يبقى {#pruning-and-what-survives}

افتراضيًا يقلّم `--all-safe` ملفات ذاكرة التخزين المؤقت المؤهلة التي يكون `atime` و`mtime` لها أقدم من `--days` (الافتراضي 100). وتُعامل الحزم المستخرجة والأدوات ذات الإصدارات وحداتٍ كاملة وفق قواعد خمولها. وتعرض المخرجات المقروءة نتائج مختارة؛ ويُستخدم التشغيل التجريبي لمراجعة المسارات المقترحة قبل الحذف.

```bash
linux-cleanup --all-safe -y            # حد 100 يوم
linux-cleanup --all-safe -y -d 30      # أكثر حدة
linux-cleanup --all-safe -y --purge-all # البوابة معطّلة — مسح كامل
```

:::danger `--purge-all` في مهمة cron تركيبة سيئة
العمل دون إشراف ودون بوابة خمول يعني أن توزيعة Gradle wrapper أو حزمة متصفحات Playwright قد تختفي قبل أسبوع من الحاجة إليها، دون أن يلاحظ أحد. يُترك `--purge-all` لتشغيلات مقصودة قبل إعادة تثبيت النظام.
:::

## تشغيله أسبوعيًا {#running-it-weekly}

```bash
linux-cleanup --install-cron
```

يجدول هذا `--all-safe -y` كل أحد الساعة 03:00، ويُلحق المخرجات بالملف `~/.linux-cleanup/logs/cron.log`. المدخل الدقيق وطريقة إزالته في [الاسم المستعار وcron](../guides/alias-and-cron.md).

وعند كتابة مدخل crontab يدويًا يُستخدم **مسار مطلق**؛ إذ لن يجد `PATH` المختصر في cron تثبيتًا في `~/.local/bin`:

```bash
0 3 * * 0 /usr/local/bin/linux-cleanup --all-safe -y --no-report --cleanup-logs >>~/.linux-cleanup/logs/cron.log 2>&1
```

يحذف `--cleanup-logs` سجل ذلك التشغيل. ولا يكتب التشغيل الآمن بالكامل وحده سجل جلسة JSON الخاص بالجولة الموجّهة، فليس لـ `--no-report` أثر إضافي هنا.

## معرفة ما فعله تشغيل cron {#checking-what-a-cron-run-did}

```bash
tail -100 ~/.linux-cleanup/logs/cron.log
```

إن ظهر في سجل cron `command not found`، فإن crontab يستخدم اسم الأمر دون مسار — انظر [استكشاف الأخطاء](../troubleshooting.md#cron-entry-runs-but-does-nothing).
