# تنظيف النظام (sudo)

**يطلب `--system` صلاحيات sudo قبل البدء، ثم يسأل عن كل خطوة من خطوات النظام.** يستخدم `apt` و`dpkg` مباشرة لأعمال الحزم، فالوضع الكامل لـ Debian وUbuntu. وقد تعمل أجزاء سجل النظام أو `/tmp` على توزيعات أخرى، لكن أوامر الحزم ستفشل؛ انظر [دعم التوزيعات](../distro-support.md).

```bash
linux-cleanup --system --dry-run
linux-cleanup --system
```

يطبع التشغيل التجريبي الأوامر المقترحة دون حذف أهداف التنظيف أو تغيير الإعدادات، وقد يكتب مع ذلك سجلًا محليًا وحالة فحص التحديثات. يُراجَع قبل التشغيل الفعلي، الذي لا تراجع عنه.

## الخطوات الست {#the-six-steps}

| الخطوة | ما تشغّله الشيفرة بعد التأكيد | الافتراضي |
|---|---|---|
| apt | `sudo apt autoremove --purge -y`, `sudo apt clean` | نعم |
| سجل النظام | `sudo journalctl --vacuum-size=100M` | نعم |
| Snap | المراجعات المعطّلة المؤهلة عبر `sudo snap remove` | نعم |
| الأنوية | سرد حزم `linux-image-*` المثبتة عبر `dpkg` | لا حذف |
| `/tmp` | `sudo find /tmp -mindepth 1 -atime +7 -delete` | نعم |
| ذاكرة الصفحات | `sudo sync`, `sudo sysctl -q -w vm.drop_caches=3` | لا |

هدف سجل النظام 100 MB وعمر `/tmp` سبعة أيام، ولا يتبع أي منهما `--days`. وتحتفظ خطوة Snap بمراجعة استرجاع معطّلة حتى يبلغ بديلها حد العمر المضبوط، ما لم يُستخدم `--purge-all`. وسرد الأنوية للعلم فقط؛ فقد يحذف apt حزم الأنوية القديمة في خطوته السابقة.

تعتمد خطوة `/tmp` على أوقات الوصول. وإن لم يسجلها نظام الملفات بموثوقية، تتخطى الأداة الحذف حسب العمر. وتفريغ ذاكرة الصفحات يحرر الذاكرة RAM لا القرص، وقد يبطئ القراءات اللاحقة ريثما تمتلئ الذاكرة مجددًا.

## الحدود {#boundaries}

يخزّن الوضع بيانات اعتماد sudo مؤقتًا أثناء عمله ليتمكن من تنفيذ أوامره المنفصلة. ولا يُبدأ تنظيف النظام إلا مع الاستعداد لمراجعة تلك الأوامر. ولـ `--speed` إصلاحات اختيارية منفصلة قد تطلب sudo أيضًا؛ فوضع النظام ليس الطريق الوحيد في سطر الأوامر الذي يستخدم sudo.

تتوقف المساحة المستعادة على الجهاز. وقد يتضمن تغيّر مساحة القرص المقيس بعد التشغيل كتابات عمليات أخرى. يُقرأ السجل لمعرفة الأوامر التي حاولت الأداة تنفيذها.
