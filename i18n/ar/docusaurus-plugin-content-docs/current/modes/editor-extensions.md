# إضافات المحررات

**يحذف `--editor-ext` إصدارات إضافات VS Code وCursor التي حلّ محلها إصدار أحدث.** فعند تحديث إضافة يبقى مجلد الإصدار القديم غالبًا على القرص. وعلى جهاز فيه إضافات كثيرة وتحديثات بضع سنوات، يتراكم ذلك إلى مئات الميغابايتات.

```bash
linux-cleanup --editor-ext
```

## الشرطان {#the-two-conditions}

لا يكون مجلد إصدار مرشحًا إلا إذا تحقق **الشرطان معًا**:

1. **وجود إصدار أحدث من الإضافة نفسها** — والإصدار الحالي لا يكون مرشحًا أبدًا
2. **خمول ذلك الإصدار القديم مدة `--days` أو أكثر** (الافتراضي 100)

أُضيف الشرط الثاني في [1.2.1](../changelog.md#121--2026-05-10). وقبل ذلك كان الاستبدال وحده كافيًا، فكانت تُحذف إصدارات قديمة حُمّلت مؤخرًا. وتعرض المخرجات أيام الخمول لكل إصدار، فيتضح سبب الإبقاء على أي شيء.

## ما لا يلمسه {#what-it-does-not-touch}

- الإصدار الحالي لأي إضافة
- إعدادات الإضافات أو اختصارات لوحة المفاتيح أو حالة مساحة العمل
- أي شيء في `~/.config` — فتلك الشجرة كلها [محمية](../reference/protected-paths.md)
- إضافات محررات غير VS Code وCursor

## بعد تشغيله {#after-running-it}

إن عرض VS Code شريط إضافة مفقودة، تُعاد تحميل النافذة: `Ctrl+Shift+P` ← **Developer: Reload Window**. فالمحرر يحتفظ بإشارة إلى مجلد لم يعد موجودًا.

وإن ذهبت إضافة فعلًا — ما يعني أن اكتشاف «أعلى إصدار» أخطأ في تحديد الإصدار الحالي — يُعاد تثبيتها و[يُبلَّغ عن الخلل](../guides/send-a-bug-report.md):

```bash
code --install-extension <publisher>.<name>
```

## المساحة المتوقعة {#expected-reclaim}

يتوقف الحجم على الإصدارات القديمة المثبتة على هذا الجهاز. يُستخدم الفحص لمراجعة المجلد الحالي قبل تقرير تنظيفه.

## في الجولة الموجّهة والوضع الآمن بالكامل {#in-the-walkthrough-and-all-safe}

يعمل بوصفه الخطوة 4 في [الجولة الموجّهة](./walkthrough.md)، ومشمول في [`--all-safe`](./all-safe.md) لأنه لا يحذف إلا نسخًا قديمة قابلة لإعادة الإنشاء.
