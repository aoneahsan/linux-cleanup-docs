# الاستعادة

**لا تراجع في linux-cleanup.** تتناول هذه الصفحة معرفة ما حُذف، والخيارات المتاحة فعلًا.

:::danger أولًا: التوقف عن الكتابة على القرص
إن حُذف شيء لا يُعوَّض وكانت النية محاولة استعادته بأدوات نحت الملفات، **يجب التوقف عن استخدام نظام الملفات الآن**. فكل كتابة تقلل فرصة استعادة البيانات غير المرتبطة.

ينطبق هذا على [الفئات التي لا تُعوَّض حقًا](#3-decide-what-is-actually-recoverable) فقط. أما ذاكرة التخزين المؤقت فلا داعي لذلك؛ تكفي إعادة جلبها.
:::

## 1. فحص السجل المتاح {#1-inspect-the-available-record}

قد يترك التشغيل سجلًا محليًا. وقد تترك الجولة الموجّهة أيضًا سجل جلسة بصيغة JSON ما لم تُعطَّل التقارير. ولا أحد منهما سجل حذف كامل ملفًا بملف أو نسخة احتياطية.

```bash
# أحدث سجل جلسة
less "$(ls -t ~/.linux-cleanup/logs/cleanup-*.log | head -1)"

# أحدث سجل للجولة الموجّهة إن وُجد
jq '.' "$(ls -t ~/.linux-cleanup/reports/report-*.json | head -1)"
```

للبحث عن مسار بعينه في السجلات المحفوظة:

```bash
grep -rn 'the-filename-you-are-missing' ~/.linux-cleanup/logs/
```

عدم العثور على تطابق لا يثبت أن الأداة لم تلمس ذلك الملف. فقد يُبلغ مساعدٌ عن مجلد ذاكرة كامل أو عن أمر بدلًا من كل ملف، وقد يحذف `--cleanup-logs` سجل تشغيل ما. يُفحص كذلك الوضع المختار وجذور الأهداف.

لحصر النتائج في خطوات جلسة واحدة:

```bash
jq '.steps[] | select(.status == "ran")' \
  "$(ls -t ~/.linux-cleanup/reports/report-*.json | head -1)"
```

## 2. التأكد من أنه لم يكن مجرد رفض {#2-confirm-it-was-not-simply-refused}

يُسجَّل الرفض أيضًا. إن وُجد سطر كهذا، فلم يُحذف شيء:

```text
✗ REFUSE: protected path: /home/you/Documents/notes
```

انظر [المسارات المحمية](./reference/protected-paths.md).

## 3. تحديد ما يمكن استعادته فعلًا {#3-decide-what-is-actually-recoverable}

| ما حُذف | الاستعادة |
|---|---|
| ذاكرة مدير حزم | **تلقائية.** يعيد التثبيت التالي تنزيلها |
| ذاكرة المتصفح | **تلقائية.** تُعاد بناؤها أثناء التصفح |
| ذاكرة Gradle أو توزيعة wrapper | **تلقائية.** يعيد البناء التالي جلبها — مع بناء أول بطيء |
| ملفات Cypress / Playwright التنفيذية | إعادة خطوة التثبيت لتلك الأداة |
| `node_modules` | `yarn install` أو `npm install` في المشروع |
| جهاز Android افتراضي | إعادة إنشائه في Android Studio. **إعدادات الملف التعريفي ذهبت**، وتُعاد تنزيل صورة النظام |
| إصدار إضافة محرر | إعادة تحميل نافذة المحرر، وإعادة التثبيت إن كانت مفقودة فعلًا |
| ذاكرة apt وسجل النظام ومراجعات snap | تُعاد من تلقاء نفسها. لا شيء يلزم |
| **ملف شخصي من `~/Downloads`** | **فقط من نسخة احتياطية خاصة**، أو بإعادة تنزيله من مصدره |
| **تنزيل غير مكتمل** | لا يُستعاد. يُعاد بدء التنزيل |

### إعادة إنشاء الأكثر شيوعًا {#regenerating-the-common-ones}

```bash
# في المشروع المتأثر
yarn install            # أو: npm install / pnpm install

# ملفات أدوات تشغيل الاختبارات
npx cypress install
npx playwright install

# Flutter
flutter pub get
```

لا شيء من هذا يحتاج إلى linux-cleanup، فكل أداة تفعل ما تفعله عادة مع ذاكرة فارغة.

## 4. إن كان لا يُعوَّض حقًا {#4-if-it-was-genuinely-irreplaceable}

واقعيًا، بهذا الترتيب:

1. **النسخة الاحتياطية الخاصة.** Timeshift أو Borg أو restic أو لقطة rsync أو المزامنة السحابية، أيًّا كان المستخدم. وهذه الإجابة الوحيدة الموثوقة.
2. **المصدر الأصلي.** الملف المنزّل يمكن تنزيله مجددًا. يُبحث عن الرابط في سجل المتصفح.
3. **سلة مهملات خدمة المزامنة.** تحتفظ Dropbox وNextcloud وGoogle Drive وما شابهها بالملفات المحذوفة على الخادم مدة معينة. إن كان المجلد متزامنًا، يُبحث هناك.
4. **أدوات نحت الملفات** — `extundelete` و`testdisk` و`photorec`. تعمل على العُقد غير المرتبطة، وفرص نجاحها ضئيلة على نظام ملفات كثير النشاط، خصوصًا أقراص SSD المفعّل فيها TRIM. يُلغى تركيب نظام الملفات أولًا أو يُعمل من قرص USB حي، ولا تُكتب البيانات المستعادة أبدًا على الجهاز نفسه.

:::caution الصراحة بشأن الخطوة 4
على قرص SSD مركّب ومستخدم بنشاط مع TRIM، لا يستعيد النحت عادة شيئًا. ولا يستحق المحاولة إلا لشيء مهم حقًا، وبعد التوقف عن الكتابة على القرص.
:::

## 5. منع تكرار ذلك {#5-stop-it-happening-again}

| التغيير | الأثر |
|---|---|
| تشغيل [`--scan`](./modes/scan.md) قبل كل تنظيف | تظهر النتيجة وهي ما تزال افتراضية |
| نقل الأشياء الثمينة خارج `~/Downloads` | `~/Documents` و`~/Desktop` [محميان](./reference/protected-paths.md) |
| تخطي الخطوة 7 في الجولة | تحتاج الملفات الشخصية حينها إلى تشغيل منفصل مقصود |
| رفع الحد: `-d 365` | لا يصبح مرشحًا إلا ما هو قديم جدًا فعلًا |
| عدم استخدام `-y` خارج `--all-safe` على جهاز موثوق | لا يلمس `-y` البيانات الشخصية، لكن القرارات لا تظهر إلا بعد التنفيذ |
| إعداد نسخ احتياطي حقيقي | الشيء الوحيد الذي يجعل أي حذف قابلًا للاستعادة |

## 6. إن فعلت الأداة ما لا ينبغي {#6-if-the-tool-did-something-it-should-not-have}

إن حدث حذف داخل [مسار محمي](./reference/protected-paths.md)، أو حُذف الإصدار *الحالي* لإضافة محرر، أو حدث أي شيء يخالف الضمانات الموثقة، فهذا خلل يستحق الإبلاغ.

```bash
linux-cleanup --debug-bundle
linux-cleanup --feedback
```

يُرفق السجل وسجل الجولة الموجّهة إن وُجد. انظر [إرسال تقرير خلل](./guides/send-a-bug-report.md).
