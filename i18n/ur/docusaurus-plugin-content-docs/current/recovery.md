# ریکوری

**linux-cleanup میں کوئی واپسی نہیں۔** یہ صفحہ یہ سمجھنے کے بارے میں ہے کہ کیا حذف ہوا اور آپ کے اصل راستے کیا ہیں۔

:::danger پہلے ڈسک پر لکھنا بند کریں
اگر کوئی ناقابل تلافی چیز حذف ہوئی ہے اور آپ فائل کارونگ سے بحال کرنے کی کوشش کرنا چاہتے ہیں، تو **ابھی فائل سسٹم کا استعمال بند کریں**۔ ہر لکھائی ان لنک ہوئے ڈیٹا کو واپس پانے کا امکان کم کرتی ہے۔

یہ صرف [واقعی ناقابل تلافی زمروں](#3-decide-what-is-actually-recoverable) پر لاگو ہوتا ہے۔ کیش کے لیے اسے چھوڑ دیں — بس متعلقہ ٹول کو دوبارہ لانے دیں۔
:::

## 1. دستیاب ریکارڈ دیکھیں {#1-inspect-the-available-record}

ایک رن مقامی لاگ چھوڑ سکتا ہے۔ گائیڈڈ واک تھرو ایک JSON سیشن ریکارڈ بھی چھوڑ سکتا ہے، اگر رپورٹیں بند نہ کی گئی ہوں۔ دونوں میں سے کوئی مکمل فائل بہ فائل حذف کا ریکارڈ یا بیک اپ نہیں۔

```bash
# سب سے حالیہ سیشن لاگ
less "$(ls -t ~/.linux-cleanup/logs/cleanup-*.log | head -1)"

# سب سے نیا واک تھرو ریکارڈ، اگر ہو
jq '.' "$(ls -t ~/.linux-cleanup/reports/report-*.json | head -1)"
```

محفوظ لاگز میں کوئی خاص پاتھ ڈھونڈنے کے لیے:

```bash
grep -rn 'the-filename-you-are-missing' ~/.linux-cleanup/logs/
```

کوئی مطابقت نہ ملنا یہ ثابت نہیں کرتا کہ ٹول نے وہ فائل نہیں چھیڑی۔ کوئی معاون پروگرام ہر فائل کے بجائے پورا کیش فولڈر یا ایک کمانڈ درج کر سکتا ہے، اور `--cleanup-logs` کسی رن کا لاگ حذف کر سکتا ہے۔ چنا گیا موڈ اور ہدف جڑیں بھی دیکھیں۔

ایک سیشن کے مراحل تک محدود کرنے کے لیے:

```bash
jq '.steps[] | select(.status == "ran")' \
  "$(ls -t ~/.linux-cleanup/reports/report-*.json | head -1)"
```

## 2. تصدیق کریں کہ یہ صرف انکار تو نہیں تھا {#2-confirm-it-was-not-simply-refused}

انکار بھی لاگ میں درج ہوتے ہیں۔ اگر ایسی لائن ملے تو کچھ حذف نہیں ہوا:

```text
✗ REFUSE: protected path: /home/you/Documents/notes
```

دیکھیں [محفوظ پاتھس](./reference/protected-paths.md)۔

## 3. طے کریں کہ اصل میں کیا واپس آ سکتا ہے {#3-decide-what-is-actually-recoverable}

| کیا حذف ہوا | ریکوری |
|---|---|
| پیکیج مینیجر کیش | **خود بخود۔** اگلا انسٹال اسے دوبارہ ڈاؤن لوڈ کرتا ہے |
| براؤزر کیش | **خود بخود۔** براؤزنگ کے دوران دوبارہ بنتا ہے |
| Gradle کیش یا wrapper ڈسٹری بیوشن | **خود بخود۔** اگلا بلڈ دوبارہ لاتا ہے — پہلا بلڈ سست ہوگا |
| Cypress / Playwright بائنریز | اس ٹول کا انسٹال مرحلہ دوبارہ چلائیں |
| `node_modules` | پروجیکٹ میں `yarn install` یا `npm install` |
| Android AVD | Android Studio میں دوبارہ بنائیں۔ **پروفائل کی ترتیب جا چکی**؛ سسٹم امیج دوبارہ ڈاؤن لوڈ ہوتی ہے |
| ایڈیٹر ایکسٹینشن ورژن | ایڈیٹر کی ونڈو دوبارہ لوڈ کریں؛ واقعی غائب ہو تو دوبارہ انسٹال کریں |
| apt کیش، جرنل، snap ریویژنز | خود ہی دوبارہ بنتے ہیں۔ کچھ کرنے کی ضرورت نہیں |
| **`~/Downloads` سے ذاتی فائل** | **صرف آپ کے اپنے بیک اپ سے**، یا اصل ذریعے سے دوبارہ ڈاؤن لوڈ |
| **ادھورا ڈاؤن لوڈ** | واپس نہیں آتا۔ ڈاؤن لوڈ دوبارہ شروع کریں |

### عام چیزیں دوبارہ بنانا {#regenerating-the-common-ones}

```bash
# متاثرہ پروجیکٹ میں
yarn install            # یا: npm install / pnpm install

# ٹیسٹ رنرز کی بائنریز
npx cypress install
npx playwright install

# Flutter
flutter pub get
```

ان میں سے کسی کے لیے linux-cleanup کی ضرورت نہیں — آپ بس ہر ٹول کو وہی کرنے دے رہے ہیں جو وہ خالی کیش پر کرتا ہے۔

## 4. اگر واقعی ناقابل تلافی تھا {#4-if-it-was-genuinely-irreplaceable}

حقیقت پسندی سے، ترتیب وار:

1. **آپ کا اپنا بیک اپ۔** Timeshift، Borg، restic، rsync اسنیپ شاٹ، کلاؤڈ سنک — جو بھی آپ استعمال کرتے ہوں۔ یہی واحد قابل اعتماد جواب ہے۔
2. **اصل ذریعہ۔** ڈاؤن لوڈ کی گئی فائل دوبارہ ڈاؤن لوڈ ہو سکتی ہے۔ URL کے لیے براؤزر کی ہسٹری دیکھیں۔
3. **سنک سروس کا ری سائیکل بن۔** Dropbox، Nextcloud، Google Drive اور ان جیسی سروسز حذف شدہ فائلیں کچھ عرصہ سرور پر رکھتی ہیں۔ اگر فولڈر سنک ہوتا تھا تو وہاں دیکھیں۔
4. **فائل کارونگ ٹولز** — `extundelete`، `testdisk`، `photorec`۔ یہ ان لنک ہوئے inodes پر کام کرتے ہیں اور مصروف فائل سسٹم پر، خاص طور پر TRIM والے SSD پر، بہت کم امید رکھتے ہیں۔ پہلے فائل سسٹم ان ماؤنٹ کریں یا live USB سے کام کریں، اور بحال شدہ ڈیٹا کبھی اسی ڈیوائس پر نہ لکھیں۔

:::caution مرحلہ 4 کے بارے میں خود سے ایماندار رہیں
ماؤنٹ شدہ، فعال استعمال والے TRIM والے SSD پر کارونگ سے عموماً کچھ نہیں ملتا۔ یہ صرف واقعی اہم چیز کے لیے آزمانے لائق ہے، اور وہ بھی ڈسک پر لکھنا بند کرنے کے بعد۔
:::

## 5. دوبارہ ہونے سے روکیں {#5-stop-it-happening-again}

| تبدیلی | اثر |
|---|---|
| ہر صفائی سے پہلے [`--scan`](./modes/scan.md) چلائیں | نتیجہ تب دکھتا ہے جب وہ ابھی صرف امکان ہو |
| قیمتی چیزیں `~/Downloads` سے باہر رکھیں | `~/Documents` اور `~/Desktop` [محفوظ](./reference/protected-paths.md) ہیں |
| واک تھرو میں مرحلہ 7 چھوڑیں | پھر ذاتی فائلوں کے لیے سوچا سمجھا الگ رن چاہیے |
| حد بڑھائیں: `-d 365` | صرف واقعی پرانی فائلیں امیدوار بنتی ہیں |
| قابل اعتماد مشین پر `--all-safe` کے علاوہ `-y` کبھی استعمال نہ کریں | `-y` ذاتی ڈیٹا نہیں چھو سکتا، مگر فیصلے آپ کو بعد میں ہی دکھتے ہیں |
| ایک اصل بیک اپ بنائیں | یہی واحد چیز ہے جو کسی بھی حذف کو واپس لانے لائق بناتی ہے |

## 6. اگر ٹول نے وہ کیا جو اسے نہیں کرنا چاہیے تھا {#6-if-the-tool-did-something-it-should-not-have}

اگر کسی [محفوظ پاتھ](./reference/protected-paths.md) کے اندر حذف ہوا، یا ایڈیٹر ایکسٹینشن کا *موجودہ* ورژن حذف ہوا، یا کچھ اور ایسا ہوا جو دستاویز میں بیان کردہ حفاظتی رکاوٹوں کے خلاف ہو — تو یہ رپورٹ کرنے لائق خرابی ہے۔

```bash
linux-cleanup --debug-bundle
linux-cleanup --feedback
```

لاگ اور، اگر ہو تو، واک تھرو ریکارڈ ساتھ دیں۔ دیکھیں [خرابی کی رپورٹ بھیجیں](./guides/send-a-bug-report.md)۔
