# مکمل محفوظ (بیچ)

**`--all-safe` ایک ہی بار میں ہر دوبارہ بن سکنے والا کیش صاف کرتا ہے۔** یہ بغیر نگرانی دیکھ بھال کا موڈ ہے اور واحد موڈ جس پر `--yes` لاگو ہوتا ہے۔

```bash
linux-cleanup --all-safe        # پورے بیچ کے لیے ایک تصدیق
linux-cleanup --all-safe -y     # کوئی سوال نہیں — cron والی صورت
```

## یہاں "محفوظ" کا مطلب {#what-safe-means-here}

محفوظ کا مطلب ہے **دوبارہ بن سکنے والا**: پیکیج مینیجر کیش، براؤزر اور ایپلیکیشن کیش، اور پرانا ڈویلپر ٹول ڈیٹا۔ اس کا مطلب بغیر خطرے کے **نہیں**، اور نہ ہی پلٹنے لائق — حذف پھر بھی [مستقل](../safety/irreversibility.md) ہے۔

`--yes` ہو یا نہ ہو، `--all-safe` انہیں کبھی نہیں چھوتا:

- `~/Downloads`، `~/Desktop` یا کہیں اور کی ذاتی فائلیں
- ادھورے ڈاؤن لوڈز
- `node_modules` فولڈرز
- [محفوظ پاتھس کی فہرست](../reference/protected-paths.md) پر کچھ بھی
- گلوبل انسٹال پیکیجز یا شیل کی ابتدائی فائلیں

یہ زمرے [ڈیزائن کے تحت صرف انٹرایکٹو](../safety/guards.md#guard-3--personal-data-is-interactive-only) ہیں اور اس موڈ کا حصہ ہی نہیں۔ اسی وجہ سے `--all-safe -y` کو cron جاب میں رکھنا قابل قبول ہے۔

1.1.0 سے یہ موڈ ایک **آغاز کی تصدیق** بھی چلاتا ہے جو کسی محفوظ رن ٹائم فولڈر کے ہدف فہرست میں آ جانے پر `BUG:` پیغام کے ساتھ رک جاتی ہے، تاکہ مستقبل کی کوئی خرابی خاموشی سے کچھ غلط حذف کرنے کے بجائے واضح طور پر ناکام ہو۔

## `--yes` اور اس کی حدود {#--yes-and-its-limits}

`-y` / `--yes` کیش حذف کرنے کی خود بخود تصدیق کرتا ہے۔ یہ صرف `--all-safe` کے ساتھ درست ہے؛ انٹرایکٹو موڈز اصولاً اسے نظرانداز کرتے ہیں۔

```bash
linux-cleanup --all-safe -y
```

:::caution `-y` کا مطلب ہے کہ فیصلے آپ کو بعد میں ہی دکھیں گے
اجازت فہرست اور غیر فعالیت کی رکاوٹ پھر بھی لاگو رہتی ہیں، مگر لاگ آپ رن کے بعد دیکھتے ہیں۔ اکیلا مکمل محفوظ رن واک تھرو کی JSON سیشن رپورٹ نہیں لکھتا۔ پہلے رن کے لیے پہلے ایک [`--scan`](./scan.md) اور ایک `--all-safe --dry-run` دیکھیں۔
:::

## چھانٹی، اور کیا بچتا ہے {#pruning-and-what-survives}

ڈیفالٹ طور پر `--all-safe` ان اہل کیش فائلوں کی چھانٹی کرتا ہے جن کا `atime` اور `mtime` دونوں `--days` (ڈیفالٹ 100) سے پرانے ہوں۔ کھولے گئے پیکیجز اور ورژن والے ٹولز اپنے غیر فعالیت کے اصولوں کے تحت پوری اکائی کے طور پر سنبھالے جاتے ہیں۔ پڑھنے والا آؤٹ پٹ منتخب نتائج بتاتا ہے؛ حذف سے پہلے مجوزہ پاتھس دیکھنے کے لیے آزمائشی رن استعمال کریں۔

```bash
linux-cleanup --all-safe -y            # 100 دن کی حد
linux-cleanup --all-safe -y -d 30      # زیادہ سخت
linux-cleanup --all-safe -y --purge-all # رکاوٹ بند — مکمل صفائی
```

:::danger cron جاب میں `--purge-all` برا امتزاج ہے
بغیر نگرانی اور بغیر غیر فعالیت کی رکاوٹ کا مطلب ہے کہ Gradle wrapper ڈسٹری بیوشن یا Playwright براؤزر بنڈل ضرورت سے ایک ہفتہ پہلے غائب ہو سکتا ہے، اور کوئی دیکھ بھی نہیں رہا ہوگا۔ `--purge-all` کو سوچے سمجھے، سسٹم دوبارہ انسٹال کرنے سے پہلے کے رن کے لیے رکھیں۔
:::

## اسے ہر ہفتے چلانا {#running-it-weekly}

```bash
linux-cleanup --install-cron
```

یہ `--all-safe -y` کو ہر اتوار 03:00 بجے کے لیے مقرر کرتا ہے اور آؤٹ پٹ `~/.linux-cleanup/logs/cron.log` میں شامل کرتا ہے۔ صحیح اندراج اور اسے ہٹانے کا طریقہ [ایلیاس اور cron](../guides/alias-and-cron.md) میں دیکھیں۔

اگر crontab اندراج آپ خود لکھیں تو **مکمل پاتھ** استعمال کریں — cron کا مختصر `PATH`، `~/.local/bin` والا انسٹال نہیں ڈھونڈے گا:

```bash
0 3 * * 0 /usr/local/bin/linux-cleanup --all-safe -y --no-report --cleanup-logs >>~/.linux-cleanup/logs/cron.log 2>&1
```

`--cleanup-logs` اس رن کا لاگ حذف کرتا ہے۔ اکیلے مکمل محفوظ رن واک تھرو کا JSON سیشن ریکارڈ نہیں لکھتے، اس لیے یہاں `--no-report` کا مزید کوئی اثر نہیں۔

## cron رن نے کیا کیا، یہ دیکھنا {#checking-what-a-cron-run-did}

```bash
tail -100 ~/.linux-cleanup/logs/cron.log
```

اگر cron لاگ میں `command not found` ہو تو crontab بغیر پاتھ کا کمانڈ نام استعمال کر رہا ہے — دیکھیں [مسائل کا حل](../troubleshooting.md#cron-entry-runs-but-does-nothing)۔
