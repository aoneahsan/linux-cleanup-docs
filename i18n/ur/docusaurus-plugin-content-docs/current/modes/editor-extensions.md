# ایڈیٹر ایکسٹینشنز

**`--editor-ext`، VS Code اور Cursor کے ان ایکسٹینشن ورژنز کو حذف کرتا ہے جن کی جگہ نیا ورژن آ چکا ہو۔** ایکسٹینشن اپ ڈیٹ ہونے پر پرانے ورژن کا فولڈر اکثر ڈسک پر رہ جاتا ہے۔ بہت سی ایکسٹینشنز اور چند سال کی اپ ڈیٹس والی مشین پر یہ سینکڑوں میگا بائٹ بن جاتا ہے۔

```bash
linux-cleanup --editor-ext
```

## دو شرائط {#the-two-conditions}

کوئی ورژن فولڈر تبھی امیدوار ہے جب **دونوں** پوری ہوں:

1. **اسی ایکسٹینشن کا نیا ورژن موجود ہے** — موجودہ ورژن کبھی امیدوار نہیں ہوتا
2. **وہ پرانا ورژن `--days` یا زیادہ دن سے غیر استعمال شدہ ہے** (ڈیفالٹ 100)

دوسری شرط [1.2.1](../changelog.md#121--2026-05-10) میں شامل ہوئی۔ اس سے پہلے صرف نیا ورژن ہونا کافی تھا، جس سے وہ پرانے ورژن بھی حذف ہوتے تھے جو آپ نے حال ہی میں لوڈ کیے تھے۔ آؤٹ پٹ ہر ورژن کے غیر استعمال شدہ دن دکھاتا ہے، تاکہ آپ دیکھ سکیں کہ کچھ کیوں رکھا گیا۔

## یہ کیا نہیں چھوتا {#what-it-does-not-touch}

- کسی بھی ایکسٹینشن کا موجودہ ورژن
- ایکسٹینشنز کی سیٹنگز، کی بائنڈنگز یا ورک اسپیس کی حالت
- `~/.config` میں کچھ بھی — وہ پورا درخت [محفوظ](../reference/protected-paths.md) ہے
- VS Code اور Cursor کے علاوہ کسی اور ایڈیٹر کی ایکسٹینشنز

## چلانے کے بعد {#after-running-it}

اگر VS Code غائب ایکسٹینشن کا بینر دکھائے تو ونڈو دوبارہ لوڈ کریں: `Ctrl+Shift+P` ← **Developer: Reload Window**۔ ایڈیٹر ایسے فولڈر کا حوالہ رکھے ہوئے ہے جو اب نہیں۔

اگر کوئی ایکسٹینشن واقعی جا چکی ہے — یعنی "سب سے نئے ورژن" کی پہچان نے موجودہ کو غلط پہچانا — تو اسے دوبارہ انسٹال کریں اور براہ کرم [خرابی رپورٹ کریں](../guides/send-a-bug-report.md):

```bash
code --install-extension <publisher>.<name>
```

## متوقع بچت {#expected-reclaim}

سائز اس مشین پر انسٹال پرانے ورژنز پر منحصر ہے۔ صاف کرنے کا فیصلہ کرنے سے پہلے موجودہ فولڈر اسکین سے دیکھیں۔
