# گلوبل پیکیجز کی جانچ

**`--globals`، npm، pnpm، yarn، bun اور deno میں آپ کے گلوبل انسٹال پیکیجز کی فہرست دیتا ہے اور ہر ایک پر نشان لگاتا ہے۔** [1.1.0](../changelog.md#110--2026-05-10) میں شامل ہوا۔

```bash
linux-cleanup --globals
linux-cleanup --globals -d 180
```

:::note یہ موڈ کبھی کچھ حذف نہیں کرتا
یہ کاپی پیسٹ کے لائق ان انسٹال کمانڈز دکھا کر رک جاتا ہے۔ کیا چلانا ہے، یہ آپ طے کرتے ہیں۔ گلوبل پیکیجز بالکل وہ چیز ہیں جو اچانک ہٹائے جانے پر کام کا طریقہ توڑ دیتے ہیں، اس لیے ٹول آپ کی جگہ انہیں ہٹانے سے انکار کرتا ہے۔
:::

## فیصلے {#the-verdicts}

| فیصلہ | مطلب |
|---|---|
| **recently used** | `--days` کے اندر بدلا یا استعمال ہوا۔ اسے رہنے دیں |
| **needed by: `<pkg>`** | کوئی اور گلوبل پیکیج اسے انحصار کے طور پر بتاتا ہے۔ اسے ہٹانے سے وہ ٹوٹے گا |
| **STALE — safe to uninstall** | حد سے زیادہ عرصے سے غیر استعمال شدہ اور کچھ بھی اس پر منحصر نہیں |

"ان انسٹال کرنا محفوظ" کا مطلب آپ کی مشین کے دوسرے گلوبل پیکیجز کے نقطہ نظر سے محفوظ ہے۔ یہ کسی شیل اسکرپٹ، CI جاب یا آپ کی کسی عادت کے بارے میں نہیں جان سکتا جو اس بائنری کو چلاتی ہو۔ کچھ کرنے سے پہلے فہرست پڑھیں۔

## یہاں گلوبل پیکیجز کیوں اہم ہیں {#why-global-packages-matter-here}

گلوبل انسٹال پیکیجز کوئی صفائی موڈ **کبھی** حذف نہیں کرتا۔ `~/.local/share/pnpm`، `~/.npm`، `~/.yarn`، `~/.bun/install/global` اور `~/.deno/bin` خاص طور پر انہیں محفوظ رکھنے کے لیے [بالکل مطابقت والی محفوظ فہرست](../reference/protected-paths.md#exact-match-protected-paths) میں ہیں — یہ ایک اصل خرابی کا سبق ہے جس میں pnpm کی صفائی نے انسٹال جڑ کو نشانہ بنا کر گلوبل پیکیجز مٹا دیے تھے۔ دیکھیں [1.1.0](../changelog.md#110--2026-05-10)۔

یہ جانچ اس کا سوچا سمجھا دوسرا رخ ہے: خودکاری کے بغیر نظر آنا۔

## PATH پر پیکیج مینیجرز نہ ہوں تب بھی چلتی ہے {#works-without-the-package-managers-on-path}

ہر مینیجر سے، دستیاب ہو تو اس کے CLI کے ذریعے پوچھا جاتا ہے، اور نہ ہو تو فائل سسٹم دیکھ کر۔ اس لیے جانچ اس مشین پر بھی چلتی ہے جہاں `pnpm` انسٹال تھا مگر ابھی `PATH` پر نہیں — جو اکثر بالکل وہی صورت ہوتی ہے جسے آپ سمجھنا چاہتے ہیں۔

اگر کوئی رن ٹائم ڈسک پر ہے مگر آپ کے شیل سے جڑا نہیں، تو [`--doctor`](./doctor.md) وہ موڈ ہے جو اسے ٹھیک کرتا ہے۔

## اسے چلانے کے اچھے مواقع {#good-moments-to-run-it}

- Node دوبارہ انسٹال کرنے یا ورژن مینیجر بدلنے سے پہلے
- نئی مشین پر جانے سے پہلے — یہ آپ کے ٹولز کی ساتھ لے جانے لائق فہرست ہے
- جب `npm ls -g` کا آؤٹ پٹ پہچان میں نہ آئے
- سال میں ایک دو بار، صفائی ستھرائی کے لیے
