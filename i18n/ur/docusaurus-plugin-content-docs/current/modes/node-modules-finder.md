# پرانے node_modules ڈھونڈیں

**`--node-modules` ان پروجیکٹس میں `node_modules` فولڈرز ڈھونڈتا ہے جنہیں آپ نے `--days` یا زیادہ دن سے نہیں چھوا، اور ہر ایک کو حذف کرنے کی پیشکش کرتا ہے۔** کتنی جگہ ملے گی، یہ اس مشین کے پروجیکٹس پر منحصر ہے۔

```bash
linux-cleanup --node-modules          # ڈیفالٹ 100 دن
linux-cleanup --node-modules -d 90
```

## صرف انٹرایکٹو {#interactive-only}

اس موڈ میں ہر پروجیکٹ کی تصدیق چاہیے اور یہ **`--yes` کو نظرانداز کرتا ہے**۔ یہ [`--all-safe`](./all-safe.md) کا حصہ نہیں اور بغیر نگرانی نہیں چل سکتا۔ دیکھیں [رکاوٹ 3](../safety/guards.md#guard-3--personal-data-is-interactive-only)۔

## یہ کیا ڈھونڈتا ہے {#what-it-looks-for}

یہ آپ کی پروجیکٹ جڑوں میں ایسے `node_modules` فولڈرز اسکین کرتا ہے جن کا پروجیکٹ حد سے زیادہ عرصے سے غیر استعمال شدہ ہو، اور ہر ایک کا سائز اور غیر استعمال شدہ دن بتاتا ہے۔ پہلے سے فہرست میں موجود فولڈر کے اندر کے `node_modules` الگ نہیں گنے جاتے۔

پروجیکٹ جڑیں `$XDG_CONFIG_HOME` (ڈیفالٹ `~/.config`) کے تحت `project-roots.txt` سے ترتیب دی جا سکتی ہیں۔ دیکھیں [ماحولیاتی متغیرات](../reference/environment-variables.md)۔

## یہ عموماً محفوظ کیوں ہے {#why-this-is-usually-safe}

`node_modules` ڈویلپر کی مشین پر سب سے قابل اعتماد طور پر دوبارہ بننے والی چیز ہے — `yarn install` یا `npm install` اسے لاک فائل سے دوبارہ بنا دیتا ہے۔

سب کچھ قبول کرنے سے پہلے جاننے لائق دو باتیں:

:::caution دو طریقے جن سے پھر بھی نقصان ہو سکتا ہے
**پیچ کی گئی ڈیپنڈنسی۔** اگر آپ نے `patch-package` یا yarn پیچ کے بجائے براہ راست `node_modules` کے اندر کوئی فائل بدلی، تو وہ تبدیلی کہیں اور نہیں۔ نہ کسی رجسٹری میں ہے، نہ آپ کی لاک فائل میں۔

**نہ لاک فائل، نہ نیٹ ورک۔** دوبارہ انسٹال کے لیے رجسٹری تک رسائی اور لاک فائل چاہیے۔ بغیر کمٹ شدہ لاک فائل والا پروجیکٹ شاید وہی ڈیپنڈنسی درخت نہ بنائے — اور نیٹ ورک سے کٹی مشین شاید کچھ بھی نہ بنا پائے۔
:::

دونوں عام نہیں، اور ٹول دونوں میں سے کسی کو پہچان نہیں سکتا۔ اگر فہرست کے کسی پروجیکٹ پر ان میں سے کوئی لاگو ہو تو اسے رد کر دیں۔

## یہ کیا نہیں چھوتا {#what-it-does-not-touch}

- پروجیکٹ کا سورس — صرف اس کے اندر کا `node_modules` فولڈر
- لاک فائلیں، `package.json` یا پروجیکٹ کی کوئی اور چیز
- حد کے اندر چھوئے گئے پروجیکٹس
- [محفوظ پاتھس کی فہرست](../reference/protected-paths.md) پر کچھ بھی

## زیادہ زور سے جگہ واپس لینا {#reclaiming-aggressively}

```bash
linux-cleanup --node-modules -d 30
```

حد کم کرنے سے امیدواروں کی فہرست بڑھتی ہے۔ 30 دن پر آپ کو وہ پروجیکٹس نظر آنے لگیں گے جن پر آپ اب بھی کبھی کبھار کام کرتے ہیں، اس لیے سب ایک ساتھ قبول کرنے کے بجائے فہرست پڑھیں — غلطی کی قیمت دوبارہ انسٹال ہے، جو چھوٹی ہے مگر مفت نہیں۔
