# ادھورے / لاوارث ڈاؤن لوڈز

**`--partials` چھوڑی گئی ادھوری ڈاؤن لوڈ فائلیں ڈھونڈتا ہے اور انہیں حذف کرنے کی پیشکش کرتا ہے۔** یہ وہ عارضی فائلیں ہیں جو براؤزر یا ڈاؤن لوڈ مینیجر ٹرانسفر کے دوران لکھتا ہے اور ٹرانسفر رکنے پر صاف کرنا بھول جاتا ہے۔

```bash
linux-cleanup --partials
```

## یہ کیا ڈھونڈتا ہے {#what-it-looks-for}

| ایکسٹینشن | کس نے لکھی |
|---|---|
| `.crdownload` | Chrome، Chromium، Brave، Edge، Vivaldi |
| `.part` | Firefox، wget، aria2 |
| `.fdmdownload` | Free Download Manager |

ادھوری فائل میں اتنے ہی بائٹس ہوتے ہیں جتنے ٹرانسفر رکنے سے پہلے آئے — کبھی چند کلو بائٹ، کبھی کئی گیگا بائٹ کی ISO کا زیادہ تر حصہ۔

## صرف انٹرایکٹو {#interactive-only}

ہر فائل کی تصدیق، `--yes` نظرانداز، [`--all-safe`](./all-safe.md) کا حصہ نہیں۔ دیکھیں [رکاوٹ 3](../safety/guards.md#guard-3--personal-data-is-interactive-only)۔

## ایک حذف کرنے کی قیمت {#what-deleting-one-costs-you}

:::caution ادھوری فائل شاید دوبارہ شروع ہو سکے — مگر عموماً نہیں
دوبارہ شروع کرنے کے لیے اصل ڈاؤن لوڈ سیشن چاہیے: براؤزر کے ڈاؤن لوڈ مینیجر کا اندراج، ماخذ URL، اور ایسا سرور جو رینج کی درخواستیں قبول کرے۔ اگر براؤزر دوبارہ شروع ہو چکا یا ڈاؤن لوڈ کا اندراج صاف ہو چکا، تو ادھوری فائل دوبارہ شروع نہیں ہو سکتی اور خالص ضیاع ہے۔

فائل اپنے آپ میں کبھی کام کی نہیں — آدھا ڈاؤن لوڈ ہوا آرکائیو نہیں کھلتا۔ اس لیے اصل سوال بس اتنا ہے کہ کیا آپ اسے اب بھی دوبارہ شروع کرنا چاہتے ہیں۔
:::

کسی بڑی فائل کو حذف کرنے کی منظوری سے پہلے جانچیں:

- براؤزر کا ڈاؤن لوڈ صفحہ کھولیں اور فائل کے نام سے ملتا رکا ہوا یا ناکام اندراج ڈھونڈیں
- اگر ہو تو ادھوری فائل حذف کرنے کے بجائے وہیں سے دوبارہ شروع کریں
- اگر نہ ہو تو ادھوری فائل لاوارث ہے اور حذف کرنا محفوظ ہے

## جاری ڈاؤن لوڈ بھی یہاں نظر آئے گا {#an-active-download-will-show-up-here}

جو ڈاؤن لوڈ *ابھی* چل رہا ہو اس کی بھی `.crdownload` یا `.part` فائل ہوتی ہے۔ ٹول جاری ٹرانسفر کو چھوڑے ہوئے سے الگ نہیں کر سکتا۔ جاری ادھوری فائل حذف کرنے سے ٹرانسفر ٹوٹ جاتا ہے — اس لیے شک ہو تو ڈاؤن لوڈ صفحہ دیکھیں، یا یہ موڈ تب چلائیں جب کچھ ڈاؤن لوڈ نہ ہو رہا ہو۔
