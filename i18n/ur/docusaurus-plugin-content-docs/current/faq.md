# عام سوالات

کسی خاص علامت والے مسائل [مسائل کا حل](./troubleshooting.md) میں ہیں؛ ڈیزائن کی وجوہات [حفاظتی رکاوٹیں](./safety/guards.md) میں۔

## کیا یہ میرا کوڈ حذف کر دے گا؟ {#will-it-delete-my-code}

**آپ کی سورس فائلیں، نہیں۔** `~/Documents` اور دوسرے ذاتی فولڈرز [مکمل طور پر محفوظ](./reference/protected-paths.md) ہیں، اور کوئی صفائی ہدف کسی پروجیکٹ کے سورس کی طرف نہیں جاتا۔

اس کے سب سے قریب یہ آپ کے پروجیکٹ فولڈرز میں پرانے `node_modules` ڈھونڈتا ہے۔ وہ [صرف انٹرایکٹو](./modes/node-modules-finder.md) ہیں، ہر پروجیکٹ کی تصدیق کے ساتھ، اور `yarn install` انہیں دوبارہ بنا دیتا ہے۔

ایک بات جاننے لائق: اگر آپ نے پیچ ٹول کے بجائے براہ راست `node_modules` *کے اندر* کوئی فائل بدلی، تو وہ تبدیلی کہیں اور موجود نہیں۔

## کیا یہ باہر کچھ بھیجتا ہے؟ {#does-it-phone-home}

**آن لائن ہونے پر CLI شروع میں HTTPS پر ایک عوامی ریلیز ریکارڈ جانچتا ہے۔** یہ اسکین کے نتائج، صفائی کے پاتھس یا کریش بنڈل نہیں بھیجتا۔ آف لائن ہو تو جانچ چھوڑ دی جاتی ہے اور رن جاری رہتا ہے۔

کلون پر خود تصدیق کریں:

```bash
grep -rE 'curl|wget|http://|https://' cleanup.sh lib/ modules/ bin/
```

ریلیز جانچ `modules/update_check.sh` میں ہے؛ وہ فائل بھی دیکھیں۔ انسٹال کرنے یا اپ ڈیٹ قبول کرنے میں npm یا GitHub استعمال ہوتا ہے۔ فیڈبیک معاون ایک مسودہ کھولتا ہے، اسے بھیجنا یا نہ بھیجنا آپ کا فیصلہ ہے۔

## واپسی کیوں نہیں؟ {#why-is-there-no-undo}

واپسی کا لاگ اسی ڈسک پر اضافی لکھائی ہوتا جسے آپ خالی کرنا چاہتے ہیں — 20 GB واپس لینے کے لیے 20 GB رکھنا کچھ حاصل نہیں کرتا۔ یہ جھوٹا اطمینان بھی دیتا، اور زیادہ سے زیادہ ادھورا ہوتا۔

اس کے بجائے حفاظتی ماڈل بچاؤ ہے: اجازت فہرست، غیر فعالیت کی رکاوٹ اور انٹرایکٹو تصدیق۔ پوری وجہ: [حذف مستقل ہے](./safety/irreversibility.md)۔

## کیا `--dry-run` موجود ہے؟ {#is-there-a---dry-run}

**ہاں۔** `--scan` صرف پڑھتا ہے؛ `--dry-run` فائلیں حذف کیے یا سیٹنگز بدلے بغیر چنی ہوئی صفائی سے گزرتا ہے۔ آزمائشی رن پھر بھی مقامی لاگ رکھتا ہے اور JSON سیشن رپورٹ نہیں لکھتا۔ دیکھیں [حذف سے پہلے پری ویو](./safety/preview-first.md)۔

## اسے آزمانے کا سب سے محفوظ طریقہ کیا ہے؟ {#what-is-the-safest-way-to-try-it}

```bash
linux-cleanup --self-test      # تصدیق کرتا ہے کہ رکاوٹیں واقعی چلتی ہیں
linux-cleanup --scan           # صرف پڑھتا ہے؛ دکھاتا ہے کیا واپس ملے گا
linux-cleanup --list-targets   # ہر پاتھ جسے یہ چھو سکتا ہے
linux-cleanup --all-safe --dry-run  # کیش صفائی کا پری ویو
```

ان کے بعد آپ ایک بائٹ کھوئے بغیر حفاظتی ماڈل کو کام کرتے دیکھ چکے ہوں گے۔ پھر `linux-cleanup` چلائیں اور جو بھی حیران کرے اس کا جواب `n` دیں۔

## کیا اس سے میرا کمپیوٹر تیز ہوگا؟ {#will-it-speed-up-my-computer}

تھوڑا، کبھی کبھی، اور ایمانداری سے کہیں تو بہت کم:

- پچاس کے بجائے ایک درجن ایکسٹینشن فولڈرز ہوں تو VS Code کچھ جلدی کھلتا ہے
- ہلکا کیش بھاری کیش سے ذرا جلدی پڑھا جاتا ہے
- براؤزر کے ٹھنڈے آغاز پر کوئی اثر نہیں — کیش کلید و قدر کی صورت ہوتے ہیں، تلاش O(1) ہے
- پیج کیش خالی کرنے سے RAM خالی ہوتی ہے، ڈسک نہیں، اور کرنل اسے فوراً پھر بھر دیتا ہے

اصل فائدہ یہ ہے کہ "ڈسک بھر گئی" آپ کا کام روکنا بند کر دیتی ہے — کوئی بینچ مارک نمبر نہیں۔

## اگر میں صفائی کے بیچ `Ctrl-C` دباؤں تو؟ {#what-if-i-press-ctrl-c-mid-cleanup}

جاری حذف مکمل ہوتا ہے — عموماً ایک سیکنڈ سے بھی کم میں — پھر اسکرپٹ کوڈ `130` کے ساتھ ختم ہوتی ہے۔ لاگ اس لمحے تک سب کچھ رکھتا ہے۔ [کریش ٹریپ جان بوجھ کر `130` کو نظرانداز کرتا ہے](./reference/exit-codes.md)، اس لیے کوئی کریش بنڈل نہیں لکھا جاتا۔

## کیا میں اسے root کے طور پر چلا سکتا ہوں؟ {#can-i-run-it-as-root}

چلا سکتے ہیں، مگر نہیں چلانا چاہیے۔ یہ عام صارف کے طور پر چلنے کے لیے بنا ہے، اور root کے طور پر چلانا صرف تب نقصان کا دائرہ بڑھاتا ہے جب کبھی کوئی خرابی رکاوٹوں سے نکل جائے۔ [`--system`](./modes/system-cleanup.md) جائز sudo ضرورتیں اندر ہی، ایک ایک جانچا ہوا کمانڈ کر کے سنبھالتا ہے۔

## کیا یہ میرے ڈسٹرو پر چلتا ہے؟ {#does-it-work-on-my-distro}

`$HOME` کے اندر کیش کی صفائی **ہر** Linux ڈسٹری بیوشن پر چلتی ہے۔

[`--system`](./modes/system-cleanup.md) **صرف Debian اور Ubuntu** کے لیے ہے — یہ ڈسٹرو پہچانے بغیر `apt` اور `dpkg` چلاتا ہے۔ Fedora، Arch یا openSUSE پر اس کے پیکیج مراحل ناکام ہوتے ہیں، جبکہ جرنل، `/tmp` اور پیج کیش کے مراحل چلتے رہتے ہیں۔ دیکھیں [ڈسٹرو سپورٹ](./distro-support.md)۔

## WSL کا کیا؟ {#what-about-wsl}

CLI، Linux کی طرف چلتا ہے۔ صفائی سے پہلے اپنے Linux ہوم سے `/mnt/c/` کی طرف جانے والا ہر سم لنک دیکھیں۔ اجازت فہرست سم لنکس حل کرتی ہے، مگر Windows کا `Documents` پاتھ خود بخود Linux ہوم کے کسی اصول میں نہیں آتا۔

## Python، Go یا Rust کے بجائے bash کیوں؟ {#why-bash-rather-than-python-go-or-rust}

جن سسٹمز کے لیے یہ بنا ہے ان سب پر Bash پہلے سے موجود ہے۔ کمپائل شدہ بائنری کا مطلب ایسی چیز دینا ہوتا جسے صارفین آسانی سے جانچ نہ سکیں؛ Python یا Node میں بنانے سے اس ٹول پر رن ٹائم انحصار بڑھ جاتا جس کا پورا کام آپ کی ڈسک سے چیزیں ہٹانا ہے۔

اسکرپٹ تبصروں والی چند ہزار لائنوں کی bash ہے جسے ایک تجربہ کار انجینئر ایک دوپہر میں پڑھ سکتا ہے۔ `sudo` دستیاب ہوتے ہوئے `rm -rf` چلانے والے ٹول کے لیے جانچ کے قابل ہونا آسانی سے زیادہ قیمتی ہے۔

## اسے کتنی بار چلانا چاہیے؟ {#how-often-should-i-run-it}

| موڈ | کتنی بار |
|---|---|
| [`--scan`](./modes/scan.md) | مہینے میں ایک بار، بنیاد کے طور پر |
| [`--all-safe -y`](./modes/all-safe.md) | ہر ہفتے — [اسے خودکار بنائیں](./guides/alias-and-cron.md) |
| [`--system`](./modes/system-cleanup.md) | ہر تین ماہ، ہاتھ سے |
| [`--node-modules`](./modes/node-modules-finder.md) | سال میں ایک بار، جب ضمنی پروجیکٹس جمع ہو جائیں |
| [`--editor-ext`](./modes/editor-extensions.md) | جب ایڈیٹر سست لگے — `--all-safe` بھی اسے سنبھالتا ہے |
| [`--stale`](./modes/personal-stale-files.md) | ہر تین ماہ، سوچ سمجھ کر |
| [`--doctor`](./modes/doctor.md) | جب `command not found` نظر آئے |
| [`--globals`](./modes/globals-audit.md) | Node دوبارہ انسٹال کرنے یا مشین بدلنے سے پہلے |

## `--purge-all` کس لیے ہے؟ {#what-is---purge-all-for}

یہ [غیر فعالیت کی رکاوٹ](./safety/guards.md#guard-2--the-staleness-gate) بند کر دیتا ہے، غیر استعمال شدہ فائلیں چھانٹنے کے بجائے کیش پورے صاف کر دیتا ہے۔ اس میں Gradle wrapper ڈسٹری بیوشنز، Playwright براؤزرز اور Cypress بائنریز بھی آتی ہیں جو شاید آپ کو اب بھی چاہئیں۔

مشین دوبارہ انسٹال کرنے سے پہلے یہ درست انتخاب ہے، ورنہ برا ڈیفالٹ۔ اسے کبھی cron جاب کے ساتھ نہ ملائیں۔

## مجھے کون سا ورژن انسٹال کرنا چاہیے؟ {#which-version-should-i-install}

موجودہ شائع شدہ ورژن کے لیے [npm پیکیج](https://www.npmjs.com/package/linux-cleanup) دیکھیں، اور اپنی انسٹال کاپی پہچاننے کے لیے `linux-cleanup --version` چلائیں۔ اپ گریڈ سے پہلے [تبدیلیوں کی فہرست](./changelog.md) دیکھیں۔

## یہ کبھی کیا نہیں کرے گا؟ {#what-will-it-never-do}

- [محفوظ پاتھس کی فہرست](./reference/protected-paths.md) پر کچھ بھی حذف کرنا
- ہر فائل کی تصدیق کے بغیر ذاتی ڈیٹا کو چھونا
- اسکین نتائج، صفائی کے پاتھس یا کریش بنڈل خود بخود اپ لوڈ کرنا
- کوئی سروس، پس منظر کا عمل یا ایجنٹ انسٹال کرنا
- آپ کی شیل ترتیب کی کوئی موجودہ لائن بدلنا یا ہٹانا
- اپنی حذف کی ہوئی کوئی چیز واپس لانا
