# ضروریات

**linux-cleanup، `bash` 4 یا نئے اور GNU coreutils والے Linux پر چلتا ہے۔** باقی سب اختیاری ہے، اور اس کے بغیر بھی ٹول ٹھیک چلتا رہتا ہے۔

## پلیٹ فارم {#platform}

| | |
|---|---|
| **آپریٹنگ سسٹم** | صرف Linux۔ npm پیکیج `"os": ["linux"]` ظاہر کرتا ہے اور کہیں اور انسٹال ہونے سے انکار کرے گا |
| **شیل** | `bash` ≥ 4.0 |
| **Node.js** | ≥ 14 — **صرف** `npx` اور `npm install -g` کے لیے۔ git clone کے لیے ضروری نہیں |
| **اختیارات** | عام صارف کے طور پر چلتا ہے۔ صرف [`--system`](../modes/system-cleanup.md) `sudo` مانگتا ہے |

macOS اور WSL کو الگ سمجھنا بہتر ہے:

- **macOS سپورٹ نہیں۔** پاتھس، `find` کے فلیگز اور پیکیج مینیجرز مختلف ہیں۔ اس کے لیے ایک ساتھی ٹول موجود ہے؛ اسے Mac پر نہ چلائیں۔
- **WSL، Linux کی طرف چلتا ہے۔** صفائی سے پہلے `$HOME` سے `/mnt/c/` کی طرف جانے والا ہر سم لنک دیکھ لیں۔ [اجازت فہرست](../reference/protected-paths.md) سم لنکس حل کرتی ہے، مگر Linux ہوم کے محفوظ پاتھس کا مطلب یہ نہیں کہ Windows کا ہر فولڈر محفوظ ہے۔

## ضروری کمانڈز {#required-commands}

یہ تقریباً ہر عام ڈسٹرو میں موجود ہوتی ہیں: `bash`, `find`, `du`, `df`, `rm`, `awk`, `sort`, `grep`, `sed`, `stat`, `realpath`۔

`realpath` باقیوں سے زیادہ اہم ہے: محفوظ پاتھس کی جانچ سے پہلے سم لنکس یہی حل کرتا ہے۔ GNU coreutils کے بغیر کسی مختصر کنٹینر امیج پر چلانے سے پہلے انہیں انسٹال کریں۔

```bash
npx linux-cleanup --self-test
```

`--self-test` ہر ضروری کمانڈ جانچتا ہے اور پہلی غائب کمانڈ کا نام ٹھیک کرنے کے اشارے کے ساتھ بتاتا ہے۔ کچھ بھی حذف کرنے والا چلانے سے پہلے اسے چلائیں۔

## اختیاری انحصارات {#optional-dependencies}

ہر ایک ایک فیچر کھولتا ہے۔ اس کے بغیر وہ فیچر دستیاب نہیں ہوتا اور ٹول کا باقی حصہ متاثر نہیں ہوتا۔

| انحصار | کیا کھولتا ہے | اس کے بغیر |
|---|---|---|
| `jq` | Markdown / HTML میں [رپورٹ ایکسپورٹ](../modes/reports.md) | JSON رپورٹس پھر بھی لکھی جاتی ہیں؛ تبدیلی دستیاب نہیں |
| `whiptail` | بصری [TUI مینو](../modes/tui.md) | `--tui` انسٹال کے اشارے کے ساتھ CLI مینو پر لوٹ آتا ہے |
| `dialog` | `whiptail` نہ ہو تو TUI کا متبادل | اوپر کی طرح |
| `snap` | `--system` میں بند snap ریویژنز کی صفائی | وہ مرحلہ آرام سے چھوڑ دیا جاتا ہے |
| `crontab` | [ہفتہ وار cron انسٹالر](../guides/alias-and-cron.md) | `--install-cron` نہیں چل سکتا |
| `numfmt` | پڑھنے لائق بائٹ سائز | کچی بائٹ گنتی دکھائی جاتی ہے |
| `xdg-open` | HTML رپورٹس براؤزر میں کھولنا | فائل خود کھولیں |
| `less` | رپورٹس مینیجر میں صفحہ وار JSON | فائل براہ راست پڑھیں |
| `lsb_release` | فیڈبیک بنڈل میں بہتر ڈسٹرو پہچان | بنڈل پھر بھی بنتا ہے |

### اہم دو انسٹال کرنا {#installing-the-two-that-matter}

`jq` (رپورٹ ایکسپورٹ) اور `whiptail` (بصری مینو) وہ دو ہیں جو زیادہ تر لوگ چاہتے ہیں۔

```bash
# Debian / Ubuntu / Mint
sudo apt install jq whiptail

# Fedora / RHEL / Rocky
sudo dnf install jq newt

# Arch / Manjaro
sudo pacman -S jq libnewt

# openSUSE
sudo zypper install jq newt
```

RPM پر مبنی ڈسٹروز پر `whiptail` بائنری `newt` پیکیج میں آتی ہے اور Arch پر `libnewt` میں۔

## ڈسٹرو کوریج {#distro-coverage}

`$HOME` کے اندر کیش کی صفائی — جو اس ٹول سے واپس ملنے والی جگہ کا بڑا حصہ ہے — ہر Linux ڈسٹری بیوشن پر ایک جیسی چلتی ہے۔

:::warning `--system` صرف Debian/Ubuntu کے لیے
sudo موڈ براہ راست `apt` اور `dpkg` چلاتا ہے، نہ ڈسٹرو کی پہچان کرتا ہے نہ کوئی حفاظت۔ Fedora، Arch یا openSUSE پر اس کے پیکیج مراحل "command not found" کے ساتھ ناکام ہوتے ہیں۔

کون سا مرحلہ کہاں چلتا ہے، اس کی پوری تفصیل: [ڈسٹرو سپورٹ](../distro-support.md)۔
:::

## ڈسک پر آؤٹ پٹ {#output-on-disk}

ہر رن ایک مقامی لاگ لکھ سکتا ہے۔ گائیڈڈ واک تھرو JSON رپورٹ بھی لکھ سکتا ہے، اور مانگنے پر یا کسی غیر متوقع ناکامی کے بعد ڈی بگ بنڈل بنتا ہے۔ ان کا سائز رن پر منحصر ہے۔ ترتیب کے لیے [آؤٹ پٹ پاتھس](../reference/output-paths.md) دیکھیں۔
