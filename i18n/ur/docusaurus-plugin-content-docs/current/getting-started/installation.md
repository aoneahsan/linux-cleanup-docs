# انسٹالیشن

**linux-cleanup تین طریقوں سے ملتا ہے: بغیر انسٹال `npx`، گلوبل `npm` انسٹال، یا `git clone`۔** تینوں ایک ہی Bash اسکرپٹ چلاتے ہیں — npm پیکیج بس ایک ہلکا سا Node لانچر ہے جو `cleanup.sh` ڈھونڈتا ہے اور لاگز اور رپورٹس کو ایک مستقل فولڈر کی طرف رکھتا ہے۔

:::info انسٹال شدہ ورژن جانچیں
انسٹال یا اپ گریڈ کے بعد `linux-cleanup --version` چلائیں۔ [تبدیلیوں کی فہرست](../changelog.md) آزمائشی رن اور ریلیز اطلاعات میں ہونے والی تبدیلیاں درج کرتی ہے۔
:::

## طریقہ 1 — `npx`، بغیر انسٹال {#option-1--npx-no-install}

اسے آزمانے کا سب سے تیز طریقہ۔ آپ کے `PATH` پر کچھ نہیں آتا، اور اگر آپ اسے نہ اپنائیں تو پیچھے کچھ نہیں رہتا۔

```bash
npx linux-cleanup --version
npx linux-cleanup --scan      # صرف پڑھنے والی جانچ
npx linux-cleanup             # گائیڈڈ واک تھرو
```

`npx` پیکیج کو npm کیش کے ایک عارضی فولڈر میں لاتا ہے۔ آپ کے لاگز اور رپورٹس `~/.linux-cleanup/` میں لکھے جاتے ہیں — عارضی فولڈر میں **نہیں** — اس لیے npm کیش صاف ہونے پر بھی بچے رہتے ہیں اور اگلی بار بھی موجود ہوتے ہیں۔

## طریقہ 2 — گلوبل `npm` انسٹال {#option-2--global-npm-install}

```bash
npm install -g linux-cleanup
linux-cleanup --version
```

اس کے بعد `linux-cleanup` ہر جگہ آپ کے `PATH` پر ہوتا ہے۔ لاگز اور رپورٹس پھر بھی `~/.linux-cleanup/` میں جاتے ہیں۔

```bash
npm install -g linux-cleanup@latest   # اپ گریڈ
npm uninstall -g linux-cleanup        # ہٹائیں
```

پیکیج ان انسٹال کرنے سے آپ کا لگایا ہوا شیل ایلیاس یا cron اندراج نہیں ہٹتا — مکمل ہٹانے کے لیے [ان انسٹال](../guides/uninstall.md) دیکھیں۔

## طریقہ 3 — `git clone` {#option-3--git-clone}

سورس کوڈ پڑھنے، جانچنے یا بدلنے کے لیے۔ ریپوزٹری کا مواد وہی ہے جو npm پر شائع ہوتا ہے۔

```bash
git clone https://github.com/aoneahsan/linux-cleanup ~/linux-cleanup
cd ~/linux-cleanup
chmod +x cleanup.sh
./cleanup.sh --self-test
./cleanup.sh
```

رویے میں صرف ایک فرق ہے: **کلون اپنا آؤٹ پٹ سورس کے ساتھ رکھتا ہے**، یعنی `<clone>/logs/`، `<clone>/reports/` اور `<clone>/feedback/` میں، `~/.linux-cleanup/` میں نہیں۔ دونوں `LINUX_CLEANUP_DATA_HOME` سے بدلے جا سکتے ہیں۔ دیکھیں [آؤٹ پٹ پاتھس](../reference/output-paths.md)۔

پروجیکٹ MIT لائسنس کے تحت ہے، اس لیے فورک اور تبدیلیاں ٹھیک ہیں۔

## کچھ بھی حذف کرنے والا چلانے سے پہلے جانچیں {#verify-before-you-run-anything-destructive}

```bash
linux-cleanup --version      # تصدیق کرتا ہے کہ آپ کے پاس اصل میں کون سا بلڈ ہے
linux-cleanup --self-test    # انحصار، سنٹیکس اور حفاظتی جانچ
```

کامیاب خود جانچ ایک کامیابی کے پیغام پر ختم ہوتی ہے۔ یہ تصدیق کرتی ہے کہ [محفوظ پاتھس کی حفاظت](../safety/guards.md#guard-1--the-path-allowlist) واقعی `/`، `$HOME`، `~/Documents`، `~/.ssh` اور `/etc` کو رد کرتی ہے، اور `~/.cache/yarn` کو رد نہیں کرتی۔ کوئی بھی تصدیق ناکام ہو تو غیر صفر کوڈ کے ساتھ ختم ہوتی ہے۔

:::tip ہر اپ گریڈ کے بعد `--self-test` چلائیں
یہی واحد جانچ ہے جو دستاویزات پر نہیں بلکہ آپ کے پاس موجود اصل کوڈ پر چلتی ہے۔ اس میں ایک سیکنڈ لگتا ہے۔
:::

## کون سا طریقہ چنیں {#which-install-path-to-choose}

| اگر آپ… | استعمال کریں |
|---|---|
| ایک بار آزمانا چاہتے ہیں | `npx` |
| اسے باقاعدگی سے یا cron سے چلائیں گے | گلوبل `npm` انسٹال |
| سورس پڑھنا یا بدلنا چاہتے ہیں | `git clone` |
| ایسی مشین پر ہیں جس میں Node.js نہیں | `git clone` |
| آؤٹ پٹ سورس کے ساتھ چاہیے | `git clone` |

cron کے لیے گلوبل انسٹال بہتر ہے اور crontab میں **مکمل پاتھ** استعمال کریں — cron بہت مختصر `PATH` کے ساتھ چلتا ہے اور `~/.local/bin` والا انسٹال نہیں ڈھونڈ پائے گا۔ یہ cron کا سب سے عام مسئلہ ہے؛ دیکھیں [ایلیاس اور cron](../guides/alias-and-cron.md)۔

## انسٹال کرنا کیا نہیں کرتا {#what-installing-does-not-do}

- کوئی سسٹم سروس، پس منظر میں چلنے والا عمل یا شیڈول کام نہیں (جب تک آپ نہ مانگیں)
- کوئی ٹیلیمیٹری ایجنٹ نہیں۔ شروع ہونے پر، آن لائن ہو تو CLI ایک عوامی ریلیز ریکارڈ لاتا ہے؛ آف لائن ہو تو چلتا رہتا ہے
- جب تک آپ `--install-alias` یا `--doctor` نہ چلائیں، شیل کی ترتیب میں کوئی تبدیلی نہیں
- پیکیج اور `~/.linux-cleanup/` کے باہر کوئی فائل نہیں، اور دوسرا بھی تبھی بنتا ہے جب آپ اسے واقعی چلاتے ہیں
