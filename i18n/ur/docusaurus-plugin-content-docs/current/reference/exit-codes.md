# ایگزٹ کوڈز

**linux-cleanup، Unix کی روایت پر چلتا ہے: `0` کامیابی ہے، اس کے علاوہ کچھ بھی مسئلہ ہے۔** کچھ غیر صفر کوڈز متوقع ہیں اور جان بوجھ کر کریش نہیں سمجھے جاتے۔

## کوڈز {#codes}

| کوڈ | مطلب | کریش بنڈل |
|---|---|---|
| `0` | صاف رن۔ ہر مانگی گئی کارروائی مکمل ہوئی یا رد کی گئی | نہیں |
| `1` | عمومی ناکامی — کوئی لازمی شرط ٹوٹی۔ کم ہوتا ہے | ہاں |
| `2` | آرگیومنٹ پڑھنے کی خرابی۔ مدد دکھائی جاتی ہے | نہیں |
| `3` | عوامی ریلیز ریکارڈ نے اپ ڈیٹ لازمی قرار دی | نہیں |
| `127` | کمانڈ نہیں ملی — کوئی ضروری انحصار غائب ہے | ہاں |
| `130` | `Ctrl-C` (SIGINT) سے روکا گیا | نہیں |
| `137` | SIGKILL سے ختم کیا گیا — عموماً OOM killer یا `kill -9` | ہاں |
| `139` | سیگ فالٹ۔ خالص bash میں نہیں ہونا چاہیے | ہاں |
| `143` | SIGTERM سے بند کیا گیا | نہیں |
| کوئی اور غیر صفر | غیر متوقع اندرونی ناکامی | ہاں |

انجان فلیگ صفائی سے پہلے `2` کے ساتھ ختم ہوتا ہے۔ `--dry-run` سپورٹ ہے؛ یہ فائلیں حذف کیے بغیر چنے ہوئے موڈ سے گزرتا ہے۔ دیکھیں [حذف سے پہلے پری ویو](../safety/preview-first.md)۔

## کریش ٹریپ کیسے فیصلہ کرتا ہے {#how-the-crash-trap-decides}

[1.3.0](../changelog.md#130--2026-05-10) میں شامل EXIT ٹریپ اس ترتیب سے جانچتا ہے:

1. ایگزٹ کوڈ `0` ہے، **یا** اسکرپٹ نے اپنا اندرونی تکمیل کا نشان لگایا → کوئی بنڈل نہیں
2. ایگزٹ کوڈ `130` (`Ctrl-C`) یا `143` (SIGTERM) ہے → کوئی بنڈل نہیں۔ صارف کا روکنا کریش نہیں
3. ایگزٹ کوڈ `2` (آرگیومنٹ پڑھنا) ہے → کوئی بنڈل نہیں۔ اسکرپٹ نے مدد دکھا کر جان بوجھ کر روکا
4. باقی سب → `crash-<timestamp>.tar.gz` کو `~/.linux-cleanup/feedback/` میں لکھیں

بنڈل میں موجودہ سیشن لاگ، حالیہ ترین JSON ریکارڈ اور ایک مختصر سسٹم مینی فیسٹ ہوتا ہے۔ یہ آپ کی مشین پر رہتا ہے — **کچھ نہیں بھیجا جاتا**۔ ٹول پاتھ دکھاتا ہے تاکہ آپ اسے دیکھ کر طے کر سکیں کہ ای میل کرنا ہے یا نہیں۔

دیکھیں [خرابی کی رپورٹ بھیجیں](../guides/send-a-bug-report.md)۔

## کوڈ کی بنیاد پر شاخ {#branching-on-the-code}

```bash
if linux-cleanup --scan; then
  echo "اسکین کامیاب رہا"
else
  case $? in
    2)   echo "غلط فلیگ" ;;
    127) echo "انحصار غائب — --self-test چلائیں" ;;
    130) echo "صارف نے روکا" ;;
    *)   echo "غیر متوقع ناکامی — ~/.linux-cleanup/feedback/ دیکھیں" ;;
  esac
fi
```

## cron میں {#in-cron}

```bash
linux-cleanup --all-safe -y --no-report --cleanup-logs >>~/.linux-cleanup/logs/cron.log 2>&1 || \
  echo "linux-cleanup exited $?" | mail -s "cleanup failed on $(hostname)" you@example.com
```

cron جاب سے ایگزٹ کوڈ `127` کا مطلب تقریباً ہمیشہ یہ ہوتا ہے کہ crontab نے بغیر پاتھ کا کمانڈ نام استعمال کیا اور cron کا مختصر `PATH` اسے نہ ڈھونڈ سکا۔ مکمل پاتھ استعمال کریں — دیکھیں [مسائل کا حل](../troubleshooting.md#cron-entry-runs-but-does-nothing)۔

## کریش بنڈل سے غیر متوقع کوڈ کی تشخیص {#diagnosing-an-unexpected-code-from-a-crash-bundle}

بنڈل کا مینی فیسٹ ایگزٹ کوڈ درج کرتا ہے۔ عام کوڈز:

| کوڈ | عام وجہ |
|---|---|
| `137` | میموری ختم ہونے پر OOM killer۔ عموماً کسی بہت بڑے درخت پر `find` |
| `141` | SIGPIPE — کوئی پائپ جلدی بند ہوا، اکثر `tee` یا پیجر کے ختم ہونے سے |
| `139` | سیگ فالٹ — یہاں کبھی نہیں ہونا چاہیے؛ رپورٹ کریں |
| `127` | انحصار غائب۔ پہچاننے کے لیے `--self-test` چلائیں |
