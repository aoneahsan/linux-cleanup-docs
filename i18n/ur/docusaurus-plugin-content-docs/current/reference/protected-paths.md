# محفوظ پاتھس

**یہ وہ پاتھس ہیں جنہیں linux-cleanup حذف کرنے سے انکار کرتا ہے۔** انکار غیر مشروط ہے — کوئی فلیگ اسے نہیں بدلتا، `--purge-all` بھی نہیں۔

جانچ سے پہلے ہر امیدوار `realpath` سے حل کیا جاتا ہے، اس لیے کسی محفوظ فولڈر کی طرف اشارہ کرنے والا سملنک لنک کی بجائے حل شدہ پاتھ کی بنیاد پر رد ہوتا ہے۔

:::tip اس صفحے پر بھروسا کرنے کے بجائے اپنے انسٹال سے تصدیق کریں
فہرستیں ورژنز کے درمیان بدلتی ہیں، اور اس ٹول کے بارے میں ایسی سنی سنائی تفصیلات گردش کرتی ہیں جن میں وہ فولڈرز بھی ہیں جو اصل میں محفوظ **نہیں**۔

```bash
linux-cleanup --list-targets   # فہرستیں جیسی آپ کا بلڈ دیکھتا ہے
linux-cleanup --self-test      # تصدیق کرتا ہے کہ رکاوٹ معلوم پاتھس پر کام کرتی ہے
```
:::

## تین الگ فہرستیں {#three-separate-lists}

رکاوٹ تین فہرستوں سے بنی ہے جن کے ملان کے اصول الگ ہیں۔ یہ فرق اہم ہے — اسی سے `~/.npm/_cacache` صاف ہو پاتا ہے جبکہ خود `~/.npm` ناقابلِ رسائی رہتا ہے۔

| فہرست | ملان | مقصد |
|---|---|---|
| محفوظ پاتھس | پاتھ **اور اس کے نیچے سب کچھ** | ذاتی ڈیٹا، اسناد، کنفیگریشن |
| بالکل محفوظ | **صرف وہی پاتھ** | پیکیج مینیجرز کے انسٹال روٹس |
| محفوظ نام | **اس نام کی کوئی بھی فائل، کہیں بھی** | شیل-انٹ اور ہسٹری فائلیں |

## سسٹم روٹس {#system-roots}

پاتھ کے طور پر یا اس کے کسی بھی اندرونی حصے کے طور پر رد، سوائے جہاں الگ لکھا ہو۔

| پاتھ | اندر کا حصہ بھی رد |
|---|---|
| `/` | — (خود روٹ) |
| `/home` | نہیں — صرف وہی پاتھ |
| `/root` | نہیں — صرف وہی پاتھ |
| `/etc` | **ہاں** |
| `/boot` | **ہاں** |
| `/usr` | **ہاں** |
| `/var` | نہیں — صرف وہی پاتھ |
| `/lib` | نہیں — صرف وہی پاتھ |
| `/sbin` | نہیں — صرف وہی پاتھ |
| `/bin` | نہیں — صرف وہی پاتھ |
| `$HOME` | نہیں — خود ہوم روٹ، تاکہ اکیلا `$HOME` کبھی صاف نہ ہو |

:::note `/proc` اور `/sys` اس فہرست میں نہیں
کوئی صفائی ہدف ان کے قریب بھی نہیں جاتا، مگر اجازت فہرست ان کا نام واضح طور پر نہیں لیتی۔ اس ٹول کی کچھ تفصیلات کہتی ہیں کہ لیتی ہے۔ ایسا نہیں۔
:::

## ذاتی فولڈرز {#personal-directories}

اندر کی ہر چیز سمیت رد۔

| پاتھ | کیا رکھتا ہے |
|---|---|
| `~/Documents` | دستاویزات |
| `~/Pictures` | تصاویر |
| `~/Music` | آڈیو |
| `~/Videos` | ویڈیو |
| `~/Desktop` | ڈیسک ٹاپ کا مواد |
| `~/Public` | مشترکہ فائلیں |
| `~/Templates` | دستاویز کے سانچے |

:::caution `~/Downloads` جان بوجھ کر محفوظ **نہیں**
ہو بھی نہیں سکتا — وہاں کی بڑی، دیر سے پڑی فائلیں صاف کرنا ایک خصوصیت ہے ([پرانی ذاتی فائلیں](../modes/personal-stale-files.md))۔ اس کی حفاظت [رکاوٹ 3](../safety/guards.md#guard-3--personal-data-is-interactive-only) کرتی ہے: صرف انٹرایکٹو، ہر فائل کی تصدیق، اور `--yes` نظرانداز۔

اگر آپ `~/Downloads` میں کچھ ایسا رکھتے ہیں جس کا کوئی بدل نہیں، تو اسے کسی محفوظ فولڈر میں منتقل کریں۔ یہی پائیدار حل ہے۔
:::

## اسناد، کنفیگریشن اور ایجنٹ کی حالت {#credentials-configuration-and-agent-state}

| پاتھ | کیا رکھتا ہے |
|---|---|
| `~/.ssh` | SSH کلیدیں اور معلوم ہوسٹس |
| `~/.gnupg` | GPG کی رنگ |
| `~/.config` | ایپلی کیشن کنفیگریشن (بہت وسیع) |
| `~/.gnome` | GNOME سیٹنگز |
| `~/.mozilla` | Firefox پروفائلز |
| `~/.thunderbird` | Thunderbird پروفائلز |
| `~/.claude` | Claude Code کی حالت |
| `~/.local/share/claude` | Claude Code کا ڈیٹا |

:::danger دو پاتھس جنہیں اکثر محفوظ کہا جاتا ہے، محفوظ **نہیں**
**`~/.password-store`** (pass) اور **`~/.aws`** (AWS اسناد) سورس کی محفوظ فہرست میں **نہیں** ہیں۔ اس ٹول کے بارے میں کچھ تحریریں کہتی ہیں کہ ہیں۔

عملاً کوئی صفائی ہدف ان کی طرف اشارہ نہیں کرتا، اس لیے عام استعمال میں دونوں کو خطرہ نہیں — مگر ان کی حفاظت کے لیے اجازت فہرست پر بھروسا نہ کریں۔ یہ ضمانت چاہیے تو پہلے اپنے انسٹال پر `--list-targets` سے تصدیق کریں۔
:::

دھیان رہے کہ `~/.mozilla` کے محفوظ ہونے سے Firefox کیش کی صفائی نہیں رکتی: کیش `~/.cache/mozilla` میں ہے، جو الگ درخت ہے۔

## بالکل ملان والے محفوظ پاتھس {#exact-match-protected-paths}

**بالکل** ملان — اندر کا حصہ صاف کیا جا سکتا ہے۔ اسی سے آپ کے گلوبل انسٹال پیکیجز بچے رہتے ہیں، جبکہ ہر انسٹال روٹ کے اندر کا دوبارہ بن سکنے والا کیش چھانٹا جا سکتا ہے۔

| ایکو سسٹم | پاتھس |
|---|---|
| pnpm | `~/.local/share/pnpm` اور اس کے `global`, `bin`, `nodejs` |
| npm | `~/.npm`, `~/.npm-global`, `~/.npm-global/lib`, `~/.npm-global/lib/node_modules` |
| yarn | `~/.yarn`, `~/.config/yarn/global` |
| bun | `~/.bun`, `~/.bun/install`, `~/.bun/install/global` اور اس کا `node_modules`, `~/.bun/bin` |
| deno | `~/.deno`, `~/.deno/bin` |
| Node ورژن مینیجرز | `~/.volta`, `~/.volta/bin`, `~/.nvm`, `~/.nvm/versions`, `~/.fnm` |
| Rust | `~/.cargo`, `~/.cargo/bin`, `~/.rustup` |
| Go | `~/go`, `~/go/bin` |

یہ فہرست ایک اصل خرابی کی وجہ سے ہے: [1.1.0](../changelog.md#110--2026-05-10) سے پہلے pnpm صفائی کا ہدف `~/.local/share/pnpm` تھا — انسٹال روٹ — اور اس نے خود `pnpm` بائنری سمیت گلوبل انسٹال پیکیجز حذف کر دیے۔ اصلاح نے ہدف کو `~/.local/share/pnpm/store` تک محدود کیا اور یہ فہرست شامل کی تاکہ غلطی دوبارہ نہ ہو۔

[`--all-safe`](../modes/all-safe.md) شروع ہوتے وقت یہ بھی تصدیق کرتا ہے کہ ان میں سے کوئی اس کی اہداف کی فہرست میں کبھی نہ آئے؛ آئے تو `BUG:` پیغام کے ساتھ رک جاتا ہے۔

## محفوظ فائل نام {#protected-basenames}

**فائل کے نام سے، کسی بھی جگہ** رد، چاہے وہاں تک پہنچنے والا پاتھ کچھ بھی ہو:

`.bashrc` · `.bash_profile` · `.bash_login` · `.profile` · `.bash_logout` · `.zshrc` · `.zshenv` ·
`.zprofile` · `.zlogin` · `.zlogout` · `.bash_aliases` · `.bash_history` · `.zsh_history` · `.inputrc` ·
`.dircolors` · `.config` · `.local`

یہ آخری بچاؤ ہے۔ یہ اس لیے ہے کہ مستقبل کی کوئی خرابی اگر کسی طرح شیل-انٹ فائل کو اہداف کی فہرست میں ڈال دے، تب بھی اسے حذف نہ کر سکے۔

## انکار کیسا دکھتا ہے {#what-a-refusal-looks-like}

```text
✗ REFUSE: protected path: /home/you/Documents/notes
✗ REFUSE: unsafe path: '/home/you'
✗ REFUSE: shell-init / history file: /home/you/.bashrc
```

انکار درست رویہ ہے، کوئی خرابی نہیں جس سے بچ نکلنا ہو۔ اگر جو کیش آپ صاف کروانا چاہتے ہیں وہ رد ہو رہا ہے، تو وجہ تقریباً ہمیشہ کسی محفوظ جگہ پہنچنے والا سملنک ہوتی ہے — سملنک ٹھیک کریں، ٹول نہیں۔ دیکھیں [مسائل کا حل](../troubleshooting.md#refuse-protected-path)۔
