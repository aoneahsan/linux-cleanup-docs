# مشین کے پڑھنے لائق ایونٹس

`--json-events` نئی لائن سے الگ کیا ہوا JSON، stdout پر لکھتا ہے۔ پڑھنے والا متن اور سوال stderr پر جاتے ہیں، اور ان کی ایک مقامی کاپی سیشن لاگ میں رہتی ہے۔ سلسلہ اسی مشین پر رہتا ہے؛ اس میں مکمل مقامی پاتھس ہو سکتے ہیں۔ استعمال کرنے والوں کو یہ پاتھس اکاؤنٹ یا اینالیٹکس ڈیٹا کے حصے کے طور پر اپ لوڈ نہیں کرنے چاہئیں۔

یہ فلیگ `--scan` اور `--all-safe --yes` کو سپورٹ کرتا ہے۔ مکمل محفوظ رن کو `--yes` چاہیے تاکہ کوئی مشینی کلائنٹ کسی سوال پر نہ رکے۔ فائلیں حذف کیے بغیر مکمل محفوظ کارروائی کا پری ویو کرنے کے لیے `--dry-run` شامل کریں۔ مقامی لاگ اور اپ ڈیٹ جانچ کی حالت پھر بھی لکھی جا سکتی ہے۔ دوسرے موڈز ایگزٹ کوڈ 2 لوٹاتے ہیں۔

```bash
linux-cleanup --scan --json-events > scan.ndjson
linux-cleanup --all-safe --yes --dry-run --json-events > preview.ndjson
```

ہر مکمل ایونٹ میں `v: 1`، ایک `type` اور `ts` (Unix ملی سیکنڈ) ہوتا ہے۔ استعمال کرنے والوں کو اونچا `v` رد کرنا چاہیے اور ورژن 1 پر انجان فیلڈز نظرانداز کرنی چاہئیں۔ موڈ ID ایک اسٹرنگ ہے: `scan` یا `allsafe`۔

| ایونٹ | فیلڈز | مطلب |
|---|---|---|
| `plan` | `version`, `dry_run`, `profile`, `sections[]` | پہلا ایونٹ؛ چنے ہوئے موڈ کے لیے ایک سیکشن۔ سیکشن میں `id`، `title`، `stamp`، `sudo`، `deep` ہوتے ہیں۔ |
| `disk` | `phase`, `total_kb`, `free_kb`, `purgeable_kb`, `snapshots`, `snapshot_note` | موڈ سے پہلے اور بعد میں ڈسک کا نمونہ۔ غیر معاون اندازے `null` ہوتے ہیں۔ |
| `section_start` | `id`, `title`, `stamp` | چنا ہوا موڈ شروع ہوا۔ |
| `item` | `id`, `path`, `kb`, `action`, `unique`, `age_days`, `reason` | صرف پڑھنے والے اسکین کا نتیجہ، یا صفائی کے معاون کا چنا ہوا پاتھ۔ `report` صرف پڑھتا ہے، `delete` آزمائشی رن میں مجوزہ کارروائی اور اصل رن میں مکمل ہوئی معاون کارروائی ہے، `skip` انکار ہے۔ `kb` پورے KiB تک کاٹا جاتا ہے۔ |
| `progress` | `id`, `done`, `total` | واحد چنا ہوا موڈ 0/1 یا 1/1 پر ہے۔ یہ موڈ کی حد ہے، ہر فائل کا فیصد نہیں۔ |
| `error` | `id`, `message` | CLI کی بتائی ہوئی ناکامی یا انکار۔ |
| `section_result` | `id`, `status`, `freed_kb`, `items`, `reason` | حالت `completed` یا `failed` ہے۔ جب تک CLI اپنی لکھائی کو ڈسک کی دوسری سرگرمی سے الگ نہ کر سکے، بائٹس اور آئٹمز کے مجموعے `null` رہتے ہیں۔ |
| `summary` | `attempted`, `completed`, `skipped`, `failed`, `freed_kb`, `disk_free_before_kb`, `disk_free_after_kb`, `elapsed_s`, `reports`, `log`, `dry_run` | مکمل ہوئے موڈ کے بعد آخری ایونٹ۔ خالی جگہ کے دونوں نمونے مشاہدات ہیں، اس عمل سے واپس ملے بائٹس کا دعویٰ نہیں۔ |

مکمل رن میں سلسلہ `plan` سے شروع ہو کر `summary` پر ختم ہوتا ہے۔ رکا ہوا عمل یا پوری نہ ہونے والی اپ ڈیٹ کی شرط شاید کوئی summary نہ چھوڑے؛ اسے نامکمل رن سمجھیں اور ایگزٹ کوڈ اور stderr دیکھیں۔ رد کیا گیا آرگیومنٹ plan سے پہلے `error` ایونٹ بھیج کر 2 کے ساتھ ختم ہو سکتا ہے۔ فلیگ نہ ہو تو موجودہ متنی آؤٹ پٹ اور ایگزٹ کوڈز ویسے ہی رہتے ہیں۔

ایونٹ سلسلہ مقامی JSON سیشن رپورٹ کا تکملہ ہے۔ آزمائشی رن کوئی سیشن رپورٹ نہیں لکھتا۔ استعمال کرنے والا `item.path` سے کوئی مقامی فیصلہ سمجھا سکتا ہے، پھر اسے سرور سے سنک کرنے کے بجائے چھوڑ سکتا ہے۔ جب `--cleanup-logs` سیشن لاگ حذف کرتا ہے تو `summary.log` کی قدر `null` ہوتی ہے۔
