# システムのクリーンアップ（sudo）

**`--system` は始める前に sudo を求め、そのあとシステムの各手順について確認します。** パッケージの作業には `apt` と `dpkg` を直接使うため、モード全体が使えるのは Debian と Ubuntu です。ほかのディストリビューションでもジャーナルや `/tmp` の部分は動くことがありますが、パッケージのコマンドは失敗します。[対応ディストリビューション](../distro-support.md)を参照。

```bash
linux-cleanup --system --dry-run
linux-cleanup --system
```

ドライランは、クリーンアップの対象を削除したり設定を変えたりせずに、予定のコマンドを表示します。それでもローカルのログと更新チェックの状態は書き込むことがあります。元に戻せない本番実行の前に確認してください。

## 6 つの手順 {#the-six-steps}

| 手順 | 確認後にコードが実行するもの | 既定 |
|---|---|---|
| apt | `sudo apt autoremove --purge -y`, `sudo apt clean` | はい |
| ジャーナル | `sudo journalctl --vacuum-size=100M` | はい |
| Snap | 条件を満たす無効なリビジョンを `sudo snap remove` で削除 | はい |
| カーネル | `dpkg` でインストール済みの `linux-image-*` パッケージを一覧表示 | 削除なし |
| `/tmp` | `sudo find /tmp -mindepth 1 -atime +7 -delete` | はい |
| ページキャッシュ | `sudo sync`, `sudo sysctl -q -w vm.drop_caches=3` | いいえ |

ジャーナルの目標は 100 MB、`/tmp` の経過日数は 7 日で、どちらも `--days` に従いません。Snap の手順では、`--purge-all` を使わない限り、置き換えたリビジョンが設定した経過日数に達するまで、無効になったロールバック用のリビジョンを残します。カーネルの一覧は情報表示のみです。置き換えられたカーネルのパッケージは、その前の apt の手順で削除されることがあります。

`/tmp` の手順はアクセス時刻に頼っています。ファイルシステムがそれを確実に記録しない場合、経過日数による削除はスキップします。ページキャッシュの解放で空くのはディスクではなく RAM で、キャッシュがまた埋まるまでは読み込みが遅くなることがあります。

## 範囲と注意点 {#boundaries}

このモードは、個別のコマンドを実行できるように、動作中は sudo の認証を保持します。それらのコマンドを確認するつもりがないなら、システムのクリーンアップは始めないでください。`--speed` にも sudo を求めることがある任意の修正があり、CLI で sudo を使うのはシステムモードだけではありません。

取り戻せる量はマシンによって変わります。実行後に測ったディスク容量の変化には、ほかのプロセスの書き込みも含まれることがあります。ツールが実行しようとしたコマンドはログで確認してください。
