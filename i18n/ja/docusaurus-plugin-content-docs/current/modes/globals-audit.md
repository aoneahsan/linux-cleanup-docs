# グローバルパッケージの監査

**`--globals` は、npm、pnpm、yarn、bun、deno でグローバルにインストールしたパッケージを一覧にし、それぞれに判定を付けます。** [1.1.0](../changelog.md#110--2026-05-10) で追加しました。

```bash
linux-cleanup --globals
linux-cleanup --globals -d 180
```

:::note このモードは何も削除しません
コピーして使えるアンインストールのコマンドを表示して終わります。何を実行するかはあなたが決めます。グローバルパッケージは、不意に消えると作業の流れを壊しやすいものなので、ツールが代わりに削除することはしません。
:::

## 判定 {#the-verdicts}

| 判定 | 意味 |
|---|---|
| **recently used** | `--days` 日以内に変更または使用された。そのままに |
| **needed by: `<pkg>`** | ほかのグローバルパッケージが依存関係として宣言している。削除するとそれが壊れる |
| **STALE — safe to uninstall** | しきい値を超えて使われておらず、依存しているものもない |

「安全にアンインストールできる」とは、マシン上のほかのグローバルパッケージから見て安全という意味です。そのバイナリを呼ぶシェルスクリプト、CI のジョブ、あなたの習慣までは知りようがありません。実行する前に一覧を読んでください。

## なぜここでグローバルパッケージが大事なのか {#why-global-packages-matter-here}

グローバルにインストールしたパッケージは、どのクリーンアップモードでも**決して**削除しません。`~/.local/share/pnpm`、`~/.npm`、`~/.yarn`、`~/.bun/install/global`、`~/.deno/bin` は、まさにそれを守るために[完全一致の保護リスト](../reference/protected-paths.md#exact-match-protected-paths)に入っています。pnpm の掃除がインストール先を対象にしてグローバルパッケージを消してしまった、実際の不具合から得た教訓です。[1.1.0](../changelog.md#110--2026-05-10)を参照。

この監査はその対になる、意図した仕組みです。自動化せずに見えるようにします。

## パッケージマネージャーが PATH になくても動く {#works-without-the-package-managers-on-path}

各マネージャーには、使えるときは CLI で、使えないときはファイルシステムを直接調べて問い合わせます。そのため、`pnpm` をインストールしたのに今は `PATH` にない、というマシンでも監査は動きます。それこそ原因を探りたい状況であることが多いはずです。

実行環境がディスクにあるのにシェルにつながっていない場合、それを直すのは [`--doctor`](./doctor.md) です。

## 実行するとよいタイミング {#good-moments-to-run-it}

- Node の入れ直しやバージョン管理ツールの切り替えの前
- 新しいマシンへの移行の前。手持ちのツールの持ち運べる一覧になります
- `npm ls -g` の出力が見てもわからなくなったとき
- 年に 1〜2 回、手入れとして
