# 使われていない個人ファイル

**`--stale` は、`~/Downloads` と設定された非保護ルートで、約 10 MB を超え、`--days` 日以上使われていないファイルを見つけ、1 つずつ削除を提案します。**

```bash
linux-cleanup --stale         # または: -p
linux-cleanup --stale -d 180  # 180 日以上使われていないファイルのみ
```

:::danger 個人ファイルはかけがえのないものかもしれません
`~/Downloads` や設定した非保護ルートには、あなたが置いたものがそのまま入っています。大切なものの唯一のコピーが含まれていることもあります。

ツールには、二度と開かないインストーラーと、まだ必要になっていないだけの文書を区別できません。区別しようともしません。**候補はすべて読んでください。**
:::

## 方針として対話式 {#interactive-by-policy}

ファイルごと、または範囲ごとの確認が必須です。ここでは `--yes` は無視され、これからもそうです。このモードは [`--all-safe`](./all-safe.md) にも含まれません。[関門 3](../safety/guards.md#guard-3--personal-data-is-interactive-only)を参照。

何かを尋ねる前に候補の一覧をすべて表示するので、モードを実行してすべて断るのも、それらのディレクトリを確認する正当な方法です。

## ファイルが候補になる条件 {#what-makes-a-file-a-candidate}

次の 3 つを同時に満たすものです。

1. 設定された個人用のルートにある。既定は `~/Downloads` で、`~/Desktop` などの保護されたルートは対象外です
2. 約 10 MB を超えている
3. `atime` と `mtime` の両方が `--days`（既定は 100）より古い

個人用のルートは、`$XDG_CONFIG_HOME`（既定は `~/.config`）の下の `personal-roots.txt` で設定できます。[環境変数](../reference/environment-variables.md)を参照。

:::note `~/Downloads` が保護リストにない理由
入れられないのです。そこを掃除することがこのモードのすべてだからです。[許可リスト](../safety/guards.md#guard-1--the-path-allowlist)が `~/Documents`、`~/Pictures`、`~/Music`、`~/Videos` を守っているのは、まさに届くディレクトリが思ったとおりの 1 つだけになるようにするためです。

大切なものを `~/Downloads` に置いているなら、保護された場所に移してください。それが長く効く対策で、このツール以外からも守れます。
:::

## 候補の一覧の読み方 {#reading-the-candidate-list}

各項目にはパス、サイズ、未使用日数が表示されます。立ち止まって考えたいもの：

| 種類 | 考えること |
|---|---|
| インストーラー、ISO、`.deb`/`.AppImage` | たいてい安全。再ダウンロードできます |
| ダウンロードではなく自分で作ったもの | 残すか、保護された場所に移す |
| 顧客向けや仕事の納品物 | 残す。ダウンロードフォルダーは置き場所に向きません |
| 入手元がはっきりしないメディア | 受け入れる前に調べる |
| 一度も展開していないアーカイブ | 先に中身を確認する |

## より安全な順番 {#a-safer-sequence}

```bash
linux-cleanup --audit            # $HOME で実際に大きいものは何か
linux-cleanup --stale -d 365     # 本当に古いファイルだけ
```

365 日から始めて少しずつ下げると、まず短くてわかりやすい一覧が手に入ります。それが片付いたら、しきい値を下げてください。
