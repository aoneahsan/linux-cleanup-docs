# 変更履歴

`linux-cleanup` のリリースの履歴です。形式は [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) に従い、[セマンティック バージョニング](https://semver.org/spec/v2.0.0.html)を使っています。

公開中の最新バージョンは [npm のパッケージ](https://www.npmjs.com/package/linux-cleanup)で確認してください。すべての記録は[ソースの変更履歴](https://github.com/aoneahsan/linux-cleanup/blob/main/CHANGELOG.md)にあります。ここでは、掃除の判断に影響する変更を説明します。

## 2.1.1 — 2026-11-22 {#211--2026-11-22}

`--help`、`--version`、メニューの「情報」画面、フィードバックの画面に、サイト、このマニュアル、デスクトップアプリのダウンロードページを載せました。実行レポートの `credits.tool_homepage` は製品のサイトになりました。「情報」画面から、スクリプトはネットワークを使わないという記述をなくしました。起動時に公開リリース記録を一度読むためです。各モードが消すものに変更はありません。

## 2.1.0 — 2026-11-21 {#210--2026-11-21}

`--json-events` は、`--scan` と対話なしの `--all-safe --yes` について、バージョン付きのローカルの JSON イベントを出力します。完全安全に `--dry-run` を加えると、削除せずに予定のパスを報告します。出力にはローカルの完全なパスが含まれることがあるので、マシンの外に出さないでください。

## 2.0.1 — 2026-11-21 {#201--2026-11-21}

README に、linux-cleanup を公開しているすべての場所を載せました。スクリプトの動きに変更はありません。

## 2.0.0 — 2026-11-10 {#200--2026-11-10}

`--dry-run`、起動時の公開リリース記録の確認、常設の CLI のコピーを更新する `--refresh-app` を加えました。通常のお知らせでは初回の実行は通り、次の起動から止めます。緊急のお知らせでは古いコピーをすぐに止めます。オフラインのときはそのまま動きます。ドライランは掃除の対象を消さず設定も変えませんが、ローカルのログと更新確認の状態は書くことがあります。

## 1.6.0 — 2026-09-18 {#160--2026-09-18}

読み取り専用の `--speed` の診断と、プロジェクトと個人ファイルの探索ルートの設定を加えました。`noatime` のファイルシステムでのアイドルの判定を直しました。古いリリースではアクセス時刻が記録されないため、まだ使っているキャッシュを消すことがありました。エイリアスと cron の導入先は常設のコピーになり、ログの掃除はその回のログだけを消すようになりました。

## 1.5.2 — 2026-09-18 {#152--2026-09-18}

無効になった最近の Snap のリビジョンを、元に戻すためのコピーとして残すようにしました。また `--node-modules` が Yarn PnP の内部を一覧に出さないようにしました。

## 1.5.1 — 2026-09-18 {#151--2026-09-18}

展開済みのパッケージとブラウザーのキャッシュの整理を、項目まるごとの単位で行うようにしました。使っているインストールから、たまにしか使わないファイルだけが消えることを防ぎます。

## 1.5.0 — 2026-09-18 {#150--2026-09-18}

Gradle と Android Studio のキャッシュの整理を、バージョンのまとまり単位で行うようにしました。また、使われていない `node_modules` の検出と、専用の削除の関門を直しました。以前の 1.4.0/1.5.0 の掃除では、展開済みのキャッシュが不完全なまま残ることがあります。復旧の手順はソースの変更履歴を見てください。

## 1.3.0 — 2026-05-10 {#130--2026-05-10}

仕上げのリリースです。画面メニューと、クラッシュ時の自動記録を加えました。掃除の処理は新しくしておらず、既存の安全の関門とアイドルの関門も変わりません。

### 追加 {#added}

- **[TUI モード](./modes/tui.md)**（`-t` / `--tui` / `-g` / `--gui`）— whiptail か dialog を使うメニューです。選ぶたびに通常の CLI の出力で実行し、終わるとメニューに戻ります。どちらのツールもなければ、ディストリビューションに合わせた導入の案内を出して CLI のメニューに切り替えます。
- **クラッシュ用バンドルの自動作成** — EXIT のトラップが、予期しない 0 以外の終了のときに、セッションログ、最新の記録、システムのマニフェストを入れた `crash-<stamp>.tar.gz` を `~/.linux-cleanup/feedback/` に書き出し、メールで送れる 1 行を表示します。

  正常な終了、`Ctrl-C`（130）、`SIGTERM`（143）、引数の解析エラー（2）では作りません。**ネットワークは使いません。** 共有すると決めるまで、バンドルはマシンに残ります。
- TUI の**情報**画面に、バージョン、連絡先、ライセンス、プライバシーの約束を載せました。

### 変更 {#changed}

- バナーとセッションのまとめを `tui` モードでも出さないようにし、画面とログの出力がぶつからないようにしました。

## 1.2.1 — 2026-05-10 {#121--2026-05-10}

1.2.0 のアイドルの関門を、作り直せるキャッシュではなく*ツール*であるものすべてに広げました。こうしたものを消すには、動いているソフトがそれに依存していないこと、**そして** `--days` 日のあいだ触れていないことの**両方**が必要になりました。

### 変更 {#changed}

- **Android の AVD** — 以前は確認すると `~/.android/avd` を丸ごと消していました。今は `*.avd` のディレクトリを、隣の `*.ini` と組にして 1 つのまとまりとして調べ、プロファイルのすべてのファイルがしきい値を超えてアイドルのときだけ整理します。最近使ったエミュレーターのプロファイルはそのまま残ります。
- **[置き換え済みの VS Code / Cursor 拡張機能](./modes/editor-extensions.md)** — 「新しいバージョンがある」という確認は最初の条件を満たすだけでした。今は、置き換え済みのディレクトリがしきい値を超えてアイドルであることも*必要*です。最近読み込んだ古いバージョンは一覧に出しますが残し、バージョンごとのアイドル日数を表示します。
- **Flatpak のユーザーデータ** — `~/.local/share/flatpak` にはキャッシュだけでなく、ユーザー単位でインストールしたアプリが入っています。ユーザー単位のアプリが 1 つでもあれば、このツリーには触れないようにしました。さらに、ツリー全体がしきい値を超えてアイドルであることも求めます。より安全な方法として `flatpak uninstall --user --unused` を案内します。

### 追加 {#added}

- `newest_access_age_days <path>` — パスの下のどこかにある、いちばん新しい `atime`/`mtime` からの日数を返します。
- `prune_stale_units <root> <days> [glob]` — 最上位の子をそれぞれ分けられないまとまりとして扱い、途中までの整理で状態が壊れないようにします。

### 理由 {#why}

1.2.0 がまだ Android の AVD を丸ごと消していること、そしてキャッシュではなくツールであるものすべてに同じ考え方を当てはめるべきだと、利用者が指摘してくれました。ほかのツールが依存しているソフトも、利用者自身が最近使ったソフトも、消すべきではありません。

## 1.2.0 — 2026-05-10 {#120--2026-05-10}

**既定の削除の方針を、長く使われていないものだけにしました。** 対象のキャッシュの中のものは、ファイルが `--days` 日（既定は 100 日）のあいだ、`atime` と `mtime` の両方で触れられていない場合にだけ消します。

### 変更 {#changed}

- **すべてのキャッシュのモジュールが使う共通の掃除処理 `clean_target` を、丸ごと消すのではなく整理する動きにしました。** しきい値を超えたファイルだけを消し、そのあと空のディレクトリを片付けます。最近使ったファイルは残り、ディレクトリの枠も残るので、ツールは自分の構成を見つけられます。
- **[`--all-safe`](./modes/all-safe.md) も対象ごとに同じように整理し**、まとめには対象ごとに空いたバイト数**と**残したバイト数を表示します。
- **npm のキャッシュの掃除もアイドルの関門に従います。** これまでは経過時間をまったく見ない `npm cache clean --force` を必ず実行していました。
- 実行前のバナーに、有効な方針（「prune ≥Nd」または「FULL PURGE」）を表示します。

### 追加 {#added}

- **`--purge-all`** で、1.2.0 より前の、すべて消す動きに戻せます。その得失もドキュメントに書いています。
- **`prune_stale <root> <days>`** — モジュール向けの公開の補助関数です。保護パスを拒否し、2 つの時刻がどちらもしきい値を超えたところだけを消し、空のディレクトリを片付け、空いたバイト数を報告します。

### 理由 {#why}

1.1.0 の既定では、確認するとキャッシュのツリーを丸ごと消していました。すぐ作り直せる `~/.cache/yarn` ならそれで正しいのですが、`~/.gradle/wrapper/dists/` では誤りです。来月本当に必要になるかもしれない 230 MB のダウンロードだからです。

100 日というしきい値で、「最近触れたので消えると困る」ものと「3 か月開いていない」ものがはっきり分かれます。慣れた人は、今でも古い動きを選んだり、`-d 30` で関門を厳しくしたりできます。

## 1.1.0 — 2026-05-10 {#110--2026-05-10}

安全性を強化したリリースです。グローバルにインストールしたパッケージとシェルの初期化ファイルに、決して触れないようにしました。

### 修正 {#fixed}

- **pnpm のグローバルパッケージが消えていました。** pnpm のコンテンツストアの掃除が `~/.local/share/pnpm`（`PNPM_HOME`）を対象にしていたためです。ここにはグローバルにインストールしたパッケージ、bin の入り口、`pnpm setup` が入れた `pnpm` のバイナリそのものがあります。今は、作り直せるコンテンツアドレス方式のキャッシュである `~/.local/share/pnpm/store` だけを対象にします。

  影響があったのは `--all-safe`、メニューの 3 番、スキャン、ガイド付きの手順、`--list-targets` です。

### 追加 — 安全の関門 {#added--safety-guards}

- **[`PROTECTED_EXACT`](./reference/protected-paths.md#exact-match-protected-paths)** — パッケージマネージャーのインストール先とランタイムのホームを、完全一致で守ります。対象は pnpm、npm、yarn、bun、deno、volta、nvm、fnm、cargo、rustup、Go です。
- **[`PROTECTED_BASENAMES`](./reference/protected-paths.md#protected-basenames)** — 名前がシェルの初期化や履歴のファイルであれば、どこにあってもそのパスを拒否します。
- **`--all-safe` の起動時の確認** — 保護されたランタイムのディレクトリが対象の一覧に紛れ込んだら `BUG:` のメッセージで止まり、気づかないうちに元に戻ることを防ぎます。

### 追加 — bun と deno への対応 {#added--bun-and-deno-coverage}

- bun：`~/.bun/install/cache` のキャッシュを掃除し、`~/.bun/install/global` は守ります。
- deno：`~/.cache/deno` のキャッシュを掃除し、`~/.deno/bin` は守ります。
- どちらも `--all-safe`、`--scan`、新しいグローバルパッケージの監査に組み込みました。

### 追加 — モード {#added--modes}

- **[`--globals`](./modes/globals-audit.md)** — npm、pnpm、yarn、bun、deno で直接インストールしたグローバルパッケージを読み取りのみで一覧にし、それぞれに `recently used`、`needed by: <pkg>`、`STALE — safe to uninstall` の印を付け、そのままコピーできるアンインストールのコマンドを表示します。**何も削除しません。** パッケージマネージャーの CLI が `PATH` になくても動きます。
- **[`--doctor`](./modes/doctor.md)** — ディスクにあるのにシェルの初期化に組み込まれていないランタイム（nvm、pnpm、bun、deno、cargo）を見つけ、標準の設定を追記するか尋ねます。**確認のうえで追記するだけです。既存の行を消したり変えたりはしません。**

### 変更 {#changed}

- `--all-safe` は「globals are PRESERVED」と「shell-init files are NEVER touched」というお知らせをはっきり表示します。

## 1.0.0 — 2026-05-09 {#100--2026-05-09}

最初の公開リリースです。

### 配布 {#distribution}

- npm で公開。`npx linux-cleanup` または `npm install -g linux-cleanup` で実行できます。パッケージには小さな Node のランチャーが入っていて、bash の入り口を見つけ、ログと記録を `~/.linux-cleanup/` に置きます。npx の一時ディレクトリが消えてもなくなりません。
- `git clone` で直接使うこともでき、その場合は出力をクローンの中に残します。

### 機能 {#features}

- **10 の手順のガイド付きの流れ**を既定のモードにしました。進み具合の見出し、`a` / `s` / `q` の確認、手順ごとに空いたバイト数と累計を表示します。
- **許可リストによる安全** — 選び抜いた保護リストの中のパスと、`$HOME` や `/` そのものを拒否します。
- **個人データは対話式のみ** — まとめて処理することも、`--yes` で進めることもありません。
- **掃除の分類** — パッケージマネージャーのキャッシュ（yarn、npm、pnpm、pip、composer）、アプリのキャッシュ（Chrome、Firefox、Brave、Chromium、Edge、Vivaldi、Gradle、Cypress、Playwright、TypeScript、Zoom）、開発ツール（Android の AVD、pub-cache、Dart、flatpak）、エディター拡張機能、使われていない `node_modules`、途中のダウンロードと使われていない個人ファイル、sudo でのシステムの掃除。
- **セッションの記録** — 毎回、標準の JSON を書き、必要に応じて Markdown と HTML に書き出せます。HTML はダークモードに合わせる CSS を埋め込んでいます。
- **[レポートの管理](./modes/reports.md)**（`--reports`）と、対話なしの `--export FMT ID`。
- **セルフテスト**（`--self-test`）— 依存関係、すべてのシェルファイルの構文、安全の関門の正常さを確認します。`/`、`$HOME`、`~/Documents`、`/etc` で保護が true を返すことを確かめます。
- 整理された不具合報告のための **`--feedback`** と **`--debug-bundle`**。
- **プライバシー** — ネットワークは一切使いません。テレメトリー、分析、クラッシュ報告もありません。マシンの外に出るのは、あなたがメールで送ると決めたものだけです。
- **作るものすべてに作者の表示** — ログは出どころを示す見出しで始まり、記録には最上位に `credits` の項目があり、HTML の出力にはフッターに表示があります。
- **導入の補助** — `--install-alias`、`--install-cron` と、それぞれの削除のコマンド。
- `NO_COLOR` と `--no-color` に対応。

### セキュリティと安全性の強化 {#security-and-safety-hardening}

- HTML の出力では、JSON から来た値をすべて `jq` の `@html` フィルターでエスケープし、壊れた記録からの注入を防ぎます。
- 任意の依存関係（`snap`、`crontab`、`xdg-open`、`jq`）ごとに `command -v` で確認します。
- `realpath -m` で、保護パスの確認の前にシンボリックリンクを解決するので、シンボリックリンクで許可リストをすり抜けることはできません。
