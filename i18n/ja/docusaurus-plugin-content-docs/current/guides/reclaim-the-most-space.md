# 意図して容量を取り戻す

**まず測ってください。見つかったパスに対処できる、いちばん狭い範囲のクリーンアップを選んでください。** キャッシュのルートについて表示されるサイズは、そのすべてを削除できる、あるいは削除すべきだという意味ではありません。

## 1. 大きいパスを見つける {#1-find-the-large-paths}

```bash
linux-cleanup --audit
linux-cleanup --scan
```

`--audit` は、このツールでは掃除できないものも含めて、`$HOME` の大きい項目を一覧にします。`--scan` は、設定されたキャッシュのルートやほかの候補を、何も削除せずに一覧にします。ディスクの大部分が仮想マシンのイメージ、データセット、ゲームのライブラリなら、関係のないクリーンアップモードを実行するのではなく、それを直接確認してください。

## 2. 普段のキャッシュをプレビューする {#2-preview-routine-caches}

```bash
linux-cleanup --all-safe --dry-run
```

既定の完全安全モードは、100 日のアイドルしきい値を過ぎた、条件を満たす再生成できるキャッシュを間引きます。プレビューは削除せずにそのルールをたどります。それでもローカルのログと更新チェックの状態は書き込まれることがあります。

予定のパスがすべて作り直せるものか再ダウンロードできるものなら、`linux-cleanup --all-safe` を実行して確認メッセージを読んでください。`--yes` は、このマシンをすでに確認したうえで無人で実行するためのものです。

## 3. プロジェクトの依存関係は別に確認する {#3-review-project-dependencies-separately}

```bash
linux-cleanup --node-modules --dry-run
```

プロジェクトの依存関係のモードは対話式です。本番の削除の前に、プロジェクトのパスとロックファイルを確認してください。`node_modules` の中でその場で行った変更は、依存関係を入れ直しても戻りません。

## 4. システムのストレージは別に確認する {#4-review-system-storage-separately}

```bash
linux-cleanup --system --dry-run
```

システムモード全体は apt と dpkg を使うため、Debian と Ubuntu 向けです。sudo を求め、ジャーナルの整理、`/tmp` の古いファイル、任意のページキャッシュの手順を含みます。ページキャッシュの手順が影響するのはディスクではなく RAM です。[システムのクリーンアップ](../modes/system-cleanup.md)を参照。

## 5. 経過日数のしきい値は、もう一度プレビューしてから変える {#5-change-the-age-threshold-only-after-another-preview}

`--days N` は、どの未使用ファイルや、どのキャッシュの単位が対象になるかを変えます。100 から 30 に下げると最近使ったものまで消えることがあるので、選んだ値でまずドライランを確認してください。`--purge-all` は経過日数の保護を無効にします。あとで再ダウンロードが必要になる Gradle のディストリビューションやテスト用ブラウザーが消えることがあります。

## 6. 個人ファイルは別の判断にする {#6-keep-personal-files-as-a-separate-decision}

`--stale` は、大きく使われていない個人ファイルの候補を表示し、削除のたびに確認します。古いダウンロードが唯一のコピーかもしれません。`--yes` ではこのモードは承認されません。[使われていない個人ファイル](../modes/personal-stale-files.md)と[削除は元に戻せない](../safety/irreversibility.md)を参照。

取り戻せる容量は、マシンと、実行中に書き込むほかのプロセスによって変わります。ほかのモードが必要かどうかを決める前に、最後のログと残されたパスを確認してください。
