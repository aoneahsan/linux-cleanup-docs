# 安全装置

**linux-cleanup は、削除の前に最大 4 つの独立した関門を設けています。パスは、自分に当てはまる関門をすべて通過しなければなりません。** このページでは、各関門が何か、なぜあるのか、何を守らないのかを説明します。

これらの安全装置が安全モデルのすべてです。その後ろにバックアップも[元に戻す機能](./irreversibility.md)もありません。

## 関門 1 — パスの許可リスト {#guard-1--the-path-allowlist}

常に有効です。無効にできず、どのフラグでも回避できません。

削除の前に、対象は `realpath` で解決され、保護パスそのもの、またはその内側に当たれば拒否されます。解決が先に行われるため、シンボリックリンクでパスをすり抜けさせることはできません。`~/.cache/yarn` が `~/Documents` 内へのシンボリックリンクなら、解決後のパスは `~/Documents` の中になり、関門が働いて削除は拒否されます。

これを 3 つの別々のリストが支えています。

| リスト | 一致のしかた | 目的 |
|---|---|---|
| システムのルートと個人用ディレクトリ | パスそのもの、またはその配下すべて | `/etc`, `~/Documents`, `~/.ssh`, `~/.config`, … |
| パッケージマネージャーのインストール先 | **完全一致のみ** | `~/.local/share/pnpm`, `~/.npm`, `~/.cargo`, … |
| シェルの初期化ファイルと履歴ファイル | **ファイル名、場所を問わず** | `.bashrc`, `.zshrc`, `.bash_history`, … |

関門が働くと、stderr に拒否が表示されます。

```text
✗ REFUSE: protected path: /home/you/Documents/notes
```

完全一致のリストには補足が必要です。`~/.npm` は*完全一致*で保護されているため、その配下の `~/.npm/_cacache` は掃除できます。これは意図したものです。インストール先は残し、その中の再生成できるキャッシュは掃除の対象にします。完全なリストは[保護パス](../reference/protected-paths.md)にあります。

:::note この関門がしないこと
守るのは*場所*であって、*価値*ではありません。`~/Downloads` にある 40 GB のかけがえのない動画は許可リストでは守られません。`~/Downloads` は保護パスではないからです。それを守るのは[関門 3](#guard-3--personal-data-is-interactive-only)です。
:::

クリーンアップモードは名前の決まった対象パスを選び、そのうえで保護パスのチェックが危険な場所を拒否します。保護リストに含まれないパスが自動的に安全というわけではありません。各モードの対象とドライランを確認してください。

## 関門 2 — アイドルしきい値 {#guard-2--the-staleness-gate}

既定値：100 日。[1.2.0](../changelog.md#120--2026-05-10) で導入し、[1.2.1](../changelog.md#121--2026-05-10) で拡張しました。

1.2.0 からは、既定の方針は**全消去ではなく間引き**です。対象ディレクトリの中で、ファイルが削除されるのは `atime` と `mtime` が**両方とも** `--days` より古い場合だけです。残った空のディレクトリは片付け、ディレクトリそのものの枠は残すので、持ち主のツールは引き続き自分の構成を見つけられます。

両方のタイムスタンプを条件にすることには意味があります。`mtime` だけだと、1 年前にダウンロードして昨日読んだファイルが消えてしまいます。`atime` だけでは、`noatime` や `relatime` でマウントされたファイルシステムで信頼できません。両方を求めるのが慎重な読み方です。

キャッシュではなく*ツール*であるもの（Android の AVD、エディター拡張機能のバージョン、flatpak のユーザーデータ）については、1.2.1 でもう 1 つ条件を加えました。こうした資産は、**それに依存する動作中のソフトウェアがなく、かつしきい値を超えて使われていない**場合にだけ削除します。各資産は分割できない単位として評価するので、中途半端な間引きで削除しかけのエミュレーターのプロファイルが残ることはありません。

```bash
linux-cleanup --all-safe -y -d 30    # より積極的：しきい値 30 日
linux-cleanup --all-safe -y          # 既定：100 日
linux-cleanup --all-safe --purge-all # 関門オフ — 全消去、1.2.0 より前の動作
```

:::danger `--purge-all` はこの関門を完全に無効にします
`--purge-all` を付けると、対象のキャッシュはどれも経過日数に関係なく丸ごと消去されます。この関門が生まれたのは、まさにこの動作が原因でした。Gradle wrapper のディストリビューション、古いリリースブランチ用の Playwright のブラウザー、バージョン固定した依存パッケージの yarn キャッシュの tarball が消え、どれも再ダウンロードに手間がかかります。

マシンを入れ直す前なら正当な選択です。日常の既定としては不適切です。
:::

実行前のバナーに有効な方針が表示されるので、これから何が起きるかが曖昧になることはありません。

## 関門 3 — 個人データは対話式のみ {#guard-3--personal-data-is-interactive-only}

個人ファイルに触れうるモードは、方針として対話式です。

- [`--stale`](../modes/personal-stale-files.md) — `~/Downloads` と設定された非保護ルートにある、大きく使われていないファイル
- [`--partials`](../modes/partial-downloads.md) — 放置された途中のダウンロード
- [`--node-modules`](../modes/node-modules-finder.md) — 長く使われていないプロジェクトの依存ディレクトリ

**`--yes` はこれらのモードには適用されず、今後も適用されません。** `--yes` が自動で承認するのは再生成できるキャッシュだけです。ツールは候補の一覧を表示し、1 件ずつ確認を待ち、あなたが答えるまで何も削除しません。

理由は、個人ファイルにはプログラムが読み取れる手がかりがないからです。二度と開かないインストーラーと、まだ必要になっていないだけの文書の唯一のコピーを、ディスク上で区別する方法はありません。わかるのは本人だけなので、ツールは推測しません。

## 関門 4 — sudo の制限 {#guard-4--sudo-confinement}

[`--system`](../modes/system-cleanup.md) は `sudo` を呼び出す唯一のモードで、それも決まった操作の一覧に限られます。どれも個別に確認できる呼び出しで、1 つずつ確認を求めます。

| 操作 | 確認の既定 |
|---|---|
| `apt autoremove --purge -y` + `apt clean` | はい |
| `journalctl --vacuum-size=100M` | はい |
| 無効になった snap のリビジョンを削除 | はい |
| インストール済みカーネルの一覧表示 — **削除はしない** | — |
| `atime` が 7 日より古い `/tmp` のファイルを削除 | はい |
| `sync` + `sysctl vm.drop_caches=3` | **いいえ** |

スクリプトは `/etc/sudoers` を編集せず、`--system` は操作ごとに確認します。`sudo` が使えない場合、モードは中途半端な状態で続けずに中止します。

ここでは 2 つの値が**固定で、`--days` に従いません**。ジャーナル整理の目標（100 MB）と、`/tmp` の経過日数のしきい値（7 日）です。

## どの関門も守らないもの {#what-no-guard-covers}

安心させるより、穴をはっきり示すほうが役に立ちます。

| 穴 | 意味 |
|---|---|
| **元に戻せない** | ここにあるどれも、削除を取り消せるものにはしません。[削除は元に戻せない](./irreversibility.md)を参照。 |
| **`~/Downloads` は保護されていない** | 対話式の個人ファイルモードで到達できます。候補を読んでください。`~/Desktop` は保護されています。 |
| **`--purge-all` で関門 2 が外れる** | 関門 1、3、4 は引き続き有効で、アイドルしきい値だけが外れます。 |
| **root で実行すると被害の範囲が広がる** | このツールは一般ユーザーでの実行を前提にしています。正当な sudo の用途は `--system` が内部で扱います。 |
| **安全装置が守るのはパスで、中身ではない** | 保護ディレクトリはどこにあっても安全ですが、その外にある大事なファイルは安全ではありません。 |
| **`/proc` と `/sys` は保護リストにない** | 何も対象にしていませんが、許可リストにも名前がありません。 |

## 安全装置を自分で確かめる {#verifying-the-guards-yourself}

```bash
npx linux-cleanup --self-test      # 既知のパスで関門が働くことを確認
npx linux-cleanup --list-targets   # 対象リストと保護リストの両方を表示
```

`--self-test` が正直な確認方法です。`/`、`$HOME`、`~/Documents`、`~/.ssh`、`/etc` が保護され、`~/.cache/yarn` が保護されていないことを確かめ、1 つでも失敗すれば 0 以外の終了コードで終わります。ドキュメントは古くなることがありますが、この確認は実際に手元にあるコードに対して動きます。
