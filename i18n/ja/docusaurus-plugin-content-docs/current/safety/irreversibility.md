# 削除は元に戻せない

**linux-cleanup は `rm -rf` を呼び出します。元に戻す機能、ゴミ箱のフォルダー、スナップショット、バックアップの手順はありません。**
一度削除したパスは、このツールでも、どのフラグを渡しても取り戻せません。

:::danger 最初に本番実行する前に読んでください
- 削除したファイルはゴミ箱に**入りません**。
- `--undo` も復元コマンドもなく、隠れたコピーもどこにも残りません。
- ローカルのログで実行内容をたどることはでき、ガイド付き手順の記録には手順の要約が残ります。どちらもファイル単位のバックアップではありません。
- かけがえのないファイルでバックアップがなかった場合、それは失われます。

このツールの安全性は、最初から[間違ったものを削除しない](./guards.md)ことだけで成り立っています。
:::

## 「再生成できる」が本当に約束すること

このツールが削除するものの大半は「再生成できる」と説明されています。この言葉には正確な意味があり、何を意味して何を意味しないかをはっきりさせておく価値があります。

| 意味すること | 意味しないこと |
|---|---|
| *ほかの*プログラムがデータを作り直せる | linux-cleanup が作り直せる |
| 次の `yarn install` でパッケージが再ダウンロードされる | バイトがまだディスクのどこかにある |
| ブラウザーは閲覧中にキャッシュを作り直す | 削除は取り消せる |
| 作り直すにはネットワークか時間、またはその両方が必要なことがある | 作り直しは無料ですぐに済む |

Playwright のブラウザー一式は再生成できますが、再ダウンロードには数分と数百メガバイトの通信が必要です。オフラインのマシンではまったく再生成できません。「再生成できる」とはデータがどこから来るかの話であって、取り戻しやすさの話ではありません。

## 本当にかけがえのないもの

再生成できないデータを含みうる対象が 3 つあります。3 つとも[対話式のみ](./guards.md#guard-3--personal-data-is-interactive-only)で、確認に答えるときには本気の注意が必要です。

| 対象 | 何をしても戻らない理由 |
|---|---|
| `~/Downloads` や設定された非保護ルートにある**個人ファイル** | 取り直す元がありません。それが唯一のコピーなら、それで終わりです。 |
| **途中で止まったダウンロード**（`.crdownload`、`.part` など） | 再開できるのは元のブラウザーのセッションだけで、たいていとうに終わっています。 |
| **長く使われていない `node_modules` 内の未コミットの作業** | まれですが、その場で書き換えた依存パッケージはどのレジストリにもありません。 |

実際にデータを失う原因になるのは 1 つ目です。`~/Downloads` は保護パスではありません。そこを掃除することが中心的な機能なので、保護パスには*できない*のです。そのため、そこにあるファイルと削除のあいだにあるのは、候補一覧を読むあなたの目だけです。

## 元に戻す機能がない理由

設計上の理由は次のとおりです。

1. **元に戻すためのログは、空けたいディスクそのものへの書き込みを増やします。** 20 GB を空けるために 20 GB を残しても意味がありません。
2. **誤った安心感を生みます。** 元に戻せそうに見えるツールは雑な使い方を招き、しかも取り消しはせいぜい部分的です。90% のケースを戻せる取り消しは、残りの 10% でいちばん危険です。
3. **復旧より予防に投資するほうがよいからです。** [パスの許可リスト](./guards.md#guard-1--the-path-allowlist)、[アイドルしきい値](./guards.md#guard-2--the-staleness-gate)、対話式の確認が、誤った削除そのものを防ぎます。後から取り消すより確実に優れています。

キャッシュにとっては妥当なトレードオフです。`~/Downloads` にツールを向ける前に理解しておくべきトレードオフでもあります。

## 事後に実際に残るもの

削除に驚いたときは、手元のローカル記録を確認してください。どちらもバックアップではありません。

| 記録 | 場所 | 内容 |
|---|---|---|
| セッションログ | `~/.linux-cleanup/logs/cleanup-<timestamp>.log` | 実行時の読み取れる出力（ログを消していなければ） |
| JSON レポート | `~/.linux-cleanup/reports/report-<timestamp>.json` | ガイド付き手順の要約（レポートを無効にしていなければ） |

モードや選んだ対象を確かめる手がかりにはなりますが、削除したファイルをすべて列挙するものではありません。削除した内容そのものは一切含みません。

詳しい手順：[復旧](../recovery.md)。

## 実行前にリスクを減らす

```bash
# 1. このインストールで安全装置が動くことを確認
npx linux-cleanup --self-test

# 2. 取り戻せる容量を確認 — 何も削除しません
npx linux-cleanup --scan

# 3. ガイド付きで実行し、迷うものにはすべて 'n' と答える
npx linux-cleanup
```

さらに：

- **かけがえのないものはバックアップしておいてください。** このツールに限らずそうで、どんな削除でも復旧できるのはバックアップがあるときだけです。
- **確認していないマシンで個人ファイル向けのモードを使わないでください。** まず `--scan` を実行してください。
- **`--all-safe -y` は、信頼できるマシンのキャッシュに限って使ってください。** 個人ファイルには触れませんが、終わるまで何も表示しません。
- **`--purge-all` は OS を入れ直す前のための道具と考えてください。** 日常使いのものではありません。

:::tip 身につける価値のある習慣はひとつだけ
`--all-safe` の前には毎回 `--scan` を実行してください。1 分で済み、結果がまだ仮定のうちに見せてくれる唯一の手順です。
:::
