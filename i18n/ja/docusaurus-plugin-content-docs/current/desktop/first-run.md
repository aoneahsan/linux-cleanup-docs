# ドライラン、本番実行、レシート

デスクトップアプリのクリーンアップは、どれも同じ 4 つの手順を同じ順番で進みます。どれも飛ばせません。

## 初回の起動 {#first-launch}

初めて開くと、アプリは短い手順を 3 つ表示します。このアプリが何か、CLI が必ず拒否するフォルダーはどれか、そして任意の **Google でサインイン** です。どれもスキップでき、**ヘルプ** からもう一度開けます。クリーンアップにサインインは不要です。サインインすると月の本番実行の回数が増え、複数のコンピューターで実行回数が引き継がれます（[アカウントとプラン](./accounts-and-plans.md)）。

サインインするとブラウザーで Google が開きます。そこで終えると、ブラウザーが `127.0.0.1` 経由で結果をアプリに返し、アプリのウィンドウに戻ります。

## 1. ドライラン {#1-dry-run}

**ドライランを開始** は、完全安全のクリーンアップを `--dry-run` 付きで実行します。どこからも何も削除しません。そのあと画面には、クリーンアップで削除する予定のパスと、測ったサイズとその理由、CLI が拒否して残したパスとその理由が一覧で表示されます。**リストを JSON で保存** でその一覧をこのコンピューター上のファイルに書き出せます。

アプリでは、破線のボタンは必ずドライランです。塗りつぶしのボタンはファイルを削除します。

## 2. 確定 {#2-confirm}

**確認して実行** は、本番実行を始められる唯一の画面を開きます。ドライランで見つかった内容をもう一度示し、今月プランで残っている本番実行の回数を伝え、削除は元に戻せないことを明記します。次の間は **今すぐクリーンアップを実行** を押せません。

- ドライランから 1 日以上たっている（先にもう一度実行してください）
- ほかの実行がまだ続いている
- 今月の本番実行の回数が残っていない

## 3. 本番実行 {#3-real-run}

CLI がパスを削除するたびに報告し、画面がそれを追います。削除の前にパスをもう一度確認するので、ドライランのあとで変わったものは今の状態で判断されます。**この項目のあとでキャンセル** を押すと、今の手順が終わったところで止まります。すでに削除したものは戻りません。

## 4. レシート {#4-receipt}

ドライランも含め、どの実行もレシートで終わります。実行前後の空き容量、手順ごとの完了・スキップ・失敗、実行がどう終わったかが記されます。キャンセルや中断で終わった実行では、終わらなかった手順が失敗として記録されます。レシートはこのコンピューターの **レシートと履歴** に、`~/.linux-cleanup/` にある CLI 自身のレポートやログと並んで残ります。履歴の同期があるプランでサインインしていれば、レシートの数値も送ります。パスやファイル名は決して送りません（[コンピューターの外に出るもの](./overview.md#what-leaves-your-computer)）。
