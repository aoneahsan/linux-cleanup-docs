# Машиночитаемые события

`--json-events` пишет JSON с разделением по строкам в stdout. Текст для людей и вопросы идут в stderr, а их локальная копия — в журнал сеанса. Поток остаётся на этой машине; он может содержать полные локальные пути. Программам-потребителям не следует загружать эти пути в составе данных учётной записи или аналитики.

Флаг поддерживает `--scan` и `--all-safe --yes`. Полностью безопасному запуску нужен `--yes`, чтобы машинный клиент не остановился на вопросе. Добавьте `--dry-run`, чтобы просмотреть действие полностью безопасной очистки без удаления файлов. Локальный журнал и состояние проверки обновлений всё же могут записаться. Остальные режимы возвращают код выхода 2.

```bash
linux-cleanup --scan --json-events > scan.ndjson
linux-cleanup --all-safe --yes --dry-run --json-events > preview.ndjson
```

У каждого полного события есть `v: 1`, `type` и `ts` (миллисекунды Unix). Потребителю следует отклонять больший `v` и игнорировать незнакомые поля в версии 1. Идентификатор режима — строка: `scan` или `allsafe`.

| Событие | Поля | Значение |
|---|---|---|
| `plan` | `version`, `dry_run`, `profile`, `sections[]` | Первое событие; один раздел для выбранного режима. У раздела есть `id`, `title`, `stamp`, `sudo`, `deep`. |
| `disk` | `phase`, `total_kb`, `free_kb`, `purgeable_kb`, `snapshots`, `snapshot_note` | Замер диска до и после режима. Неподдерживаемые оценки — `null`. |
| `section_start` | `id`, `title`, `stamp` | Выбранный режим начался. |
| `item` | `id`, `path`, `kb`, `action`, `unique`, `age_days`, `reason` | Результат сканирования только для чтения или путь, выбранный вспомогательной программой очистки. `report` только читает, `delete` — предлагаемое действие при пробном запуске и выполненное действие при реальном, `skip` — отказ. `kb` усекается до целых KiB. |
| `progress` | `id`, `done`, `total` | Единственный выбранный режим на 0/1 или 1/1. Это граница режима, а не процент по файлам. |
| `error` | `id`, `message` | Сбой или отказ, о котором сообщил CLI. |
| `section_result` | `id`, `status`, `freed_kb`, `items`, `reason` | Состояние — `completed` или `failed`. Итоги по байтам и пунктам остаются `null`, пока CLI не научится отличать свои записи от другой дисковой активности. |
| `summary` | `attempted`, `completed`, `skipped`, `failed`, `freed_kb`, `disk_free_before_kb`, `disk_free_after_kb`, `elapsed_s`, `reports`, `log`, `dry_run` | Последнее событие после завершённого режима. Два замера свободного места — наблюдения, а не утверждение о байтах, освобождённых этим процессом. |

Поток начинается с `plan` и заканчивается `summary` при завершённом запуске. Прерванный процесс или невыполненное требование обновления могут не оставить summary; считайте такой запуск незавершённым и ориентируйтесь на код выхода и stderr. Отклонённый аргумент может выдать событие `error` и завершиться с кодом 2 до plan. Без флага текстовый вывод и коды выхода не меняются.

Поток событий дополняет локальный JSON-отчёт о сеансе. Пробный запуск отчёт о сеансе не пишет. Потребитель может использовать `item.path`, чтобы объяснить локальное решение, а затем отбросить его, не синхронизируя с сервером. Когда `--cleanup-logs` удаляет журнал сеанса, `summary.log` равно `null`.
