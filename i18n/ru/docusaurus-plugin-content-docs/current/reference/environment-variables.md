# Переменные окружения

**Все переменные окружения, которые читает linux-cleanup.** Все необязательны.

| Переменная | По умолчанию | Действие |
|---|---|---|
| `NO_COLOR` | не задана | Любое непустое значение отключает цвет ANSI. Общий для многих инструментов стандарт с [no-color.org](https://no-color.org). То же, что `--no-color` |
| `CLEANUP_NO_COLOR` | `0` | Собственный переключатель цвета linux-cleanup. Задайте `1`, чтобы отключить цвет только здесь |
| `LINUX_CLEANUP_LOG_DIR` | `~/.linux-cleanup/logs/` (npx / npm) или `<repo>/logs/` (клон) | Куда пишутся журналы сеансов. Создаётся, если нет |
| `LINUX_CLEANUP_REPORTS_DIR` | `~/.linux-cleanup/reports/` или `<repo>/reports/` | Куда пишутся JSON-записи сеансов. Создаётся, если нет |
| `LINUX_CLEANUP_DATA_HOME` | не задана — используется родитель каталога журналов | Общий родитель для `logs/`, `reports/` и `feedback/` |
| `LINUX_CLEANUP_NPX` | не задана | **Внутренняя.** Запускатель Node ставит `1`. Не задавайте её сами |
| `LINUX_CLEANUP_LAUNCHER` | не задана | **Внутренняя.** Запускатель Node ставит `node`; настольное приложение ставит `desktop`, и тогда CLI пропускает свою проверку обновлений, потому что приложение делает свою (с 2.1.0). Не задавайте её сами |
| `XDG_CONFIG_HOME` | `~/.config` | Где ищутся `personal-roots.txt` и `project-roots.txt` |

## Перенаправить весь вывод

`LINUX_CLEANUP_DATA_HOME` — единственный рычаг, который переносит всё: журналы, записи и пакеты обратной связи:

```bash
export LINUX_CLEANUP_DATA_HOME="/mnt/secure/linux-cleanup"
linux-cleanup --scan
```

:::caution Каталог создаётся, точка монтирования — нет
Инструмент создаёт `logs/`, `reports/` и `feedback/` под указанным путём. Саму точку монтирования он **не** создаёт и не проверяет. Укажите несмонтированный путь — и вывод молча окажется на нижележащей файловой системе.

Прежде чем полагаться на это, убедитесь, что цель смонтирована и доступна для записи.
:::

Для более тонкой настройки `LINUX_CLEANUP_LOG_DIR` и `LINUX_CLEANUP_REPORTS_DIR` переопределяются по отдельности и имеют приоритет над корнем данных.

## Управление цветом

```bash
export NO_COLOR=1          # всё на этой машине, все инструменты
export CLEANUP_NO_COLOR=1  # только linux-cleanup
linux-cleanup --no-color   # только этот запуск
```

`CLEANUP_NO_COLOR` нужен, когда вы хотите цвет во всех остальных инструментах и простой вывод в этом — обычно при передаче вывода туда, где портятся управляющие последовательности.

## Настройка сканируемых корней

Два файла в `$XDG_CONFIG_HOME` (по умолчанию `~/.config`) определяют, какие каталоги обходят сканеры личных файлов и проектов:

| Файл | Кто использует | Корни по умолчанию |
|---|---|---|
| `personal-roots.txt` | [`--stale`](../modes/personal-stale-files.md) | `~/Downloads`; защищённые корни вроде `~/Desktop` игнорируются |
| `project-roots.txt` | [`--node-modules`](../modes/node-modules-finder.md) | Ваши каталоги проектов |

Один путь на строку. Это следует [спецификации XDG Base Directory](https://specifications.freedesktop.org/basedir-spec/), так что `XDG_CONFIG_HOME` переносит оба файла.

:::danger Корень в `personal-roots.txt` расширяет то, что может быть удалено
Сканер личных файлов [только интерактивный](../safety/guards.md#guard-3--personal-data-is-interactive-only), поэтому без вашего подтверждения по каждому файлу ничего не удаляется. Но добавленный корень — это каталог, содержимое которого начнёт появляться в списках кандидатов.

[Список разрешённых путей](./protected-paths.md) по-прежнему действует и по-прежнему главнее: добавив сюда `~/Documents`, вы не сделаете его удаляемым.
:::

## Для CI и скриптов

```bash
NO_COLOR=1 linux-cleanup --scan > /tmp/scan.log
```

Отдельное сканирование не создаёт JSON-отчёт о сеансе пошагового сценария. В скриптах проверяйте [код выхода](./exit-codes.md) или используйте [`--json-events`](./json-events.md) для структурированного вывода.

## Что он не читает

- `PATH` — разве что чтобы определить, какие необязательные инструменты установлены
- `USER` и `LOGNAME` — разве что для заголовка журнала
- Историю, псевдонимы и настройки вашей оболочки — [`--doctor`](../modes/doctor.md) единственный режим, читающий файлы инициализации оболочки, и только чтобы проверить, подключена ли среда выполнения
- Никаких удалённых или сетевых настроек. Их просто нет

Если `$HOME` не задан, скрипт сразу прерывается, а не гадает. См. [Устранение неполадок](../troubleshooting.md#home-is-not-set).
