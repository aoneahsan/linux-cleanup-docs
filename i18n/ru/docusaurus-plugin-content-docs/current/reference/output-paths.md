# Пути вывода

**Весь вывод лежит под одним корневым каталогом данных.** Каким именно — зависит от способа установки, и оба можно переопределить.

## Структура {#layout}

```text
$DATA_HOME/
├── logs/
│   ├── cleanup-<YYYY-MM-DD_HHMMSS>.log     # по одному на сеанс
│   └── cron.log                             # дописывается еженедельным cron
├── reports/
│   ├── report-<YYYY-MM-DD_HHMMSS>.json     # запись пошагового сценария, если не отключена
│   ├── report-<YYYY-MM-DD_HHMMSS>.md       # создаётся --export md
│   └── report-<YYYY-MM-DD_HHMMSS>.html     # создаётся --export html
└── feedback/
    ├── debug-bundle-<YYYY-MM-DD_HHMMSS>.tar.gz   # создаётся --debug-bundle
    └── crash-<YYYY-MM-DD_HHMMSS>.tar.gz          # создаётся автоматически при сбое
```

## Значения по умолчанию для способов установки {#per-install-defaults}

| Способ установки | `$DATA_HOME` |
|---|---|
| `npx linux-cleanup` | `~/.linux-cleanup/` |
| `npm install -g linux-cleanup` | `~/.linux-cleanup/` |
| `git clone` | Сам каталог клона |

Разница сделана намеренно. `npx` запускает пакет из временного каталога кэша npm, который очищается, так что записанный туда вывод пропал бы; `~/.linux-cleanup/` сохраняется между запусками. Клон и так лежит в постоянном месте, поэтому вывод остаётся рядом с исходниками.

Переопределить можно оба через [`LINUX_CLEANUP_DATA_HOME`](./environment-variables.md) или отдельно каталоги журналов и записей.

## Хранение {#retention}

| Путь | Автоочистка | Примечания |
|---|---|---|
| `logs/cleanup-*.log` | Только с `--cleanup-logs` | Этот флаг в конце удаляет журнал **этого запуска**. Прежние журналы остаются |
| `logs/cron.log` | Никогда | Никогда не ротируется. Ротируйте сами, если разрастётся |
| `reports/*.json` | **Никогда** | Долговременный журнал аудита |
| `reports/*.md`, `*.html` | **Никогда** | Создаются по запросу и удаляются по запросу |
| `feedback/*.tar.gz` | **Никогда** | Вы решаете, когда они больше не нужны |

`--cleanup-logs` — единственное автоматическое удаление, которое инструмент делает со своим выводом, и оно касается только файлов `.log`.

## Размер и хранение {#size-and-retention}

Размер журналов и пакетов зависит от путей и событий запуска. Прежде чем удалять старые записи, посмотрите, что накопилось. Чтобы осознанно проредить старые файлы:

```bash
find ~/.linux-cleanup/logs/    -name 'cleanup-*.log' -mtime +90 -delete
find ~/.linux-cleanup/reports/ -name 'report-*'      -mtime +90 -delete
```

Ротация журнала cron:

```bash
mv ~/.linux-cleanup/logs/cron.log ~/.linux-cleanup/logs/cron.log.old
touch ~/.linux-cleanup/logs/cron.log
```

## Права {#permissions}

Файлы принадлежат пользователю, запустившему инструмент. Действующие права смотрите через `stat` на своей машине: важны и права каталогов, заданные инструментом, и umask процесса. Не делитесь журналом или пакетом, не прочитав его.

## Что содержат эти файлы {#what-these-files-contain}

:::caution Журналы и пакеты содержат ваши пути
Журнал сеанса называет каждый затронутый путь, то есть содержит имена каталогов вашей машины — имена проектов, а иногда и имена файлов из `~/Downloads`.

Всё это остаётся локально и никуда не отправляется, но просмотрите пакет перед отправкой по почте:

```bash
tar -tzf ~/.linux-cleanup/feedback/debug-bundle-*.tar.gz
```

См. [Отправить отчёт об ошибке](../guides/send-a-bug-report.md).
:::

Ничто здесь не содержит **содержимого** файлов — только пути, размеры и отметки времени. Это записи о том, что произошло, а не копии удалённого. См. [Восстановление](../recovery.md).
