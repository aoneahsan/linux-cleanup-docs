# Пошаговый сценарий (по умолчанию)

**Запуск `linux-cleanup` без флагов открывает пошаговый сценарий: десять шагов по всем категориям очистки, и каждый спрашивает, прежде чем что-то делать.** Это рекомендуемый способ интерактивной работы с инструментом.

```bash
linux-cleanup          # или: linux-cleanup -w / --walkthrough
```

## Десять шагов {#the-ten-steps}

| # | Шаг | Что удаляет | Примечания |
|---|---|---|---|
| 1 | Кэш менеджеров пакетов | Можно создать заново | yarn, npm, npx, pnpm, pip, composer, bun, deno |
| 2 | Кэш приложений | Можно создать заново | Браузеры, Gradle, Cypress, Playwright, Zoom, VSIX редакторов |
| 3 | Данные инструментов разработчика | Только давно не используемое | Android AVD, pub-cache, анализ Dart, flatpak |
| 4 | Старые расширения редакторов | Давно не используемое + вытесненное | VS Code / Cursor |
| 5 | Давно не используемые `node_modules` | **Интерактивно** | Проекты, простаивающие дольше порога |
| 6 | Недокачанные и брошенные загрузки | **Интерактивно** | `.crdownload`, `.part`, `.fdmdownload` |
| 7 | Давно не используемые личные файлы | **Интерактивно** | Крупные неиспользуемые файлы в `~/Downloads` и заданных вами личных корнях |
| 8 | Очистка системы (sudo) | Система | apt, журнал, snap, `/tmp`, кэш страниц |
| 9 | Итоговая проверка размеров | Ничего | Сводка только для чтения |
| 10 | Создание читаемого отчёта | Ничего | Экспорт в Markdown / HTML — нужен `jq` |

Шаги 5, 6 и 7 — [только интерактивные](../safety/guards.md#guard-3--personal-data-is-interactive-only). Их нельзя подтвердить автоматически, а шаг 7 — единственный во всём инструменте, который может удалить что-то действительно незаменимое.

## Как устроены вопросы {#how-the-prompts-work}

Два уровня подтверждения.

**На уровне шага** вы решаете, что делать со всей категорией:

| Клавиша | Действие |
|---|---|
| `a` | Выполнить шаг. Это вариант по умолчанию — выбирается клавишей Enter |
| `s` | Полностью пропустить шаг |
| `q` | Сразу выйти из сценария, сохранив сделанное |

**На уровне цели**, внутри выбранного шага, у каждого пункта своё подтверждение `[Y/n]` или `[y/N]`. Заглавная буква — вариант по умолчанию.

Так что `a` на уровне шага не обязывает удалять всё, что в нём есть, — вы по-прежнему видите каждую цель и отвечаете на неё.

## Нарастающие итоги {#running-totals}

После каждого выполненного шага инструмент печатает измеренное изменение и итог сеанса на этот момент.

Итоговая сводка показывает свободное место на диске до и после. Это значение измеряется через `df`, поэтому отражает всё, что происходит на машине: если во время сеанса шла сборка, показанный объём освобождённого может оказаться меньше суммы по шагам и даже отрицательным. Это не ошибка; см. [Устранение неполадок](../troubleshooting.md#disk-usage-grew-during-the-session).

## Досрочный выход {#quitting-early}

`q` на любом вопросе шага или `Ctrl-C` в любой момент корректно завершают сеанс:

- Уже выполненные удаления остаются безвозвратными; какие шаги успели начаться до прерывания, смотрите в журнале
- `Ctrl-C` завершает работу с кодом `130`, который [обработчик сбоев намеренно игнорирует](../reference/exit-codes.md#how-the-crash-trap-decides), поэтому пакет сбоя не создаётся
- Шаги, до которых не дошло, записываются в отчёт как пропущенные

## Отчёт о сеансе {#the-session-report}

Сценарий пишет JSON-отчёт в `~/.linux-cleanup/reports/report-<timestamp>.json`, если не указаны `--no-report` или `--dry-run`. В нём состояние и освобождённые байты по каждому шагу, диск и память до и после и итоги сеанса. Полный список полей: [Схема отчёта](../reference/report-schema.md).

Шаг 10 при желании преобразует его в Markdown и HTML. Для этого шага нужен `jq`; без него шаг записывается как `skipped (jq missing)`, а JSON всё равно пишется.

```bash
linux-cleanup --no-report    # не создавать JSON; журналы всё равно пишутся
```

## Полезные сочетания параметров {#options-worth-combining}

```bash
linux-cleanup -d 30          # порог простоя 30 дней вместо 100
linux-cleanup --purge-all    # полностью отключить порог простоя
linux-cleanup --no-color     # вывод без цвета
linux-cleanup --cleanup-logs # удалить журнал этого запуска в конце
```

:::danger `--purge-all` меняет то, что удаляют шаги 1–4
Когда [порог простоя](../safety/guards.md#guard-2--the-staleness-gate) отключён, шаги очистки кэша стирают цели целиком, а не прореживают неиспользуемые файлы. Под это попадают дистрибутивы Gradle wrapper, браузеры Playwright и бинарные файлы Cypress, которые могут вам ещё понадобиться. Баннер перед запуском сообщает, какая стратегия действует.
:::

| Ситуация | Лучший режим |
|---|---|
| Нужна только одна категория | [Меню](./menu.md) или [TUI](./tui.md) |
| Без присмотра или из cron | [Полностью безопасная очистка](./all-safe.md) с `-y` |
| Хотите посмотреть, а не удалять | [Сканирование](./scan.md) |
| Нужна визуальная версия этого режима | [TUI](./tui.md) |
