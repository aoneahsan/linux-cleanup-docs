# Поиск заброшенных node_modules

**`--node-modules` находит каталоги `node_modules` в проектах, которых вы не касались `--days` или больше дней, и предлагает удалить каждый.** Сколько места освободится, зависит от проектов на этой машине.

```bash
linux-cleanup --node-modules          # по умолчанию 100 дней
linux-cleanup --node-modules -d 90
```

## Только интерактивно {#interactive-only}

Этот режим требует подтверждения по каждому проекту и **игнорирует `--yes`**. Он не входит в [`--all-safe`](./all-safe.md) и не может работать без присмотра. См. [барьер 3](../safety/guards.md#guard-3--personal-data-is-interactive-only).

## Что он ищет {#what-it-looks-for}

Он просматривает корни ваших проектов в поисках каталогов `node_modules`, чей проект простаивает дольше порога, и показывает для каждого размер и число дней простоя. Вложенные `node_modules` внутри уже перечисленного каталога отдельно не считаются.

Корни проектов настраиваются в `project-roots.txt` внутри `$XDG_CONFIG_HOME` (по умолчанию `~/.config`). См. [Переменные окружения](../reference/environment-variables.md).

## Почему это обычно безопасно {#why-this-is-usually-safe}

`node_modules` — самое надёжно восстанавливаемое на машине разработчика: `yarn install` или `npm install` соберёт его заново по lock-файлу.

Две оговорки, которые стоит знать, прежде чем соглашаться на всё:

:::caution Два случая, когда это всё же может обойтись дорого
**Пропатченная зависимость.** Если вы правили файл прямо в `node_modules`, а не через `patch-package` или patch yarn, этой правки больше нигде нет — ни в реестре, ни в lock-файле.

**Нет lock-файла, нет сети.** Для переустановки нужен доступ к реестру и lock-файл. Проект без закоммиченного lock-файла может собрать другое дерево зависимостей, а машина без сети — вообще ничего.
:::

Оба случая редки, и инструмент не может распознать ни один из них. Если что-то из этого относится к проекту в списке, откажитесь от него.

## Что он не трогает {#what-it-does-not-touch}

- Исходный код проекта — только каталог `node_modules` внутри
- Lock-файлы, `package.json` и всё остальное в проекте
- Проекты, которых касались в пределах порога
- Ничего из [списка защищённых путей](../reference/protected-paths.md)

## Агрессивное освобождение {#reclaiming-aggressively}

```bash
linux-cleanup --node-modules -d 30
```

Понижение порога расширяет список кандидатов. При 30 днях появятся проекты, над которыми вы ещё иногда работаете, поэтому читайте список, а не соглашайтесь на всё сразу: ошибка обойдётся переустановкой — недорого, но не бесплатно.
