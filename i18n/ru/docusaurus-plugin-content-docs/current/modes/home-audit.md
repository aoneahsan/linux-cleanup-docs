# Проверка домашнего каталога

**`--audit` перечисляет 20 самых крупных элементов в `$HOME`, отсортированных по размеру.** Он ничего не удаляет, и ему всё равно, может ли инструмент очистить найденное.

```bash
linux-cleanup --audit
```

## Чем это отличается от `--scan` {#why-this-is-different-from---scan}

[`--scan`](./scan.md) измеряет категории, которые linux-cleanup умеет очищать. `--audit` измеряет ваш домашний каталог — и всё.

В этом и смысл. Если диск на самом деле заполнил образ виртуальной машины на 60 GB, скачанный набор данных или библиотека Steam, `--scan` о них не скажет никогда, а `--audit` поставит их в начало списка.

| | `--audit` | `--scan` |
|---|---|---|
| Охват | Всё в `$HOME` | Только категории, которые можно очистить |
| Отвечает на вопрос | Что занимает мой диск? | Что может освободить этот инструмент? |
| Пишет JSON-отчёт о сеансе | Нет | Нет |
| Удаляет | Никогда | Никогда |

## Обычный порядок {#the-usual-workflow}

```bash
linux-cleanup --audit    # что занимает много?
linux-cleanup --scan     # что может освободить этот инструмент?
```

Если верхние строки проверки есть и в сканировании, инструмент поможет. Если нет, вы узнали нечто более полезное: место занято там, куда этот инструмент не заходит, и с этим можно разобраться напрямую.

Типичные крупные вещи, которые linux-cleanup **не** очищает:

- Образы виртуальных машин и хранилища контейнеров (`~/.local/share/libvirt`, `~/.local/share/docker`)
- Игровые библиотеки (Steam, Lutris)
- Наборы данных, веса моделей, медиатеки
- Всё в `~/Documents`, `~/Pictures`, `~/Music`, `~/Videos` — все они [защищены](../reference/protected-paths.md)

## Разбор находки {#following-up-on-a-finding}

```bash
du -sh ~/.local/share/*      | sort -rh | head -20
du -sh ~/*                   | sort -rh | head -20
```

`--audit` — быстрый первый проход; `du` сужает поиск, когда понятно, куда смотреть.
