# Отчёты

**Пошаговый сценарий пишет JSON-запись сеанса** в `~/.linux-cleanup/reports/report-<timestamp>.json`, если не указаны `--no-report` или `--dry-run`. Другие режимы такую запись не создают. Существующие записи автоматически не удаляются.

Markdown и HTML — необязательные преобразования, которые создаются по запросу.

```bash
linux-cleanup --reports              # интерактивный менеджер
linux-cleanup --export both latest   # неинтерактивное преобразование
```

## Что содержит запись сеанса {#what-a-session-record-contains}

| Раздел | Содержит |
|---|---|
| `schema_version` | Сейчас `1` |
| `credits` | Название, версия, домашняя страница, лицензия и сведения об авторе инструмента |
| `meta` | Отметки времени, длительность, хост, пользователь, режим, порог простоя, путь к журналу, способ запуска |
| `disk` | Использование файловой системы до и после |
| `memory` | Использование памяти до и после |
| `steps` | По записи на шаг: номер, название, состояние, освобождённые байты |
| `totals` | Всего освобождено байтов, итог в читаемом виде, выполненные и пропущенные шаги |

Полное описание всех полей: [Схема отчёта](../reference/report-schema.md).

## Интерактивный менеджер {#the-interactive-manager}

```bash
linux-cleanup --reports
```

Показывает прошлые сеансы и позволяет открыть любой из них, преобразовать в Markdown или HTML, открыть HTML в браузере или удалить.

Если `jq` не установлен, варианты преобразования скрыты — см. [ниже](#jq-is-required-for-conversion).

## Экспорт {#exporting}

Без вопросов — для скриптов и привычек:

```bash
linux-cleanup --export both latest   # Markdown + HTML из самой свежей записи
linux-cleanup --export html all      # все записи в HTML
linux-cleanup --export md 3          # запись № 3 в Markdown
```

| Аргумент | Принимает |
|---|---|
| Формат | `md`, `html`, `both` |
| Идентификатор | номер записи, `latest` или `all` |

Результат кладётся рядом с JSON с той же отметкой времени в имени файла. HTML самодостаточен — встроенный CSS, поддержка тёмной темы, никаких внешних ресурсов, — поэтому его можно отправить по почте или заархивировать одним файлом.

## Для преобразования нужен `jq` {#jq-is-required-for-conversion}

:::note JSON пишется всегда; преобразование — необязательная часть
Без `jq` пошаговый сценарий всё равно создаёт JSON-запись. Недоступен только экспорт в Markdown и HTML, а шаг 10 сценария записывается как `skipped (jq missing)`.

```bash
sudo apt install jq      # Debian / Ubuntu
sudo dnf install jq      # Fedora / RHEL
sudo pacman -S jq        # Arch
```
:::

Сгенерированный HTML экранирует каждое значение из JSON фильтром `@html` в `jq`, так что испорченные входные данные не могут внедрить разметку в страницу.

## Запросы к JSON напрямую {#querying-the-json-directly}

JSON предназначен для чтения программами:

```bash
# Сколько освобождено за самый свежий сеанс
jq '.totals.total_reclaimed_human' ~/.linux-cleanup/reports/report-*.json | tail -1

# Каждый шаг, который действительно выполнялся, в самом свежем сеансе
jq '.steps[] | select(.status == "ran") | {title, freed_bytes}' \
  "$(ls -t ~/.linux-cleanup/reports/report-*.json | head -1)"

# Сколько освобождено за все записанные сеансы
jq -s 'map(.totals.total_reclaimed_bytes) | add' ~/.linux-cleanup/reports/report-*.json
```

## Хранение {#retention}

Эти записи **никогда** не удаляются автоматически — даже `--cleanup-logs`, который удаляет только файл журнала текущего запуска.

Чтобы проредить их самостоятельно:

```bash
find ~/.linux-cleanup/reports/ -name 'report-*' -mtime +90 -delete
```

Чтобы не создавать запись для одного запуска, укажите `--no-report`; журнал всё равно пишется.

## Это записи, а не резервные копии {#these-are-records-not-backups}

:::danger Запись сеанса — сводка шагов, а не резервная копия
Она фиксирует шаги и наблюдения о диске, а не полный список всех удалённых файлов. В ней нет удалённого содержимого, и ничто в ней не может ничего восстановить. После нежелательного удаления она полезна тем, что помогает понять, что восстанавливать из своей резервной копии или что скачать снова. См. [Восстановление](../recovery.md).
:::
