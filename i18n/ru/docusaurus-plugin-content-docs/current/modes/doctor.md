# Doctor

**`--doctor` находит среды выполнения, которые есть на диске, но не подключены в настройках оболочки, и предлагает добавить недостающий блок инициализации.** Появился в [1.1.0](../changelog.md#110--2026-05-10).

```bash
linux-cleanup --doctor
```

Это режим для случая, когда вы точно установили pnpm, а видите `pnpm: command not found`.

## Только добавляет {#additive-only}

:::note Doctor никогда не удаляет и не правит существующие строки
Он **дописывает** стандартный блок инициализации — и только после вашего подтверждения. Он ничего не меняет, не переставляет и не удаляет в уже существующих настройках оболочки.

Файлы инициализации оболочки дополнительно защищены на уровне удаления: `safe_rm` отклоняет любой путь с именем файла `.bashrc`, `.zshrc`, `.profile`, `.bash_aliases` и подобным, где бы он ни находился. См. [Защищённые пути](../reference/protected-paths.md#protected-basenames).
:::

## Что он проверяет {#what-it-checks}

| Среда | Признак | Что добавляет |
|---|---|---|
| `nvm` | есть `~/.nvm`, нет инициализации `NVM_DIR` | Стандартный блок загрузки nvm |
| `pnpm` | есть `~/.local/share/pnpm`, нет в `PATH` | Экспорт `PNPM_HOME` и добавление в `PATH` |
| `bun` | есть `~/.bun`, нет в `PATH` | Блок инициализации Bun |
| `deno` | есть `~/.deno`, нет в `PATH` | Добавление Deno в `PATH` |
| `cargo` | есть `~/.cargo`, нет в `PATH` | `. "$HOME/.cargo/env"` |

## Как это обычно случается {#how-this-usually-happens}

Установщик записывает блок инициализации в файл, который ваша оболочка не читает. `~/.profile` читают только оболочки входа; если есть `~/.bash_profile`, он его перекрывает; изменение `~/.bashrc` никогда не доходит до сеанса `zsh`. Среда устанавливается нормально, а потом будто исчезает.

То же бывает после переноса репозитория dotfiles между машинами или смены оболочки входа.

## После этого {#afterwards}

Перезапустите оболочку, иначе покажется, что изменение не сработало:

```bash
source ~/.bashrc     # или ~/.zshrc
```

Затем проверьте:

```bash
command -v pnpm && pnpm --version
```

## Связь с проверкой глобальных пакетов {#its-relationship-to-the-globals-audit}

[`--globals`](./globals-audit.md) работает, даже когда менеджера пакетов нет в `PATH`, — он переходит к осмотру файловой системы. Так что если проверка показывает глобальные пакеты pnpm, а сам `pnpm` не находится, решение — `--doctor`.
