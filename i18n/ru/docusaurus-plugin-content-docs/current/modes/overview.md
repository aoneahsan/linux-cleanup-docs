# Обзор режимов

**У linux-cleanup одна точка входа, а режим выбирается одним флагом.** Запуск без флагов открывает [пошаговый сценарий](./walkthrough.md).

Режимы взаимоисключающие — указывайте один. Параметры вроде `--days` и `--yes` с ними сочетаются.

## Только чтение — никогда ничего не удаляют {#read-only--never-deletes-anything}

Эти режимы не удаляют цели очистки. Они всё равно могут записать локальный журнал, а проверка выпусков при наличии сети может прочитать публичную запись.

| Режим | Флаг | Показывает |
|---|---|---|
| [Сканирование](./scan.md) | `-s` `--scan` | Все категории кэша с текущими размерами |
| [Проверка домашнего каталога](./home-audit.md) | `--audit` | 20 самых крупных элементов в `$HOME` |
| [Проверка глобальных пакетов](./globals-audit.md) | `--globals` | Глобальные пакеты npm/pnpm/yarn/bun/deno |
| Список целей | `--list-targets` | Все пути, которые может затронуть инструмент, и защищённый список |
| Самопроверка | `--self-test` | Проверка зависимостей, синтаксиса и защит |
| Версия | `-V` `--version` | Версия и автор |

## Очистка — данные, которые можно создать заново {#cleanup--regenerable-data}

Эти режимы могут удалять цели очистки. `--yes` пропускает пакетное подтверждение только в `--all-safe`; остальные режимы сохраняют свои вопросы.

| Режим | Флаг | Поведение |
|---|---|---|
| [Пошаговый сценарий](./walkthrough.md) | _(по умолчанию)_ `-w` | Десять шагов с вопросом перед каждым |
| [Меню](./menu.md) | `-m` `--menu` | Нумерованное меню — выберите одну категорию |
| [TUI](./tui.md) | `-t` `--tui` | То же в окне whiptail/dialog |
| [Полностью безопасная очистка](./all-safe.md) | `-a` `--all-safe` | Весь кэш, который можно создать заново, за один проход |
| [Расширения редакторов](./editor-extensions.md) | `--editor-ext` | Вытесненные версии VS Code / Cursor |
| [Очистка системы](./system-cleanup.md) | `--system` | apt, журнал, snap, `/tmp`, кэш страниц — нужен `sudo` |

## Очистка — только интерактивно {#cleanup--interactive-only}

Личные данные и данные проектов. Эти режимы **игнорируют `--yes`** и требуют подтверждения по каждому пункту. См. [барьер 3](../safety/guards.md#guard-3--personal-data-is-interactive-only).

| Режим | Флаг | Находит |
|---|---|---|
| [Давно не используемые личные файлы](./personal-stale-files.md) | `-p` `--stale` | Крупные неиспользуемые файлы в `~/Downloads` и настроенных незащищённых корнях |
| [Недокачанные загрузки](./partial-downloads.md) | `--partials` | `.fdmdownload`, `.crdownload`, `.part` |
| [Поиск node_modules](./node-modules-finder.md) | `--node-modules` | Каталоги зависимостей проектов, простаивающие N+ дней |

## Вывод, исправления и настройка {#output-repair-and-setup}

| Режим | Флаг | Назначение |
|---|---|---|
| [Отчёты](./reports.md) | `--reports` | Список, преобразование и просмотр прошлых отчётов |
| [Экспорт](./reports.md#exporting) | `--export FMT ID` | Неинтерактивное преобразование |
| [Doctor](./doctor.md) | `--doctor` | Починить инициализацию оболочки для nvm, pnpm, bun, deno, cargo |
| [Диагностика скорости](./speed.md) | `--speed` | Измерить нагрузку и автозапуск; необязательные исправления спрашивают отдельно |
| Обратная связь | `--feedback` | Инструкции для отчёта об ошибке, необязательный черновик mailto |
| Отладочный пакет | `--debug-bundle` | Упаковать последний журнал и отчёт в tar.gz |
| Установить псевдоним | `--install-alias` | Добавить псевдоним оболочки `cleanup` |
| Установить cron | `--install-cron` | Еженедельный `--all-safe -y`, по воскресеньям в 03:00 |
| Удалить псевдоним / cron | `--uninstall-alias` `--uninstall-cron` | Убрать что-либо из этого |

## Как выбрать режим {#choosing-a-mode}

| Цель | Режим |
|---|---|
| Первый запуск инструмента | `--self-test`, `--scan`, `--all-safe --dry-run` |
| Освободить место сейчас, сохраняя контроль | _(пошаговый сценарий по умолчанию)_ |
| Освободить место сейчас, без вопросов | `--all-safe -y` |
| Одна конкретная категория | `--menu` / `--tui` |
| Еженедельное обслуживание без присмотра | `--all-safe -y` + `--install-cron` |
| Максимум места перед переустановкой системы | `--all-safe -y --purge-all` |
| Понять, что съедает диск | `--audit`, `--scan` |
| Накопились старые сторонние проекты | `--node-modules` |
| `command not found` после установки | `--doctor` |

## Параметры, которые сочетаются с режимами {#options-that-combine-with-modes}

| Параметр | По умолчанию | Действие |
|---|---|---|
| `-d N` `--days N` | 100 | Порог простоя. Чем меньше, тем агрессивнее |
| `--purge-all` | выкл. | Отключает порог простоя — полная очистка |
| `-y` `--yes` | выкл. | Автоматически подтверждает кэш, который можно создать заново. Только с `--all-safe` |
| `--no-report` | выкл. | Не создавать JSON-отчёт. Журналы всё равно пишутся |
| `--cleanup-logs` | выкл. | Удалить журнал этого запуска в конце. Отчёты сохраняются всегда |
| `--no-color` | выкл. | Отключить цвета ANSI. Учитывается и `NO_COLOR` |
| `-n` `--dry-run` | выкл. | Пройти выбранную очистку без удаления; локальный журнал и состояние проверки обновлений всё же могут записаться |
| `--json-events` | выкл. | NDJSON для `--scan` или неинтерактивного `--all-safe --yes` |

Подробно: [Флаги CLI](../reference/cli-flags.md) и [матрица режимов](../reference/modes-matrix.md).
