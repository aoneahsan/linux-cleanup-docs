# Полностью безопасная очистка (пакетом)

**`--all-safe` за один проход очищает весь кэш, который можно создать заново.** Это режим для обслуживания без присмотра и единственный, на который действует `--yes`.

```bash
linux-cleanup --all-safe        # одно подтверждение на весь пакет
linux-cleanup --all-safe -y     # без вопросов — вариант для cron
```

## Что здесь значит «безопасно» {#what-safe-means-here}

Безопасно — значит **можно создать заново**: кэш менеджеров пакетов, кэш браузеров и приложений, давно не используемые данные инструментов разработчика. Это **не** значит «без риска» и не значит «обратимо» — удаление по-прежнему [безвозвратно](../safety/irreversibility.md).

Чего `--all-safe` не тронет никогда, с `--yes` или без:

- Личные файлы в `~/Downloads`, `~/Desktop` и где-либо ещё
- Недокачанные загрузки
- Каталоги `node_modules`
- Ничего из [списка защищённых путей](../reference/protected-paths.md)
- Глобально установленные пакеты и файлы инициализации оболочки

Эти категории [только интерактивные по замыслу](../safety/guards.md#guard-3--personal-data-is-interactive-only) и в этот режим просто не входят. Поэтому `--all-safe -y` допустимо запускать из cron.

С версии 1.1.0 режим также выполняет **проверку при запуске**: если какой-либо защищённый каталог среды выполнения попадёт в список целей, работа прервётся с сообщением `BUG:`. Так будущая регрессия громко провалится, а не удалит то, что не следует.

## `--yes` и его пределы {#--yes-and-its-limits}

`-y` / `--yes` автоматически подтверждает удаление кэша. Он действует только с `--all-safe`; интерактивные режимы по правилу его игнорируют.

```bash
linux-cleanup --all-safe -y
```

:::caution С `-y` вы увидите решения только после
Список разрешённых путей и порог простоя по-прежнему действуют, но журнал вы читаете после запуска. Отдельный полностью безопасный запуск не пишет JSON-отчёт о сеансе пошагового сценария. Перед первым запуском посмотрите [`--scan`](./scan.md) и `--all-safe --dry-run`.
:::

## Прореживание и что остаётся {#pruning-and-what-survives}

По умолчанию `--all-safe` прореживает подходящие файлы кэша, у которых и `atime`, и `mtime` старше `--days` (по умолчанию 100). Распакованные пакеты и версионированные инструменты обрабатываются целиком по своим правилам простоя. Читаемый вывод сообщает выборочные результаты; чтобы увидеть предлагаемые пути до удаления, используйте пробный запуск.

```bash
linux-cleanup --all-safe -y            # порог 100 дней
linux-cleanup --all-safe -y -d 30      # агрессивнее
linux-cleanup --all-safe -y --purge-all # барьер выключен — полная очистка
```

:::danger `--purge-all` в задании cron — плохое сочетание
Без присмотра и без порога простоя дистрибутив Gradle wrapper или набор браузеров Playwright может исчезнуть за неделю до того, как понадобится, и никто этого не заметит. Оставьте `--purge-all` для осознанных запусков перед переустановкой системы.
:::

## Еженедельный запуск {#running-it-weekly}

```bash
linux-cleanup --install-cron
```

Это планирует `--all-safe -y` на воскресенье в 03:00 и дописывает вывод в `~/.linux-cleanup/logs/cron.log`. Точная запись и способ её убрать — в разделе [Псевдоним и cron](../guides/alias-and-cron.md).

Если вы пишете запись crontab сами, используйте **абсолютный путь**: минимальный `PATH` cron не найдёт установку в `~/.local/bin`:

```bash
0 3 * * 0 /usr/local/bin/linux-cleanup --all-safe -y --no-report --cleanup-logs >>~/.linux-cleanup/logs/cron.log 2>&1
```

`--cleanup-logs` удаляет журнал этого запуска. Отдельные полностью безопасные запуски не пишут JSON-запись сеанса пошагового сценария, поэтому `--no-report` здесь ничего не добавляет.

## Что сделал запуск из cron {#checking-what-a-cron-run-did}

```bash
tail -100 ~/.linux-cleanup/logs/cron.log
```

Если в журнале cron есть `command not found`, crontab использует имя команды без пути — см. [Устранение неполадок](../troubleshooting.md#cron-entry-runs-but-does-nothing).

## Когда лучше другой режим {#when-to-use-something-else}

| Ситуация | Лучший режим |
|---|---|
| Первый раз на этой машине | [`--scan`](./scan.md), затем `--all-safe --dry-run` |
| Хотите видеть каждое решение | [Пошаговый сценарий](./walkthrough.md) |
| Нужно очистить одну категорию | [Меню](./menu.md) или [TUI](./tui.md) |
| Хотите освободить место и за счёт личных файлов | [Давно не используемые личные файлы](./personal-stale-files.md), интерактивно |
