# Быстрый старт

**Перед удалением проверьте защиты, изучите сканирование и просмотрите выбранный режим.** Сколько места освободится, зависит от путей и файлов на этой машине.

:::caution Не пропускайте шаги 1 и 2
Они занимают две минуты и отличают очистку, которую вы контролировали, от той, о результатах которой вы узнали потом. Этот инструмент [удаляет безвозвратно](../safety/irreversibility.md).
:::

## Шаг 1 — проверьте установку {#step-1--verify-the-install}

```bash
npx linux-cleanup --version
npx linux-cleanup --self-test
```

`--version` показывает, какая у вас сборка. `--self-test` проверяет зависимости и синтаксис оболочки и убеждается, что защиты действительно срабатывают. Успешный запуск заканчивается сообщением об успехе; при любой неудачной проверке код выхода ненулевой, и на этом нужно остановиться.

## Шаг 2 — проверка без удаления {#step-2--audit-deleting-nothing}

```bash
npx linux-cleanup --scan
```

`--scan` работает только на чтение. Он перечисляет корни кэша и их текущий размер, а также других кандидатов и наблюдения о системе. Он ничего не удаляет и не пишет JSON-отчёт о сеансе.

Прочитайте пути, прежде чем продолжить. Размер корня кэша не означает, что весь каталог можно удалить. Отдельно проверьте каждый неожиданный путь и каждый личный файл-кандидат.

## Шаг 3 — предпросмотр очистки {#step-3--preview-the-cleanup}

```bash
npx linux-cleanup --all-safe --dry-run
```

Это проходит полностью безопасный режим очистки кэша, не удаляя файлы и не меняя настройки. Прочитайте предлагаемые действия и решите, запускать ли. Реальное удаление нельзя отменить.

## Шаг 4 — запустите пошаговый сценарий {#step-4--run-the-guided-walkthrough}

```bash
npx linux-cleanup
```

Без флагов запускается [пошаговый сценарий](../modes/walkthrough.md): десять шагов, каждый спрашивает перед действием, с нарастающим итогом освобождённых байтов.

На каждом шаге есть три варианта:

| Клавиша | Действие |
|---|---|
| `a` | Выполнить шаг (по умолчанию — выбирается клавишей Enter) |
| `s` | Пропустить шаг |
| `q` | Сразу выйти из сценария |

Внутри шага у каждой цели своё подтверждение `[Y/n]`. Получается два уровня: пропустить всю категорию или принять её и отклонить отдельные пункты.

Десять шагов по порядку:

1. Кэш менеджеров пакетов
2. Кэш приложений
3. Данные инструментов разработчика
4. Старые расширения редакторов
5. Давно не используемые `node_modules`
6. Недокачанные и брошенные загрузки
7. Давно не используемые личные файлы
8. Очистка системы (sudo)
9. Итоговая проверка размеров
10. Создание читаемого отчёта

:::tip На шагах 6 и 7 не торопитесь
Всё, что до них, можно создать заново. Недокачанные загрузки и давно не используемые личные файлы — нет: читайте каждого кандидата, а не принимайте всё сразу. При первом запуске можно пропустить оба шага клавишей `s`, если хотите разобрать их отдельно позже.
:::

`Ctrl-C` останавливает сценарий с кодом `130`. Уже выполненные удаления остаются безвозвратными. Какие шаги успели пройти до прерывания, видно в журнале.

## Шаг 5 — прочитайте отчёт {#step-5--read-the-report}

Сеанс заканчивается сводкой, где указан журнал и, если он создан, отчёт. Читайте пути, которые показал именно ваш запуск, а не предполагайте фиксированное место для каждого способа установки.

Пошаговый сценарий пишет JSON-отчёт, если не указаны `--no-report` или `--dry-run`. Чтобы преобразовать имеющийся отчёт для чтения или архива, установите `jq` и выполните:

```bash
linux-cleanup --export both latest   # Markdown и HTML рядом с JSON
linux-cleanup --reports              # интерактивный менеджер отчётов
```

См. [Отчёты](../modes/reports.md).

## Шаг 6 — автоматизируйте, когда будете доверять {#step-6--automate-it-once-you-trust-it}

Только после ручного запуска, который вас устроил:

```bash
linux-cleanup --install-alias   # набирайте `cleanup` откуда угодно
linux-cleanup --install-cron    # еженедельно --all-safe -y, по воскресеньям в 03:00
```

Задание cron запускает `--all-safe -y`, который автоматически подтверждает **только кэш, который можно создать заново**. Личные файлы он тронуть не может — [эти режимы игнорируют `--yes`](../safety/guards.md#guard-3--personal-data-is-interactive-only).

Что именно пишет каждая команда и как это убрать, описано в разделе [Псевдоним и cron](../guides/alias-and-cron.md).
