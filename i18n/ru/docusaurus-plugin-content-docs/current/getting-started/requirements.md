# Требования

**linux-cleanup работает в Linux с `bash` 4 или новее и GNU coreutils.** Всё остальное необязательно, и без него инструмент продолжает работать.

## Платформа {#platform}

| | |
|---|---|
| **Операционная система** | Только Linux. Пакет npm объявляет `"os": ["linux"]` и откажется устанавливаться в другой системе |
| **Оболочка** | `bash` ≥ 4.0 |
| **Node.js** | ≥ 14 — **только** для `npx` и `npm install -g`. Для git clone не нужен |
| **Права** | Работает от обычного пользователя. `sudo` запрашивает только [`--system`](../modes/system-cleanup.md) |

macOS и WSL стоит рассмотреть отдельно:

- **macOS не поддерживается.** Пути, флаги `find` и менеджеры пакетов там другие. Для macOS есть родственный инструмент; не запускайте этот на Mac.
- **WSL работает на стороне Linux.** Перед очисткой проверьте все символические ссылки из `$HOME` в `/mnt/c/`. [Список разрешённых путей](../reference/protected-paths.md) разрешает ссылки, но защищённые пути домашнего каталога Linux не означают, что защищён каждый каталог Windows.

## Обязательные команды {#required-commands}

Они есть практически в любом распространённом дистрибутиве: `bash`, `find`, `du`, `df`, `rm`, `awk`, `sort`, `grep`, `sed`, `stat`, `realpath`.

`realpath` важнее остальных: именно он разрешает символические ссылки перед проверкой защищённых путей. В минимальном образе контейнера без GNU coreutils установите их перед запуском.

```bash
npx linux-cleanup --self-test
```

`--self-test` проверяет каждую обязательную команду и называет первую отсутствующую с подсказкой, как это исправить. Запускайте его перед любым удалением.

## Необязательные зависимости {#optional-dependencies}

Каждая открывает одну возможность. Без неё эта возможность недоступна, а остальной инструмент работает как обычно.

| Зависимость | Что открывает | Без неё |
|---|---|---|
| `jq` | [Экспорт отчётов](../modes/reports.md) в Markdown / HTML | JSON-отчёты по-прежнему пишутся; преобразование недоступно |
| `whiptail` | Визуальное [меню TUI](../modes/tui.md) | `--tui` переключается на меню CLI с подсказкой по установке |
| `dialog` | Запасной вариант TUI без `whiptail` | Как выше |
| `snap` | Удаление отключённых ревизий snap в `--system` | Этот шаг аккуратно пропускается |
| `crontab` | [Еженедельный установщик cron](../guides/alias-and-cron.md) | `--install-cron` не сможет работать |
| `numfmt` | Читаемые размеры в байтах | Показываются сырые числа байтов |
| `xdg-open` | Открытие HTML-отчётов в браузере | Откройте файл вручную |
| `less` | Постраничный просмотр JSON в менеджере отчётов | Читайте файл напрямую |
| `lsb_release` | Более точное определение дистрибутива в пакетах обратной связи | Пакет всё равно создаётся |

### Установка двух главных {#installing-the-two-that-matter}

`jq` (экспорт отчётов) и `whiptail` (визуальное меню) — те две, что нужны большинству.

```bash
# Debian / Ubuntu / Mint
sudo apt install jq whiptail

# Fedora / RHEL / Rocky
sudo dnf install jq newt

# Arch / Manjaro
sudo pacman -S jq libnewt

# openSUSE
sudo zypper install jq newt
```

В дистрибутивах на основе RPM программа `whiptail` входит в пакет `newt`, а в Arch — в `libnewt`.

## Поддержка дистрибутивов {#distro-coverage}

Очистка кэша внутри `$HOME` — а это подавляющая часть того, что освобождает инструмент, — одинаково работает в любом дистрибутиве Linux.

:::warning `--system` — только Debian/Ubuntu
Режим с sudo напрямую вызывает `apt` и `dpkg`, без определения дистрибутива и без защиты. В Fedora, Arch или openSUSE его шаги с пакетами завершаются ошибкой «command not found».

Подробно о том, какие шаги где работают: [Поддержка дистрибутивов](../distro-support.md).
:::

## Что пишется на диск {#output-on-disk}

Каждый запуск может записать локальный журнал. Пошаговый сценарий может также записать JSON-отчёт, а отладочный пакет создаётся по запросу или после неожиданного сбоя. Их размер зависит от запуска. Структура описана в разделе [Пути вывода](../reference/output-paths.md).
