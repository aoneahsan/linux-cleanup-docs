# Установка

**linux-cleanup доступен тремя способами: `npx` без установки, глобальная установка через `npm` или `git clone`.** Все три запускают один и тот же скрипт Bash: пакет npm — это тонкий загрузчик на Node, который находит `cleanup.sh` и направляет журналы и отчёты в постоянный каталог.

:::info Проверьте установленную версию
После установки или обновления выполните `linux-cleanup --version`. В [списке изменений](../changelog.md) записаны изменения пробного запуска и уведомлений о выпусках.
:::

## Вариант 1 — `npx`, без установки {#option-1--npx-no-install}

Самый быстрый способ попробовать. В ваш `PATH` ничего не попадает, и если вы передумаете, ничего не останется.

```bash
npx linux-cleanup --version
npx linux-cleanup --scan      # проверка только для чтения
npx linux-cleanup             # пошаговый сценарий
```

`npx` скачивает пакет во временный каталог кэша npm. Журналы и отчёты пишутся в `~/.linux-cleanup/`, **а не** во временный каталог, поэтому переживают очистку кэша npm и остаются на месте в следующий раз.

## Вариант 2 — глобальная установка через `npm` {#option-2--global-npm-install}

```bash
npm install -g linux-cleanup
linux-cleanup --version
```

После этого `linux-cleanup` доступен в `PATH` отовсюду. Журналы и отчёты по-прежнему идут в `~/.linux-cleanup/`.

```bash
npm install -g linux-cleanup@latest   # обновить
npm uninstall -g linux-cleanup        # удалить
```

Удаление пакета не удаляет установленный вами псевдоним оболочки или запись cron — полное удаление описано в разделе [Удаление](../guides/uninstall.md).

## Вариант 3 — `git clone` {#option-3--git-clone}

Чтобы читать исходный код, проверять его или менять. Содержимое репозитория — это то, что публикуется в npm.

```bash
git clone https://github.com/aoneahsan/linux-cleanup ~/linux-cleanup
cd ~/linux-cleanup
chmod +x cleanup.sh
./cleanup.sh --self-test
./cleanup.sh
```

Единственное отличие в поведении: **клон хранит вывод рядом с исходным кодом** — в `<clone>/logs/`, `<clone>/reports/` и `<clone>/feedback/`, а не в `~/.linux-cleanup/`. Оба расположения меняются через `LINUX_CLEANUP_DATA_HOME`. См. [Пути вывода](../reference/output-paths.md).

Проект распространяется по лицензии MIT, так что форки и изменения разрешены.

## Проверьте до любого удаления {#verify-before-you-run-anything-destructive}

```bash
linux-cleanup --version      # показывает, какая сборка у вас на самом деле
linux-cleanup --self-test    # проверка зависимостей, синтаксиса и защит
```

Успешная самопроверка заканчивается сообщением об успехе. Она проверяет, что [защита путей](../safety/guards.md#guard-1--the-path-allowlist) действительно отклоняет `/`, `$HOME`, `~/Documents`, `~/.ssh` и `/etc` и не отклоняет `~/.cache/yarn`. Любая неудачная проверка завершается ненулевым кодом.

:::tip Запускайте `--self-test` после каждого обновления
Это единственная проверка, которая работает на вашем реальном коде, а не на документации. Она занимает секунду.
:::

## Какой способ выбрать {#which-install-path-to-choose}

| Если вы… | Используйте |
|---|---|
| Хотите попробовать один раз | `npx` |
| Будете запускать регулярно или из cron | Глобальная установка через `npm` |
| Хотите читать или менять исходный код | `git clone` |
| Работаете на машине без Node.js | `git clone` |
| Хотите хранить вывод рядом с кодом | `git clone` |

Для cron лучше глобальная установка и **абсолютный путь** в crontab: cron работает с минимальным `PATH` и не найдёт установку в `~/.local/bin`. Это самая частая проблема с cron; см. [Псевдоним и cron](../guides/alias-and-cron.md).

## Чего установка не делает {#what-installing-does-not-do}

- Не создаёт системную службу, фоновый процесс или задание по расписанию (пока вы сами не попросите)
- Нет агента телеметрии. При запуске CLI, если есть сеть, получает одну публичную запись о выпусках; без сети продолжает работу
- Не меняет настройки оболочки, если вы не запустите `--install-alias` или `--doctor`
- Не создаёт файлов вне пакета и `~/.linux-cleanup/`, а последний — только когда вы действительно его запускаете
