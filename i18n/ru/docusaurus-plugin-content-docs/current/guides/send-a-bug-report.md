# Отправить отчёт об ошибке

**Две команды дают всё, что нужно сопровождающему.** Ничего не отправляется автоматически — вы просматриваете пакет и отправляете его сами.

```bash
linux-cleanup --debug-bundle    # упаковать последний журнал и запись сеанса
linux-cleanup --feedback        # инструкции и необязательный черновик mailto
```

## Быстрый путь {#the-quick-path}

```bash
linux-cleanup --debug-bundle
```

Создаёт `~/.linux-cleanup/feedback/debug-bundle-<timestamp>.tar.gz`, в котором:

- Последний журнал сеанса
- Последняя JSON-запись сеанса, если она есть
- `MANIFEST.txt` с дистрибутивом, ядром, версией bash и выводом самопроверки

Затем:

```bash
linux-cleanup --feedback
```

Подсказывает, что приложить, и предлагает открыть черновик `mailto:` с уже заполненными сведениями о системе.

## Просмотрите пакет перед отправкой {#review-the-bundle-before-sending-it}

:::caution В пакете есть пути с вашей машины
Не содержимое файлов — но журнал называет каждый затронутый путь, то есть имена каталогов, проектов, а иногда и файлов из `~/Downloads`.

Сначала посмотрите:

```bash
tar -tzf ~/.linux-cleanup/feedback/debug-bundle-*.tar.gz     # список содержимого
tar -xzOf ~/.linux-cleanup/feedback/debug-bundle-*.tar.gz    # прочитать целиком
```

Если там есть что-то личное, распакуйте пакет, удалите или замажьте файл и упакуйте заново — или отправьте только манифест и нужные строки.
:::

## Пакеты сбоя {#crash-bundles}

Начиная с [1.3.0](../changelog.md#130--2026-05-10), неожиданный выход с ненулевым кодом автоматически записывает `crash-<timestamp>.tar.gz` в тот же каталог и печатает путь.

В нём текущий журнал, последняя запись сеанса и манифест системы с кодом выхода.

**Пакет никуда не загружается.** Проверка выпусков читает публичный текстовый файл, но не отправляет ни пакетов, ни локальных путей. Пакет остаётся на вашем диске, пока вы не решите, делиться ли им.

При ожидаемом выходе пакеты сбоя **не** создаются: `0`, `130` (`Ctrl-C`), `143` (SIGTERM) и `2` (ошибка аргументов) исключены. См. [Коды выхода](../reference/exit-codes.md#how-the-crash-trap-decides).

## Что приложить {#what-to-include}

Хороший отчёт короткий и конкретный:

| Что приложить | Пример |
|---|---|
| Дистрибутив и версия | `lsb_release -d` |
| Версия Bash | `bash --version \| head -1` |
| Версия инструмента | `linux-cleanup --version` |
| Точная команда | `linux-cleanup --all-safe -y -d 30` |
| Ожидалось и получилось | «ожидал, что Gradle wrapper останется, а он удалён» |
| Пакет | Приложите tar.gz |

Самая ценная строка — **что ожидалось и что получилось**. Журнал сам по себе показывает, что произошло, но не то, почему вы считаете это ошибкой.

| Канал | Для чего |
|---|---|
| [GitHub issues](https://github.com/aoneahsan/linux-cleanup/issues) | Ошибки, запросы функций — предпочтительно, публично |
| [aoneahsan@gmail.com](mailto:aoneahsan@gmail.com) | Всё, что вы предпочли бы не публиковать |
| Pull request | У вас есть исправление. Лицензия MIT, форки приветствуются |

Запросы функций в виде описания приветствуются так же, как код. Расскажите, что бы вы хотели очищать и почему существующие режимы этого не охватывают.

## Ошибки, о которых стоит сообщить сразу {#bugs-worth-reporting-immediately}

Всё, что противоречит описанной модели безопасности:

- Удаление внутри [защищённого пути](../reference/protected-paths.md)
- Удалена *текущая* версия расширения редактора, а не только вытесненная
- Удалён файл новее `--days` без `--purge-all`
- Режим личных данных сработал без подтверждения
- Сетевой запрос, отправляющий локальные пути очистки или отчёты

Каждый такой случай — нарушение модели безопасности, а не просто неудобство.

## Конфиденциальность: что покидает вашу машину {#privacy-what-leaves-your-machine}

:::note Проверка выпусков и локальные отчёты
При запуске, если есть сеть, linux-cleanup читает по HTTPS одну публичную запись о выпусках. Он не загружает результаты сканирования, журналы и пакеты сбоя. Установка и обновление копии используют npm или GitHub.

Проверьте на клоне:

```bash
grep -rE 'curl|wget|http://|https://' cleanup.sh lib/ modules/ bin/
```

Запрос выпусков и команда, предлагаемая для более новой копии, — в `modules/update_check.sh`.
:::

Журналы, записи и пакеты — локальные файлы. Сопровождающий их не видит и не может отправить исправление на вашу машину: новая версия приходит, когда вы снова запускаете `npx` или обновляетесь.
