# Удаление

**Сначала уберите автоматизацию, затем пакет, затем данные.** Удаление пакета не удаляет установленный вами псевдоним оболочки или запись cron — это отдельные вещи.

## 1. Уберите автоматизацию {#1-remove-the-automation}

```bash
linux-cleanup --uninstall-alias
linux-cleanup --uninstall-cron
```

Сделайте это **до** удаления пакета, пока команда ещё есть. Если вы уже удалили его, см. [ручное удаление](#if-you-removed-the-package-first) ниже.

Проверьте:

```bash
crontab -l | grep -i cleanup     # вывода быть не должно
grep -rn 'cleanup' ~/.bash_aliases ~/.zshrc 2>/dev/null
```

## 2. Удалите пакет {#2-remove-the-package}

```bash
npm uninstall -g linux-cleanup
```

При использовании `npx` ничего не установлено — кэш npm сам избавится от пакета. Чтобы очистить его сейчас:

```bash
npm cache clean --force
```

Для git clone удалите каталог:

```bash
rm -rf ~/linux-cleanup
```

:::caution Клон хранит свои журналы и записи
В отличие от установок через npm, клон хранит вывод в `<clone>/logs/` и `<clone>/reports/`. Удаление клона удаляет и их. Скопируйте заранее то, что хотите сохранить. См. [Пути вывода](../reference/output-paths.md).
:::

## 3. Удалите данные {#3-remove-the-data}

Журналы, записи сеансов и пакеты обратной связи лежат в `~/.linux-cleanup/` и при удалении пакета **никогда** не удаляются.

```bash
ls -la ~/.linux-cleanup/           # посмотрите перед удалением
rm -rf ~/.linux-cleanup/
```

Они небольшие — обычно несколько мегабайт — и это единственное свидетельство того, что удаляли прошлые запуски. Хранить их ничего не стоит; удаление, как и любое другое, необратимо.

Если вы задавали `LINUX_CLEANUP_DATA_HOME`, удалите вместо этого тот каталог и уберите экспорт из настроек оболочки.

## 4. Удалите настройки, если создавали их {#4-remove-configuration-if-you-created-any}

```bash
rm -f ~/.config/personal-roots.txt ~/.config/project-roots.txt
```

Эти файлы есть, только если вы создали их сами. См. [Переменные окружения](../reference/environment-variables.md#configuring-the-scanned-roots).

## Если вы сначала удалили пакет {#if-you-removed-the-package-first}

Уберите обе вспомогательные настройки вручную.

**Cron:**

```bash
crontab -e
# удалите строку с linux-cleanup или cleanup.sh
```

**Псевдоним:**

```bash
grep -n 'cleanup' ~/.bash_aliases ~/.zshrc 2>/dev/null
```

Удалите найденную строку псевдонима в редакторе, затем выполните `source` для файла или откройте новый терминал.

## Что остаётся {#what-is-left-behind}

После всего этого — ничего. Инструмент не устанавливает системных служб, фоновых процессов, юнитов systemd, записей в `/etc` и файлов, принадлежащих root. Всё, что он создаёт, находится в вашем домашнем каталоге.

Изменения в системе, которые он не отменяет, потому что это не его файлы:

- **Удалённый кэш остаётся удалённым.** Он восстанавливается, когда понадобится каждому инструменту
- **Блоки инициализации оболочки, добавленные [`--doctor`](../modes/doctor.md),** остаются. Это правильная настройка для установленных у вас сред выполнения; если они не нужны, удалите их вручную

## Проверка {#verify}

```bash
command -v linux-cleanup      # вывода быть не должно
crontab -l | grep -i cleanup  # вывода быть не должно
ls ~/.linux-cleanup 2>&1      # ожидается: No such file or directory
```
