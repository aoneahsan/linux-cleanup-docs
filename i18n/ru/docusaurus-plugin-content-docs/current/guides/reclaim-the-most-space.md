# Освобождать место осознанно

**Сначала измерьте. Выберите самый узкий объём очистки, который решает найденную проблему.** Показанный размер корня кэша не обещает, что очистка может или должна удалить его целиком.

## 1. Найдите крупные пути {#1-find-the-large-paths}

```bash
linux-cleanup --audit
linux-cleanup --scan
```

`--audit` показывает крупные элементы в `$HOME`, включая то, что этот инструмент очищать не умеет. `--scan` перечисляет настроенные корни кэша и других кандидатов, ничего не удаляя. Если место в основном занято образом виртуальной машины, набором данных или игровой библиотекой, разберитесь с ними напрямую, а не запускайте посторонние режимы очистки.

## 2. Просмотрите обычный кэш {#2-preview-routine-caches}

```bash
linux-cleanup --all-safe --dry-run
```

Полностью безопасный режим по умолчанию прореживает подходящий кэш, который можно создать заново, после порога простоя в 100 дней. Предпросмотр проходит эти правила без удаления. Локальный журнал и состояние проверки обновлений всё же могут записаться.

Если каждый предлагаемый путь — то, что можно собрать или скачать заново, запустите `linux-cleanup --all-safe` и прочитайте его подтверждение. `--yes` — для запуска без присмотра, когда вы эту машину уже проверили.

## 3. Отдельно проверьте зависимости проектов {#3-review-project-dependencies-separately}

```bash
linux-cleanup --node-modules --dry-run
```

Режим зависимостей проектов интерактивен. Перед реальным удалением проверьте путь проекта и его lock-файл. Локальная правка внутри `node_modules` после переустановки зависимостей не вернётся.

## 4. Отдельно проверьте системное хранилище {#4-review-system-storage-separately}

```bash
linux-cleanup --system --dry-run
```

Полный системный режим использует apt и dpkg, поэтому он для Debian и Ubuntu. Он запрашивает sudo и включает очистку журнала, старые файлы в `/tmp` и необязательный шаг с кэшем страниц. Этот шаг влияет на RAM, а не на диск. См. [Очистка системы](../modes/system-cleanup.md).

## 5. Меняйте порог возраста только после нового предпросмотра {#5-change-the-age-threshold-only-after-another-preview}

`--days N` меняет, какие неиспользуемые файлы или целые единицы кэша подходят под очистку. Снижение со 100 до 30 может удалить то, чем вы пользовались недавно, поэтому сначала посмотрите пробный запуск с выбранным значением. `--purge-all` отключает защиту по возрасту; он может удалить дистрибутив Gradle или тестовый браузер, которые придётся скачать заново.

## 6. Личные файлы — отдельное решение {#6-keep-personal-files-as-a-separate-decision}

`--stale` показывает крупные давно не используемые личные файлы-кандидаты и спрашивает о каждом удалении. Старая загрузка может оказаться вашей единственной копией. `--yes` этот режим не разрешает. См. [Давно не используемые личные файлы](../modes/personal-stale-files.md) и [Удаление безвозвратно](../safety/irreversibility.md).

Сколько места освободится, зависит от машины и от других процессов, которые пишут на диск во время запуска. Прежде чем решать, нужен ли ещё один режим, посмотрите итоговый журнал и оставленные пути.
