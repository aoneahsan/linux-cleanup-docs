# Поддержка дистрибутивов

**Очистка кэшей домашнего каталога рассчитана на дистрибутивы Linux с нужными утилитами GNU.**
[`--system`](./modes/system-cleanup.md) использует пакетные команды Debian и Ubuntu. Перед очисткой проверьте установленные инструменты через `--self-test`.

## Кратко {#the-summary}

| Семейство дистрибутивов | Очистка кэшей в `$HOME` | `--system` |
|---|---|---|
| Debian, Ubuntu, Mint, Pop!\_OS | Полная | **Полная** |
| Fedora, RHEL, Rocky, Alma | С нужными утилитами | Не используйте: шаги apt завершаются сбоем |
| Arch, Manjaro, EndeavourOS | С нужными утилитами | Не используйте: шаги apt завершаются сбоем |
| openSUSE | С нужными утилитами | Не используйте: шаги apt завершаются сбоем |
| Alpine, минимальные контейнеры | Нужны Bash и утилиты GNU | Не используйте: шаги apt завершаются сбоем |
| WSL | С нужными утилитами | Только Debian/Ubuntu; сначала проверьте смонтированные пути |

:::warning `--system` не определяет дистрибутив
Шаги apt напрямую вызывают `apt` и `dpkg` без проверки `command -v` и без перехода на `dnf`, `pacman` или `zypper`. В системе не на базе Debian каждый шаг завершается с "command not found".

После сбоя apt режим не прерывается: последующие шаги всё равно могут выполниться. В других дистрибутивах не используйте его.

Некоторые описания этого инструмента утверждают, что `--system` поддерживает несколько дистрибутивов по уровням — с `dnf` вместо `apt` и `paccache` в Arch. **Такого кода нет.** Проверьте на клоне через `grep -rn 'dnf\|pacman\|zypper' modules/system_sudo.sh` — команда ничего не находит.
:::

## По шагам {#step-by-step}

| Шаг `--system` | Debian/Ubuntu | Fedora/RHEL | Arch | openSUSE |
|---|---|---|---|---|
| `apt autoremove` + `apt clean` | Работает | **Сбой** | **Сбой** | **Сбой** |
| `journalctl --vacuum-size=100M` | Работает | Работает | Работает | Работает |
| Отключённые ревизии snap | Работает | Если snap установлен | Если snap установлен | Если snap установлен |
| Список ядер (`dpkg --list`) | Работает | Молча — ничего не печатает | Молча | Молча |
| Файлы `/tmp` старше 7 дней | Работает | Работает | Работает | Работает |
| Сброс страничного кэша | Работает | Работает | Работает | Работает |

Шаги журнала, `/tmp` и страничного кэша опираются на `journalctl`, `find` и `sysctl`, которые ведут себя одинаково везде, где есть systemd. Шаг ядер в любом случае только выводит список, так что его сбой в системах без dpkg ничего не стоит.

## Пакетная часть своими руками {#doing-the-package-part-yourself}

В системе не на базе Debian следуйте рекомендациям по обслуживанию её собственного менеджера пакетов. Команды ниже — примеры, которые стоит прочитать перед запуском:

```bash
# Fedora / RHEL / Rocky
sudo dnf autoremove
sudo dnf clean all

# Arch / Manjaro  (paccache входит в pacman-contrib)
sudo pacman -Rns "$(pacman -Qtdq)"    # осиротевшие пакеты, если есть
sudo paccache -r                       # оставляет 3 последние версии
sudo pacman -Scc                       # очищает весь кэш пакетов

# openSUSE
sudo zypper clean --all
sudo zypper packages --orphaned
```

Для кэшей домашнего каталога сначала посмотрите, что найдёт linux-cleanup:

```bash
linux-cleanup --scan
linux-cleanup --all-safe --dry-run
```

## Кэши домашнего каталога {#home-cache-targets}

Пути в домашнем каталоге зависят от установленных инструментов, а не от дистрибутива. Набор отличается от машины к машине:

- Кэши менеджеров пакетов — yarn, npm, pnpm, pip, composer, bun, deno
- Кэши браузеров — Chrome, Firefox, Brave, Chromium, Edge, Vivaldi
- Кэши инструментов сборки — Gradle, Cypress, Playwright, TypeScript
- Данные инструментов разработчика — Android AVD, Flutter pub-cache, Dart, flatpak
- Расширения редакторов — VS Code, Cursor
- `node_modules`, недокачанные загрузки, давно не используемые личные файлы
- Сканирование, проверка, проверки безопасности и локальные журналы

## Минимальные контейнеры {#minimal-containers}

Alpine и другие минимальные образы обычно содержат BusyBox вместо GNU coreutils. Инструменту нужны GNU `find`, `du`, `stat` и особенно `realpath` — именно он разрешает символические ссылки перед [проверкой защищённых путей](./reference/protected-paths.md).

```bash
apk add coreutils findutils bash
linux-cleanup --self-test
```

`--self-test` называет первую недостающую зависимость. Пока он не пройдёт, не запускайте удаляющие режимы.

## WSL {#wsl}

Инструмент работает в среде Linux. Защита путей разрешает символические ссылки, но не считает личные папки Windows защищёнными папками Linux. Внимательно просмотрите сканирование и пробный запуск, если домашний каталог или кэши указывают в `/mnt/`.

## macOS {#macos}

Не поддерживается. Пакет npm объявляет `"os": ["linux"]` и откажется устанавливаться. Пути, флаги `find` и менеджеры пакетов — всё другое.
