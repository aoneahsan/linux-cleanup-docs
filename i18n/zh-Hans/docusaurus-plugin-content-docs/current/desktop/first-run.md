# 试运行、实际运行、清理回执

桌面应用中的每次清理都按相同顺序走相同的四步，哪一步都不能跳过。

## 首次启动 {#first-launch}

应用第一次打开时会显示三个简短的步骤：这个应用是什么、命令行始终拒绝哪些文件夹，以及可选的 **用 Google 登录**。每一步都可以跳过，并可从 **帮助** 中再次打开。清理从来不需要登录；登录会增加每月的实际运行次数，并在您的各台电脑之间保持运行次数（[账户与套餐](./accounts-and-plans.md)）。

登录会在您的浏览器中打开 Google。在那里完成后，浏览器会通过 `127.0.0.1` 把结果交还给应用，应用窗口随即接手。

## 1. 试运行 {#1-dry-run}

**开始试运行** 会以 `--dry-run` 运行全安全清理。它在任何地方都不删除任何东西。随后界面会列出清理将删除的每条路径、测得的大小及原因，以及命令行拒绝并保留的每条路径及原因。**将列表保存为 JSON** 会把这份列表写入这台电脑上的一个文件。

应用中的虚线按钮总是试运行。实线按钮会删除文件。

## 2. 确认 {#2-confirm}

**检查并运行** 会打开唯一能启动实际运行的界面。它会重复试运行的发现，说明您的套餐本月还剩多少次实际运行，并声明删除是永久的。在以下情况下，**立即运行清理** 不可用：

- 试运行已超过一天（请先重新运行）；
- 另一次运行仍在进行；
- 本月已没有剩余的实际运行次数。

## 3. 实际运行 {#3-real-run}

命令行每删除一条路径都会报告，界面会同步跟进。它在删除每条路径前都会再检查一次，所以自试运行以来发生变化的东西，会按它现在的状态判断。**此项完成后取消** 会在当前步骤结束后停止；已经删除的东西保持删除状态。

## 4. 清理回执 {#4-receipt}

每次运行都以一份清理回执结束，试运行也不例外：运行前后的可用空间、每一步标记为已完成、已跳过或失败，以及运行如何结束。被取消或中断的运行会把未完成的步骤列为失败。清理回执保存在这台电脑的 **清理回执与历史** 中，与命令行自己在 `~/.linux-cleanup/` 中的报告和日志放在一起。登录并使用带历史同步的套餐时，应用还会发送清理回执中的数字——绝不会发送路径或文件名（[什么会离开您的电脑](./overview.md#what-leaves-your-computer)）。
