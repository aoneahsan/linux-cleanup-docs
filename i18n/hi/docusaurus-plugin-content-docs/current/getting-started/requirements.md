# ज़रूरतें

**linux-cleanup `bash` 4 या नए और GNU coreutils वाले Linux पर चलता है।** बाकी सब वैकल्पिक है और न होने पर सलीके से कम हो जाता है।

## प्लैटफ़ॉर्म {#platform}

| | |
|---|---|
| **ऑपरेटिंग सिस्टम** | केवल Linux। npm पैकेज `"os": ["linux"]` घोषित करता है और दूसरी जगह इंस्टॉल होने से मना कर देगा |
| **शेल** | `bash` ≥ 4.0 |
| **Node.js** | ≥ 14 — **केवल** `npx` और `npm install -g` के लिए। git clone के लिए ज़रूरी नहीं |
| **अधिकार** | सामान्य उपयोगकर्ता के रूप में चलता है। केवल [`--system`](../modes/system-cleanup.md) `sudo` माँगता है |

macOS और WSL को अलग से समझना ठीक है:

- **macOS समर्थित नहीं है।** पथ, `find` फ़्लैग और पैकेज मैनेजर अलग हैं। उसके लिए एक सहयोगी टूल है; इसे Mac पर न चलाएँ।
- **WSL Linux की तरफ़ चलता है।** सफ़ाई से पहले `$HOME` से `/mnt/c/` में जाने वाले हर सिमलिंक की जाँच करें। [अनुमति-सूची](../reference/protected-paths.md) सिमलिंक हल करती है, पर उसके संरक्षित Linux होम पथों का मतलब यह नहीं कि हर Windows फ़ोल्डर संरक्षित है।

## ज़रूरी कमांड {#required-commands}

ये लगभग हर मुख्य डिस्ट्रो में होते हैं: `bash`, `find`, `du`, `df`, `rm`, `awk`, `sort`, `grep`, `sed`, `stat`, `realpath`।

`realpath` बाकियों से ज़्यादा अहम है: संरक्षित-पथ जाँच से पहले सिमलिंक यही हल करता है। GNU coreutils के बिना वाली छोटी कंटेनर इमेज पर चलाने से पहले इन्हें इंस्टॉल करें।

```bash
npx linux-cleanup --self-test
```

`--self-test` हर ज़रूरी कमांड परखता है और पहले ग़ायब कमांड का नाम, ठीक करने के सुझाव के साथ बताता है। कुछ भी हटाने वाला चलाने से पहले इसे चलाएँ।

## वैकल्पिक निर्भरताएँ {#optional-dependencies}

हर एक एक फ़ीचर खोलती है। उसके बिना वह फ़ीचर नहीं मिलता और टूल का बाकी हिस्सा अप्रभावित रहता है।

| निर्भरता | क्या खोलती है | इसके बिना |
|---|---|---|
| `jq` | Markdown / HTML [रिपोर्ट एक्सपोर्ट](../modes/reports.md) | JSON रिपोर्ट फिर भी लिखी जाती है; बदलना संभव नहीं |
| `whiptail` | विज़ुअल [TUI मेन्यू](../modes/tui.md) | `--tui` इंस्टॉल सुझाव के साथ CLI मेन्यू पर लौट जाता है |
| `dialog` | `whiptail` न होने पर TUI का विकल्प | ऊपर जैसा |
| `snap` | `--system` में बंद snap संशोधनों की सफ़ाई | वह चरण साफ़-साफ़ छोड़ दिया जाता है |
| `crontab` | [साप्ताहिक cron इंस्टॉलर](../guides/alias-and-cron.md) | `--install-cron` नहीं चल सकता |
| `numfmt` | पढ़ने लायक बाइट आकार | कच्ची बाइट गिनती पर लौट जाता है |
| `xdg-open` | HTML रिपोर्ट ब्राउज़र में खोलना | फ़ाइल ख़ुद खोलें |
| `less` | रिपोर्ट मैनेजर में पन्नों में JSON | फ़ाइल सीधे पढ़ें |
| `lsb_release` | फ़ीडबैक बंडल में बेहतर डिस्ट्रो पहचान | बंडल फिर भी बनता है |

### दो ज़रूरी चीज़ें इंस्टॉल करना {#installing-the-two-that-matter}

`jq` (रिपोर्ट एक्सपोर्ट) और `whiptail` (विज़ुअल मेन्यू) वही दो हैं जो ज़्यादातर लोग चाहते हैं।

```bash
# Debian / Ubuntu / Mint
sudo apt install jq whiptail

# Fedora / RHEL / Rocky
sudo dnf install jq newt

# Arch / Manjaro
sudo pacman -S jq libnewt

# openSUSE
sudo zypper install jq newt
```

RPM आधारित डिस्ट्रो पर `whiptail` बाइनरी `newt` पैकेज में आती है और Arch पर `libnewt` में।

## डिस्ट्रो कवरेज {#distro-coverage}

`$HOME` के भीतर कैश सफ़ाई — जो इस टूल से मिलने वाली जगह का बड़ा हिस्सा है — हर Linux डिस्ट्रीब्यूशन पर एक जैसी चलती है।

:::warning `--system` केवल Debian/Ubuntu पर
sudo मोड सीधे `apt` और `dpkg` चलाता है, न डिस्ट्रो की पहचान, न कोई जाँच। Fedora, Arch या openSUSE पर इसके पैकेज चरण "command not found" के साथ विफल होते हैं।

कौन-सा चरण कहाँ चलता है, इसका पूरा ब्योरा: [डिस्ट्रो समर्थन](../distro-support.md)।
:::

## डिस्क पर आउटपुट {#output-on-disk}

हर रन एक स्थानीय लॉग लिख सकता है। गाइडेड वॉकथ्रू JSON रिपोर्ट भी लिख सकता है, और माँगने पर या किसी अनपेक्षित विफलता के बाद एक डीबग बंडल बनता है। इनका आकार रन पर निर्भर है। बनावट के लिए [आउटपुट पथ](../reference/output-paths.md) देखें।
