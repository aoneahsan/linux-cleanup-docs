# इंस्टॉलेशन

**linux-cleanup तीन तरीकों से मिलता है: बिना इंस्टॉल `npx`, ग्लोबल `npm` इंस्टॉल, या `git clone`।** तीनों एक ही Bash स्क्रिप्ट चलाते हैं — npm पैकेज बस एक पतला Node लॉन्चर है जो `cleanup.sh` ढूँढता है और लॉग व रिपोर्ट को एक स्थायी फ़ोल्डर की ओर रखता है।

:::info इंस्टॉल किया गया संस्करण जाँचें
इंस्टॉल या अपग्रेड के बाद `linux-cleanup --version` चलाएँ। [बदलाव सूची](../changelog.md) ड्राई रन और रिलीज़ सूचनाओं में हुए बदलाव दर्ज करती है।
:::

## विकल्प 1 — `npx`, बिना इंस्टॉल {#option-1--npx-no-install}

इसे परखने का सबसे तेज़ तरीका। आपके `PATH` पर कुछ नहीं आता, और अगर आप इसे न अपनाएँ तो पीछे कुछ नहीं छूटता।

```bash
npx linux-cleanup --version
npx linux-cleanup --scan      # केवल-पढ़ने वाली जाँच
npx linux-cleanup             # गाइडेड वॉकथ्रू
```

`npx` पैकेज को एक अस्थायी npm कैश फ़ोल्डर में लाता है। आपके लॉग और रिपोर्ट `~/.linux-cleanup/` में लिखे जाते हैं — अस्थायी फ़ोल्डर में **नहीं** — इसलिए npm कैश साफ़ होने पर भी वे बचे रहते हैं और अगली बार भी मिलते हैं।

## विकल्प 2 — ग्लोबल `npm` इंस्टॉल {#option-2--global-npm-install}

```bash
npm install -g linux-cleanup
linux-cleanup --version
```

इसके बाद `linux-cleanup` हर जगह आपके `PATH` पर रहता है। लॉग और रिपोर्ट फिर भी `~/.linux-cleanup/` में जाते हैं।

```bash
npm install -g linux-cleanup@latest   # अपग्रेड
npm uninstall -g linux-cleanup        # हटाएँ
```

पैकेज अनइंस्टॉल करने से आपका लगाया शेल एलियास या cron प्रविष्टि नहीं हटती — पूरी तरह हटाने के लिए [अनइंस्टॉल](../guides/uninstall.md) देखें।

## विकल्प 3 — `git clone` {#option-3--git-clone}

सोर्स पढ़ने, जाँचने या बदलने के लिए। रिपॉज़िटरी की सामग्री वही है जो npm प्रकाशित करता है।

```bash
git clone https://github.com/aoneahsan/linux-cleanup ~/linux-cleanup
cd ~/linux-cleanup
chmod +x cleanup.sh
./cleanup.sh --self-test
./cleanup.sh
```

व्यवहार में एक ही अंतर है: **क्लोन अपना आउटपुट सोर्स के पास रखता है**, यानी `<clone>/logs/`, `<clone>/reports/` और `<clone>/feedback/` में, `~/.linux-cleanup/` में नहीं। दोनों को `LINUX_CLEANUP_DATA_HOME` से बदला जा सकता है। देखें [आउटपुट पथ](../reference/output-paths.md)।

प्रोजेक्ट MIT लाइसेंस के तहत है, इसलिए फ़ोर्क और बदलाव ठीक हैं।

## कुछ भी हटाने वाला चलाने से पहले जाँचें {#verify-before-you-run-anything-destructive}

```bash
linux-cleanup --version      # पुष्टि करता है कि आपके पास असल में कौन-सा बिल्ड है
linux-cleanup --self-test    # निर्भरता, सिंटैक्स और सुरक्षा जाँच
```

सफल स्व-परीक्षण एक पास संदेश के साथ ख़त्म होता है। यह पुष्टि करता है कि [संरक्षित-पथ जाँच](../safety/guards.md#guard-1--the-path-allowlist) सच में `/`, `$HOME`, `~/Documents`, `~/.ssh` और `/etc` को मना करती है, और `~/.cache/yarn` को मना नहीं करती। कोई भी पुष्टि विफल होने पर गैर-शून्य कोड के साथ बाहर निकलता है।

:::tip हर अपग्रेड के बाद `--self-test` चलाएँ
यही अकेली जाँच है जो दस्तावेज़ों पर नहीं, बल्कि आपके पास मौजूद असली कोड पर चलती है। इसमें एक सेकंड लगता है।
:::

## कौन-सा तरीका चुनें {#which-install-path-to-choose}

| अगर आप… | इस्तेमाल करें |
|---|---|
| एक बार आज़माना चाहते हैं | `npx` |
| इसे नियमित रूप से या cron से चलाएँगे | ग्लोबल `npm` इंस्टॉल |
| सोर्स पढ़ना या बदलना चाहते हैं | `git clone` |
| ऐसी मशीन पर हैं जिसमें Node.js नहीं है | `git clone` |
| आउटपुट सोर्स के पास चाहिए | `git clone` |

cron के लिए ग्लोबल इंस्टॉल बेहतर है और crontab में **पूरा पथ** इस्तेमाल करें — cron बहुत छोटे `PATH` के साथ चलता है और `~/.local/bin` का इंस्टॉल नहीं ढूँढ पाएगा। यह cron की सबसे आम समस्या है; देखें [एलियास और cron](../guides/alias-and-cron.md)।

## इंस्टॉल करना क्या नहीं करता {#what-installing-does-not-do}

- कोई सिस्टम सर्विस, बैकग्राउंड डेमन या शेड्यूल किया काम नहीं (जब तक आप न माँगें)
- कोई टेलीमेट्री एजेंट नहीं। शुरू होने पर, ऑनलाइन हो तो CLI एक सार्वजनिक रिलीज़ रिकॉर्ड लाता है; ऑफ़लाइन होने पर चलता रहता है
- जब तक आप `--install-alias` या `--doctor` न चलाएँ, शेल कॉन्फ़िगरेशन में कोई बदलाव नहीं
- पैकेज और `~/.linux-cleanup/` के बाहर कोई फ़ाइल नहीं, और दूसरा भी तभी बनता है जब आप इसे सच में चलाते हैं
