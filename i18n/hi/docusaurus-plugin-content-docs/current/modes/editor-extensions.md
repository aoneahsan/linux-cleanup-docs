# एडिटर एक्सटेंशन

**`--editor-ext` VS Code और Cursor के पुराने पड़ चुके एक्सटेंशन संस्करण हटाता है।** एक्सटेंशन अपडेट होने पर पुराने संस्करण का फ़ोल्डर अक्सर डिस्क पर रह जाता है। बहुत एक्सटेंशन और कुछ साल के अपडेट वाली मशीन पर यह सैकड़ों मेगाबाइट हो जाता है।

```bash
linux-cleanup --editor-ext
```

## दो शर्तें {#the-two-conditions}

कोई संस्करण फ़ोल्डर तभी उम्मीदवार है जब **दोनों** सच हों:

1. **उसी एक्सटेंशन का नया संस्करण मौजूद है** — मौजूदा संस्करण कभी उम्मीदवार नहीं होता
2. **वह पुराना संस्करण `--days` या ज़्यादा दिनों से निष्क्रिय है** (डिफ़ॉल्ट 100)

दूसरी शर्त [1.2.1](../changelog.md#121--2026-05-10) में जुड़ी। उससे पहले केवल नया संस्करण होना काफ़ी था, जिससे वे पुराने संस्करण भी हटते थे जो आपने हाल में लोड किए थे। आउटपुट हर संस्करण के निष्क्रिय दिन दिखाता है, ताकि आप देख सकें कि कुछ क्यों रखा गया।

## यह क्या नहीं छूता {#what-it-does-not-touch}

- किसी भी एक्सटेंशन का मौजूदा संस्करण
- एक्सटेंशन की सेटिंग्स, कीबाइंडिंग या वर्कस्पेस स्थिति
- `~/.config` में कुछ भी — वह पूरा ढाँचा [संरक्षित](../reference/protected-paths.md) है
- VS Code और Cursor के अलावा किसी दूसरे एडिटर के एक्सटेंशन

## चलाने के बाद {#after-running-it}

अगर VS Code ग़ायब एक्सटेंशन का बैनर दिखाए, तो विंडो फिर लोड करें: `Ctrl+Shift+P` → **Developer: Reload Window**। एडिटर ऐसे फ़ोल्डर का संदर्भ रखे है जो अब नहीं है।

अगर कोई एक्सटेंशन सच में चला गया — यानी "सबसे नए संस्करण" की पहचान ने मौजूदा संस्करण गलत पहचाना — तो उसे फिर इंस्टॉल करें और कृपया [बग रिपोर्ट करें](../guides/send-a-bug-report.md):

```bash
code --install-extension <publisher>.<name>
```

## कितनी जगह मिलने की उम्मीद {#expected-reclaim}

आकार इस मशीन पर इंस्टॉल पुराने संस्करणों पर निर्भर है। साफ़ करने का फ़ैसला करने से पहले मौजूदा फ़ोल्डर स्कैन से देखें।

## वॉकथ्रू और पूरी तरह सुरक्षित मोड में {#in-the-walkthrough-and-all-safe}

[गाइडेड वॉकथ्रू](./walkthrough.md) के चरण 4 के रूप में चलता है, और [`--all-safe`](./all-safe.md) में शामिल है, क्योंकि यह केवल दोबारा बन सकने वाली, पुरानी पड़ी प्रतियाँ हटाता है।
