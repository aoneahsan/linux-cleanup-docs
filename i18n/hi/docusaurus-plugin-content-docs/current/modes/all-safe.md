# पूरी तरह सुरक्षित (बैच)

**`--all-safe` एक ही बार में हर दोबारा बन सकने वाला कैश साफ़ करता है।** यह बिना देखरेख रखरखाव का मोड है और अकेला मोड जिस पर `--yes` लागू होता है।

```bash
linux-cleanup --all-safe        # पूरे बैच के लिए एक पुष्टि
linux-cleanup --all-safe -y     # कोई प्रॉम्प्ट नहीं — cron वाला रूप
```

## यहाँ "सुरक्षित" का मतलब {#what-safe-means-here}

सुरक्षित का मतलब है **दोबारा बन सकने वाला**: पैकेज मैनेजर कैश, ब्राउज़र और ऐप्लिकेशन कैश, और पुराना डेवलपर-टूल डेटा। इसका मतलब बिना जोखिम **नहीं**, और न ही पलटने लायक — हटाना फिर भी [स्थायी](../safety/irreversibility.md) है।

`--yes` हो या न हो, `--all-safe` इन्हें कभी नहीं छूता:

- `~/Downloads`, `~/Desktop` या कहीं और की निजी फ़ाइलें
- अधूरे डाउनलोड
- `node_modules` फ़ोल्डर
- [संरक्षित-पथ सूची](../reference/protected-paths.md) पर कुछ भी
- ग्लोबल इंस्टॉल पैकेज या शेल-इनिट फ़ाइलें

ये श्रेणियाँ [डिज़ाइन से केवल इंटरैक्टिव](../safety/guards.md#guard-3--personal-data-is-interactive-only) हैं और इस मोड का हिस्सा ही नहीं। इसी वजह से `--all-safe -y` को cron जॉब में रखना ठीक है।

1.1.0 से यह मोड एक **शुरुआती पुष्टि** भी चलाता है जो किसी संरक्षित रनटाइम फ़ोल्डर के लक्ष्य सूची में आ जाने पर `BUG:` संदेश के साथ रुक जाती है, ताकि भविष्य की कोई गड़बड़ी चुपचाप कुछ गलत हटाने के बजाय ज़ोर से विफल हो।

## `--yes` और उसकी सीमाएँ {#--yes-and-its-limits}

`-y` / `--yes` कैश हटाने की अपने आप पुष्टि करता है। यह केवल `--all-safe` के साथ मान्य है; इंटरैक्टिव मोड नीति से इसे अनदेखा करते हैं।

```bash
linux-cleanup --all-safe -y
```

:::caution `-y` का मतलब है कि फ़ैसले आपको बाद में ही दिखेंगे
अनुमति-सूची और निष्क्रियता जाँच फिर भी लागू रहती हैं, पर लॉग आप रन के बाद देखते हैं। अकेला पूरी तरह सुरक्षित रन वॉकथ्रू की JSON सत्र रिपोर्ट नहीं लिखता। पहले रन के लिए पहले एक [`--scan`](./scan.md) और एक `--all-safe --dry-run` देखें।
:::

## छँटाई, और क्या बचता है {#pruning-and-what-survives}

डिफ़ॉल्ट रूप से `--all-safe` उन योग्य कैश फ़ाइलों की छँटाई करता है जिनका `atime` और `mtime` दोनों `--days` (डिफ़ॉल्ट 100) से पुराने हों। खुले पैकेज और संस्करण वाले टूल अपने निष्क्रियता नियमों के तहत पूरी इकाई के रूप में सँभाले जाते हैं। पढ़ने वाला आउटपुट चुने हुए नतीजे बताता है; हटाने से पहले प्रस्तावित पथ देखने के लिए ड्राई रन इस्तेमाल करें।

```bash
linux-cleanup --all-safe -y            # 100 दिन की सीमा
linux-cleanup --all-safe -y -d 30      # ज़्यादा आक्रामक
linux-cleanup --all-safe -y --purge-all # जाँच बंद — पूरा मिटाना
```

:::danger cron जॉब में `--purge-all` ख़राब मेल है
बिना देखरेख और बिना निष्क्रियता जाँच का मतलब है कि Gradle wrapper वितरण या Playwright ब्राउज़र बंडल ज़रूरत से एक हफ़्ता पहले ग़ायब हो सकता है, और कोई देख भी नहीं रहा होगा। `--purge-all` को सोचे-समझे, सिस्टम दोबारा इंस्टॉल करने से पहले के रन के लिए रखें।
:::

## इसे हर हफ़्ते चलाना {#running-it-weekly}

```bash
linux-cleanup --install-cron
```

यह `--all-safe -y` को हर रविवार 03:00 के लिए तय करता है और आउटपुट `~/.linux-cleanup/logs/cron.log` में जोड़ता है। ठीक प्रविष्टि और उसे हटाने का तरीका [एलियास और cron](../guides/alias-and-cron.md) में देखें।

अगर crontab प्रविष्टि आप ख़ुद लिखें, तो **पूरा पथ** इस्तेमाल करें — cron का छोटा `PATH` `~/.local/bin` का इंस्टॉल नहीं ढूँढेगा:

```bash
0 3 * * 0 /usr/local/bin/linux-cleanup --all-safe -y --no-report --cleanup-logs >>~/.linux-cleanup/logs/cron.log 2>&1
```

`--cleanup-logs` उस रन का लॉग हटाता है। अकेले पूरी तरह सुरक्षित रन वॉकथ्रू का JSON सत्र रिकॉर्ड नहीं लिखते, इसलिए यहाँ `--no-report` का और कोई असर नहीं।

## cron रन ने क्या किया, यह देखना {#checking-what-a-cron-run-did}

```bash
tail -100 ~/.linux-cleanup/logs/cron.log
```

अगर cron लॉग `command not found` दिखाए, तो crontab बिना पथ का कमांड नाम इस्तेमाल कर रहा है — देखें [समस्या निवारण](../troubleshooting.md#cron-entry-runs-but-does-nothing)।
