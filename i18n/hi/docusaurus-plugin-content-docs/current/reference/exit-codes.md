# एग्ज़िट कोड

**linux-cleanup Unix परंपरा मानता है: `0` सफलता है, बाकी कुछ भी समस्या है।** कुछ गैर-शून्य कोड अपेक्षित हैं और जानबूझकर क्रैश नहीं माने जाते।

## कोड {#codes}

| कोड | मतलब | क्रैश बंडल |
|---|---|---|
| `0` | साफ़ रन। हर माँगी कार्रवाई पूरी हुई या मना की गई | नहीं |
| `1` | सामान्य विफलता — कोई अनिवार्य शर्त टूटी। कम होता है | हाँ |
| `2` | आर्ग्युमेंट पार्स करने की त्रुटि। मदद छपती है | नहीं |
| `3` | सार्वजनिक रिलीज़ रिकॉर्ड ने अपडेट ज़रूरी बताया | नहीं |
| `127` | कमांड नहीं मिला — कोई ज़रूरी निर्भरता ग़ायब है | हाँ |
| `130` | `Ctrl-C` (SIGINT) से रोका गया | नहीं |
| `137` | SIGKILL से मारा गया — आम तौर पर OOM killer या `kill -9` | हाँ |
| `139` | सेगफ़ॉल्ट। शुद्ध bash में नहीं होना चाहिए | हाँ |
| `143` | SIGTERM से बंद किया गया | नहीं |
| कोई और गैर-शून्य | अनपेक्षित भीतरी विफलता | हाँ |

अनजान फ़्लैग सफ़ाई से पहले `2` के साथ निकलता है। `--dry-run` समर्थित है; यह फ़ाइलें हटाए बिना चुने गए मोड से गुज़रता है। देखें [हटाने से पहले पूर्वावलोकन](../safety/preview-first.md)।

## क्रैश ट्रैप कैसे तय करता है {#how-the-crash-trap-decides}

[1.3.0](../changelog.md#130--2026-05-10) में जोड़ा गया EXIT ट्रैप इस क्रम में परखता है:

1. एग्ज़िट कोड `0` है, **या** स्क्रिप्ट ने अपना भीतरी पूर्णता संकेत लगाया → कोई बंडल नहीं
2. एग्ज़िट कोड `130` (`Ctrl-C`) या `143` (SIGTERM) है → कोई बंडल नहीं। उपयोगकर्ता का रोकना क्रैश नहीं है
3. एग्ज़िट कोड `2` (आर्ग्युमेंट पार्स) है → कोई बंडल नहीं। स्क्रिप्ट ने मदद छापकर जानबूझकर रोका
4. बाकी सब → `crash-<timestamp>.tar.gz` को `~/.linux-cleanup/feedback/` में लिखें

बंडल में चालू सत्र लॉग, सबसे हाल का JSON रिकॉर्ड और एक छोटा सिस्टम मैनिफ़ेस्ट होता है। यह आपकी मशीन पर रहता है — **कुछ नहीं भेजा जाता**। टूल पथ छापता है ताकि आप उसे देख सकें और तय कर सकें कि ईमेल करना है या नहीं।

देखें [बग रिपोर्ट भेजें](../guides/send-a-bug-report.md)।

## कोड के आधार पर शाखा {#branching-on-the-code}

```bash
if linux-cleanup --scan; then
  echo "स्कैन सफल रहा"
else
  case $? in
    2)   echo "गलत फ़्लैग" ;;
    127) echo "निर्भरता ग़ायब — --self-test चलाएँ" ;;
    130) echo "उपयोगकर्ता ने रोका" ;;
    *)   echo "अनपेक्षित विफलता — ~/.linux-cleanup/feedback/ देखें" ;;
  esac
fi
```

## cron में {#in-cron}

```bash
linux-cleanup --all-safe -y --no-report --cleanup-logs >>~/.linux-cleanup/logs/cron.log 2>&1 || \
  echo "linux-cleanup exited $?" | mail -s "cleanup failed on $(hostname)" you@example.com
```

cron जॉब से एग्ज़िट कोड `127` का मतलब लगभग हमेशा यह है कि crontab ने बिना पथ का कमांड नाम इस्तेमाल किया और cron का छोटा `PATH` उसे नहीं ढूँढ सका। पूरा पथ इस्तेमाल करें — देखें [समस्या निवारण](../troubleshooting.md#cron-entry-runs-but-does-nothing)।

## क्रैश बंडल से अनपेक्षित कोड की जाँच {#diagnosing-an-unexpected-code-from-a-crash-bundle}

बंडल का मैनिफ़ेस्ट एग्ज़िट कोड दर्ज करता है। आम कोड:

| कोड | आम कारण |
|---|---|
| `137` | आउट-ऑफ़-मेमोरी killer। आम तौर पर बहुत बड़े ढाँचे पर `find` |
| `141` | SIGPIPE — कोई पाइप जल्दी बंद हुआ, अक्सर `tee` या पेजर के निकलने से |
| `139` | सेगफ़ॉल्ट — यहाँ कभी नहीं होना चाहिए; रिपोर्ट करें |
| `127` | निर्भरता ग़ायब। पहचानने के लिए `--self-test` चलाएँ |
