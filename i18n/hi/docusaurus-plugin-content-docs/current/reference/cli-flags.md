# CLI फ़्लैग

**linux-cleanup जो भी फ़्लैग स्वीकार करता है।** मोड एक-दूसरे को छोड़ते हैं — एक ही दें। विकल्प किसी भी मोड के साथ जुड़ते हैं।

```bash
linux-cleanup --help    # यही सूची, आपकी मशीन के असली पथों के साथ
```

अनजान फ़्लैग मदद का पाठ छापता है और कोड `2` के साथ निकलता है।

## मोड {#modes}

ज़्यादा से ज़्यादा एक दें। कोई न दें तो [वॉकथ्रू](../modes/walkthrough.md) मिलता है।

| फ़्लैग | उपनाम | क्या करता है | पूरा पेज |
|---|---|---|---|
| _(कोई नहीं)_ | `-w` `--walkthrough` | दस निर्देशित चरण, हर एक से पहले पूछता है | [वॉकथ्रू](../modes/walkthrough.md) |
| `-m` | `--menu` `-i` `--interactive` | क्रमांक वाला, सीधे जाने वाला मेन्यू | [मेन्यू](../modes/menu.md) |
| `-t` | `--tui` `-g` `--gui` | दिखने वाला whiptail / dialog मेन्यू | [TUI](../modes/tui.md) |
| `-a` | `--all-safe` | हर दोबारा बनने वाले कैश की एक साथ सफ़ाई | [पूरी तरह सुरक्षित](../modes/all-safe.md) |
| `-s` | `--scan` | हर श्रेणी की केवल-पढ़ने वाली जाँच | [स्कैन](../modes/scan.md) |
| `-p` | `--stale` | बड़ी, पुरानी निजी फ़ाइलें (इंटरैक्टिव) | [पुरानी निजी फ़ाइलें](../modes/personal-stale-files.md) |

| | `--partials` | छूटे हुए अधूरे डाउनलोड (इंटरैक्टिव) | [अधूरे / अनाथ डाउनलोड](../modes/partial-downloads.md) |
| | `--audit` | `$HOME` की 20 सबसे बड़ी चीज़ें | [होम जाँच](../modes/home-audit.md) |
| | `--node-modules` | पुराने `node_modules` (इंटरैक्टिव) | [पुराने node_modules ढूँढें](../modes/node-modules-finder.md) |
| | `--globals` | ग्लोबल पैकेज की केवल-पढ़ने वाली जाँच | [ग्लोबल पैकेज जाँच](../modes/globals-audit.md) |
| | `--doctor` | रनटाइम के लिए ग़ायब शेल-इनिट ठीक करना | [डॉक्टर](../modes/doctor.md) |
| | `--speed` | दबाव और स्टार्टअप काम देखना; बदलाव से पहले पूछता है | [स्पीड जाँच](../modes/speed.md) |
| | `--editor-ext` | पुराने पड़ चुके VS Code / Cursor संस्करण | [एडिटर एक्सटेंशन](../modes/editor-extensions.md) |
| | `--reports` | इंटरैक्टिव सत्र रिकॉर्ड मैनेजर | [रिपोर्ट](../modes/reports.md) |
| | `--export FMT ID` | गैर-इंटरैक्टिव रिकॉर्ड रूपांतरण | [रिपोर्ट](../modes/reports.md#exporting) |
| | `--feedback` | बग रिपोर्ट के निर्देश, वैकल्पिक mailto मसौदा | [बग रिपोर्ट भेजें](../guides/send-a-bug-report.md) |
| | `--debug-bundle` | सबसे नया लॉग + रिकॉर्ड एक tar.gz में | [बग रिपोर्ट भेजें](../guides/send-a-bug-report.md) |
| | `--list-targets` | हर लक्ष्य बनने वाला और संरक्षित पथ छापता है | [हटाने से पहले पूर्वावलोकन](../safety/preview-first.md) |

## विकल्प {#options}

| फ़्लैग | डिफ़ॉल्ट | असर |
|---|---|---|
| `-d N` `--days N` | `100` | निष्क्रियता की सीमा। फ़ाइल तभी योग्य है जब `atime` और `mtime` **दोनों** इसे पार करें। कम मान ज़्यादा सख़्त है |
| `--purge-all` | बंद | **निष्क्रियता की रोक बंद करता है।** कैश लक्ष्य पूरे साफ़ होते हैं — 1.2.0 से पहले का व्यवहार |
| `-y` `--yes` | बंद | दोबारा बनने वाले कैश की अपने आप पुष्टि। केवल `--all-safe` के साथ मान्य। **निजी मोड इसे अनदेखा करते हैं** |
| `--no-report` | बंद | JSON नहीं बनाता। लॉग फिर भी लिखे जाते हैं |
| `--cleanup-logs` | बंद | अंत में इस रन का लॉग हटाता है। **रिकॉर्ड हमेशा रहते हैं** |
| `-n` `--dry-run` | बंद | फ़ाइलें हटाए या सेटिंग बदले बिना चुने गए मोड से गुज़रता है। स्थानीय लॉग रहता है; JSON सत्र रिपोर्ट नहीं लिखी जाती |
| `--json-events` | बंद | `--scan` या `--all-safe --yes` के लिए stdout पर [मशीन से पढ़े जाने वाले इवेंट](./json-events.md); पढ़ने वाला पाठ stderr पर |
| `--no-color` | बंद | ANSI रंग बंद करता है। `NO_COLOR` भी माना जाता है |
| `-h` `--help` | — | मदद छापकर निकलता है |

:::danger `--purge-all` एक सुरक्षा रोक हटाता है
यह [निष्क्रियता की रोक](../safety/guards.md#guard-2--the-staleness-gate) बंद करता है, इसलिए कैश पूरे साफ़ होते हैं, चाहे आख़िरी बार कभी भी इस्तेमाल हुए हों। महँगी चीज़ें — Gradle wrapper वितरण, Playwright ब्राउज़र, Cypress बाइनरी — भी साथ जाती हैं। रन से पहले का बैनर बताता है कि कौन-सी रणनीति चालू है।
:::

:::note स्कैन और ड्राई रन अलग सवालों के जवाब देते हैं
[`--scan`](../modes/scan.md) मौजूदा पथ और आकार पढ़ता है। `--dry-run` चुनी गई सफ़ाई से गुज़रता है और बिना हटाए प्रस्तावित कार्रवाइयाँ दिखाता है। देखें [हटाने से पहले पूर्वावलोकन](../safety/preview-first.md)।
:::

## नुस्ख़े {#recipes}

| लक्ष्य | कमांड |
|---|---|
| इंस्टॉल जाँचें | `linux-cleanup --self-test` |
| देखें कितनी जगह वापस मिल सकती है | `linux-cleanup --scan` |
| चुनी गई कैश सफ़ाई का पूर्वावलोकन | `linux-cleanup --all-safe --dry-run` |
| केवल-पढ़ने वाला स्कैन JSON इवेंट के रूप में | `linux-cleanup --scan --json-events` |
| हर पथ देखें जिसे यह छू सकता है | `linux-cleanup --list-targets` |
| निर्देशित सफ़ाई | `linux-cleanup` |
| एक बार में सब, बिना सवाल | `linux-cleanup --all-safe -y` |
| सख़्त सफ़ाई | `linux-cleanup --all-safe -y -d 30` |
| दोबारा इंस्टॉल से पहले ज़्यादा से ज़्यादा जगह | `linux-cleanup --all-safe -y --purge-all` |
| दिखने वाला मेन्यू | `linux-cleanup --tui` |
| पुराने प्रोजेक्ट के निर्भरता फ़ोल्डर | `linux-cleanup --node-modules -d 90` |
| सिस्टम रखरखाव | `linux-cleanup --system` |
| साप्ताहिक स्वचालन | `linux-cleanup --install-cron` |
| सबसे नया रिकॉर्ड HTML में बदलें | `linux-cleanup --export html latest` |
| बग दर्ज करें | `linux-cleanup --debug-bundle && linux-cleanup --feedback` |

## एनवायरनमेंट वेरिएबल {#environment-variables}

सबसे ज़्यादा इस्तेमाल होने वाले, [पूरी सूची](./environment-variables.md) अलग से:

| वेरिएबल | असर |
|---|---|
| `NO_COLOR` | कोई भी ख़ाली न होने वाला मान रंग बंद करता है |
| `LINUX_CLEANUP_LOG_DIR` | लॉग फ़ोल्डर बदलता है |
| `LINUX_CLEANUP_REPORTS_DIR` | सत्र रिकॉर्ड फ़ोल्डर बदलता है |
| `LINUX_CLEANUP_DATA_HOME` | लॉग, रिकॉर्ड और फ़ीडबैक बंडल का ऊपर वाला फ़ोल्डर |

## एग्ज़िट कोड {#exit-codes}

| कोड | मतलब |
|---|---|
| `0` | साफ़ रन |
| `2` | आर्ग्युमेंट पार्स त्रुटि या इवेंट स्ट्रीम में असमर्थित मोड |
| `3` | रिलीज़ रिकॉर्ड से रोका गया पुराना संस्करण |
| `130` | `Ctrl-C` से रोका गया |
| `143` | `SIGTERM` से बंद किया गया |
| अन्य | अनपेक्षित — क्रैश बंडल लिखता है |

पूरी तालिका और क्रैश ट्रैप का तर्क: [एग्ज़िट कोड](./exit-codes.md)।
