# संरक्षित पथ

**ये वे पथ हैं जिन्हें linux-cleanup हटाने से मना करता है।** इनकार बिना शर्त है — कोई फ़्लैग इसे नहीं बदलता, `--purge-all` भी नहीं।

जाँच से पहले हर उम्मीदवार `realpath` से सुलझाया जाता है, इसलिए किसी संरक्षित फ़ोल्डर की ओर इशारा करने वाला सिमलिंक लिंक के नहीं, सुलझे हुए पथ के आधार पर अस्वीकार होता है।

:::tip इस पेज पर भरोसा करने के बजाय अपने इंस्टॉल से जाँचें
सूचियाँ संस्करणों के बीच बदलती हैं, और इस टूल के बारे में ऐसे विवरण घूमते हैं जिनमें वे फ़ोल्डर भी हैं जो असल में संरक्षित **नहीं** हैं।

```bash
linux-cleanup --list-targets   # आपका बिल्ड जैसी सूचियाँ देखता है
linux-cleanup --self-test      # पक्का करता है कि रोक जाने-पहचाने पथों पर चलती है
```
:::

## तीन अलग सूचियाँ {#three-separate-lists}

रोक तीन सूचियों से बनी है जिनके मिलान के नियम अलग हैं। यह फ़र्क मायने रखता है — इसी से `~/.npm/_cacache` साफ़ हो पाता है जबकि `~/.npm` खुद अछूता रहता है।

| सूची | मिलान | उद्देश्य |
|---|---|---|
| संरक्षित पथ | पथ **और उसके नीचे सब कुछ** | निजी डेटा, क्रेडेंशियल, कॉन्फ़िगरेशन |
| सटीक संरक्षित | **केवल वही सटीक पथ** | पैकेज मैनेजर के इंस्टॉल रूट |
| संरक्षित फ़ाइल नाम | **उस नाम की कोई भी फ़ाइल, कहीं भी** | शेल-इनिट और इतिहास फ़ाइलें |

## सिस्टम रूट {#system-roots}

पथ या उसके किसी भी बच्चे के रूप में अस्वीकार, जहाँ अलग से न लिखा हो।

| पथ | बच्चे भी अस्वीकार |
|---|---|
| `/` | — (रूट खुद) |
| `/home` | नहीं — केवल सटीक पथ |
| `/root` | नहीं — केवल सटीक पथ |
| `/etc` | **हाँ** |
| `/boot` | **हाँ** |
| `/usr` | **हाँ** |
| `/var` | नहीं — केवल सटीक पथ |
| `/lib` | नहीं — केवल सटीक पथ |
| `/sbin` | नहीं — केवल सटीक पथ |
| `/bin` | नहीं — केवल सटीक पथ |
| `$HOME` | नहीं — होम रूट खुद, ताकि अकेला `$HOME` कभी साफ़ न हो |

:::note `/proc` और `/sys` इस सूची में नहीं हैं
कोई सफ़ाई लक्ष्य उनके पास भी नहीं जाता, पर अनुमति सूची उनका नाम साफ़ नहीं लेती। इस टूल के कुछ विवरण कहते हैं कि लेती है। ऐसा नहीं है।
:::

## निजी फ़ोल्डर {#personal-directories}

उनके भीतर की हर चीज़ के साथ अस्वीकार।

| पथ | क्या रखता है |
|---|---|
| `~/Documents` | दस्तावेज़ |
| `~/Pictures` | तस्वीरें |
| `~/Music` | ऑडियो |
| `~/Videos` | वीडियो |
| `~/Desktop` | डेस्कटॉप की सामग्री |
| `~/Public` | साझा फ़ाइलें |
| `~/Templates` | दस्तावेज़ टेम्पलेट |

:::caution `~/Downloads` जानबूझकर संरक्षित **नहीं** है
हो भी नहीं सकता — वहाँ की बड़ी, लंबे समय से पड़ी फ़ाइलें साफ़ करना एक सुविधा है ([पुरानी निजी फ़ाइलें](../modes/personal-stale-files.md))। इसकी रक्षा [रोक 3](../safety/guards.md#guard-3--personal-data-is-interactive-only) करती है: केवल इंटरैक्टिव, हर फ़ाइल की पुष्टि, और `--yes` अनदेखा।

अगर आप `~/Downloads` में कुछ ऐसा रखते हैं जिसकी जगह कुछ नहीं ले सकता, तो उसे किसी संरक्षित फ़ोल्डर में ले जाएँ। यही टिकाऊ हल है।
:::

## क्रेडेंशियल, कॉन्फ़िगरेशन और एजेंट की स्थिति {#credentials-configuration-and-agent-state}

| पथ | क्या रखता है |
|---|---|
| `~/.ssh` | SSH कुंजियाँ और ज्ञात होस्ट |
| `~/.gnupg` | GPG कीरिंग |
| `~/.config` | ऐप्लिकेशन कॉन्फ़िगरेशन (बहुत व्यापक) |
| `~/.gnome` | GNOME सेटिंग्स |
| `~/.mozilla` | Firefox प्रोफ़ाइल |
| `~/.thunderbird` | Thunderbird प्रोफ़ाइल |
| `~/.claude` | Claude Code की स्थिति |
| `~/.local/share/claude` | Claude Code का डेटा |

:::danger दो पथ जिन्हें अक्सर संरक्षित बताया जाता है, संरक्षित **नहीं** हैं
**`~/.password-store`** (pass) और **`~/.aws`** (AWS क्रेडेंशियल) स्रोत की संरक्षित सूची में **नहीं** हैं। इस टूल के कुछ लेख कहते हैं कि हैं।

व्यवहार में कोई सफ़ाई लक्ष्य इनकी ओर इशारा नहीं करता, इसलिए सामान्य इस्तेमाल में दोनों को ख़तरा नहीं — पर इनकी रक्षा के लिए अनुमति सूची पर भरोसा न करें। यह गारंटी चाहिए तो पहले अपने इंस्टॉल पर `--list-targets` से जाँचें।
:::

ध्यान दें कि `~/.mozilla` के संरक्षित होने से Firefox कैश की सफ़ाई नहीं रुकती: कैश `~/.cache/mozilla` में रहता है, जो एक अलग ढाँचा है।

## सटीक मिलान वाले संरक्षित पथ {#exact-match-protected-paths}

**सटीक** मिलान — बच्चे साफ़ किए जा सकते हैं। इसी से आपके ग्लोबल इंस्टॉल पैकेज बचे रहते हैं, जबकि हर इंस्टॉल रूट के भीतर का दोबारा बनने वाला कैश छाँटा जा सकता है।

| इकोसिस्टम | पथ |
|---|---|
| pnpm | `~/.local/share/pnpm` और उसके `global`, `bin`, `nodejs` |
| npm | `~/.npm`, `~/.npm-global`, `~/.npm-global/lib`, `~/.npm-global/lib/node_modules` |
| yarn | `~/.yarn`, `~/.config/yarn/global` |
| bun | `~/.bun`, `~/.bun/install`, `~/.bun/install/global` और उसका `node_modules`, `~/.bun/bin` |
| deno | `~/.deno`, `~/.deno/bin` |
| Node संस्करण मैनेजर | `~/.volta`, `~/.volta/bin`, `~/.nvm`, `~/.nvm/versions`, `~/.fnm` |
| Rust | `~/.cargo`, `~/.cargo/bin`, `~/.rustup` |
| Go | `~/go`, `~/go/bin` |

यह सूची एक असली ख़राबी की वजह से है: [1.1.0](../changelog.md#110--2026-05-10) से पहले pnpm सफ़ाई का लक्ष्य `~/.local/share/pnpm` था — इंस्टॉल रूट — और उसने `pnpm` बाइनरी समेत ग्लोबल इंस्टॉल पैकेज हटा दिए। सुधार ने लक्ष्य को `~/.local/share/pnpm/store` तक सीमित किया और यह सूची जोड़ी ताकि गलती दोबारा न हो।

[`--all-safe`](../modes/all-safe.md) शुरू होते समय यह भी पक्का करता है कि इनमें से कोई उसकी लक्ष्य सूची में कभी न आए; आए तो `BUG:` संदेश के साथ रुक जाता है।

## संरक्षित फ़ाइल नाम {#protected-basenames}

**फ़ाइल नाम से, किसी भी जगह** अस्वीकार, चाहे वहाँ तक पहुँचने वाला पथ कुछ भी हो:

`.bashrc` · `.bash_profile` · `.bash_login` · `.profile` · `.bash_logout` · `.zshrc` · `.zshenv` ·
`.zprofile` · `.zlogin` · `.zlogout` · `.bash_aliases` · `.bash_history` · `.zsh_history` · `.inputrc` ·
`.dircolors` · `.config` · `.local`

यह आख़िरी बचाव है। यह इसलिए है कि भविष्य का कोई बग अगर किसी तरह शेल-इनिट फ़ाइल को लक्ष्य सूची में डाल दे, तब भी उसे हटा न सके।

## इनकार कैसा दिखता है {#what-a-refusal-looks-like}

```text
✗ REFUSE: protected path: /home/you/Documents/notes
✗ REFUSE: unsafe path: '/home/you'
✗ REFUSE: shell-init / history file: /home/you/.bashrc
```

इनकार सही व्यवहार है, कोई त्रुटि नहीं जिससे बचकर निकलना हो। अगर आप जो कैश साफ़ करवाना चाहते हैं वह अस्वीकार हो रहा है, तो वजह लगभग हमेशा किसी संरक्षित जगह पहुँचने वाला सिमलिंक होती है — सिमलिंक ठीक करें, टूल नहीं। देखें [समस्या निवारण](../troubleshooting.md#refuse-protected-path)।
