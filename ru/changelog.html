Журнал изменений

История выпусков linux-cleanup. Формат следует Keep a Changelog, проект использует семантическое версионирование.

Текущую опубликованную версию смотрите в пакете npm. Полную историю ведёт журнал изменений в исходниках. Записи ниже объясняют изменения, которые влияют на решение об очистке.

2.1.1 — 2026-11-22​

--help, --version, окно «О программе» в меню и экран обратной связи показывают сайт, это руководство и страницу загрузки настольного приложения. credits.tool_homepage в отчёте о запуске теперь указывает на сайт продукта. Окно «О программе» больше не утверждает, что скрипт не обращается к сети: при запуске он один раз читает публичную запись о выпусках. Что удаляет каждый режим — не изменилось.

2.1.0 — 2026-11-21​

--json-events выдаёт локальные версионированные JSON-события для --scan и неинтерактивного --all-safe --yes. С --dry-run полностью безопасная очистка сообщает предлагаемые пути, не удаляя их. Поток может содержать полные локальные пути, поэтому держите его на машине.

2.0.1 — 2026-11-21​

README перечисляет все места, где выходит linux-cleanup. Поведение скрипта не изменилось.

2.0.0 — 2026-11-10​

Добавлены --dry-run, проверка публичной записи о выпусках при запуске и --refresh-app для постоянной копии CLI. Обычные уведомления о выпуске пропускают первый запуск и блокируют со следующего; срочные блокируют старую копию сразу. Без сети запуск продолжается. Пробный запуск не удаляет цели очистки и не меняет настроек, хотя может записать локальный журнал и состояние проверки обновлений.

1.6.0 — 2026-09-18​

Добавлены диагностика --speed только для чтения и настраиваемые корни поиска для проектов и личных файлов. Исправлено определение простоя на файловых системах с noatime: старые выпуски могли удалить ещё используемый кэш, потому что время доступа не записывалось. Установка псевдонима и cron теперь указывает на постоянную копию, а очистка журналов удаляет только журнал текущего запуска.

1.5.2 — 2026-09-18​

Недавние отключённые ревизии Snap сохраняются как копии для отката; --node-modules больше не показывает внутренности Yarn PnP.

1.5.1 — 2026-09-18​

Очистка распакованных кэшей пакетов и браузеров теперь идёт по целым элементам, чтобы редко используемый файл не удалялся из установки, которая в остальном активна.

1.5.0 — 2026-09-18​

Очистка кэшей Gradle и Android Studio теперь работает с целыми единицами версий; исправлены определение давно не используемых node_modules и его отдельный барьер удаления. Прежняя очистка в 1.4.0/1.5.0 могла оставить распакованный кэш неполным; шаги восстановления — в журнале изменений исходников.

1.4.0 — 2026-07-11​

Изменено​

  • Лицензия заменена на MIT. Раньше программа распространялась под собственной лицензией «Source-Available · No-Derivatives · Non-Commercial v1.0». Теперь это свободная разрешительная лицензия, одобренная OSI: использовать, изменять, форкать, распространять и применять в коммерции можно бесплатно, с указанием авторства.

    Отказ от ответственности MIT «AS IS / без ответственности» заменяет прежние условия о гарантиях, ответственности и возмещении. package.json теперь объявляет "license": "MIT".

    Это действует с этого момента — выпуски, опубликованные раньше, сохраняют свою лицензию.

Код, защитные барьеры и CLI не изменились.

1.3.1 — 2026-05-10​

Выпуск только с документацией. Поведение не изменилось.

Добавлено​

  • Полный каталог docs/, построенный по схеме Diátaxis: руководства, практические инструкции, справка и пояснения. Описаны все режимы, флаги, пути вывода и коды выхода.
  • Отдельные страницы для всех шестнадцати режимов, справочные страницы по флагам, режимам, переменным окружения, путям вывода, кодам выхода и схеме JSON, а также практические рецепты и FAQ.
  • Раздел «Полная документация» в README со ссылками на самые нужные страницы.

Код, защитные барьеры и интерфейс CLI — те же, что в 1.3.0.

1.3.0 — 2026-05-10​

Завершающий выпуск: визуальное меню и автоматический сбор данных о сбоях. Новой логики очистки нет; защитные барьеры и пороги простоя не изменились.

Добавлено​

  • Режим TUI (-t / --tui / -g / --gui) — меню на whiptail или dialog. Каждый выбор на время запуска возвращает обычный вывод CLI, а затем снова меню. Если нет ни одного из инструментов, аккуратно переходит на меню CLI с подсказкой по установке для дистрибутива.

  • Автоматический сбор пакета сбоя — обработчик EXIT, который при неожиданном ненулевом выходе пишет в ~/.linux-cleanup/feedback/ самодостаточный crash-<stamp>.tar.gz с журналом сеанса, последней записью и манифестом системы, а затем печатает строку, которую можно отправить по почте.

    Не создаётся при чистом выходе, Ctrl-C (130), SIGTERM (143) и выходе из-за ошибки аргументов (2). Никаких сетевых запросов — пакет остаётся на вашей машине, пока вы не решите им поделиться.

  • Окно «О программе» в TUI с версией, контактами, лицензией и обещанием конфиденциальности.

Изменено​

  • Подавление баннера и итогов сеанса теперь распространяется и на режим tui, чтобы окно не конфликтовало с выводом журнала.

1.2.2 — 2026-05-10​

Исправлено​

  • Мелкие исправления ошибок и улучшения внутренней стабильности.

1.2.1 — 2026-05-10​

Распространяет порог простоя из 1.2.0 на всё, что является инструментом, а не восстанавливаемым кэшем. Удаление такого теперь требует одновременно: чтобы от него не зависела активная программа и чтобы вы не трогали его --days дней.

Изменено​

  • Android AVD — раньше ~/.android/avd после подтверждения стирался целиком. Теперь каждый каталог *.avd проверяется как единое целое вместе с соседним *.ini и очищается, только если каждый файл профиля простаивает дольше порога. Недавно использованные профили эмулятора остаются нетронутыми.
  • Вытесненные расширения VS Code / Cursor — проверка «есть более новая версия» покрывала первое условие; теперь вытесненный каталог должен ещё и простаивать дольше порога. Недавно загружавшиеся старые версии показываются, но сохраняются, с числом дней простоя для каждой.
  • Пользовательские данные Flatpak — в ~/.local/share/flatpak лежат установленные пользовательские приложения, а не только кэши. Модуль теперь отказывается трогать это дерево, если установлено хоть одно пользовательское приложение, и вдобавок требует, чтобы дерево простаивало дольше порога. Для более безопасного пути предлагает flatpak uninstall --user --unused.

Добавлено​

  • newest_access_age_days <path> — возвращает число дней с самого свежего atime/mtime в любом месте под путём.
  • prune_stale_units <root> <days> [glob] — считает каждый элемент верхнего уровня неделимым, чтобы частичная очистка не испортила состояние.

Зачем​

Пользователь заметил, что 1.2.0 по-прежнему целиком стирает Android AVD, и что то же рассуждение должно касаться всего, что является инструментом, а не кэшем: не удалять программу, от которой зависит другой инструмент, и программу, которой сам пользователь недавно пользовался.

1.2.0 — 2026-05-10​

По умолчанию удаляется только то, чем давно не пользовались. Внутри целевого кэша ничего не удаляется, пока его файлы не простоят нетронутыми — и по atime, и по mtime — --days дней, по умолчанию 100.

Изменено​

  • clean_target, общий очиститель всех модулей кэша, теперь прореживает, а не стирает всё. Он удаляет только файлы старше порога, затем убирает пустые каталоги. Недавно использованные файлы остаются, остаётся и сама структура каталогов, чтобы инструменты находили свою раскладку.
  • --all-safe прореживает каждую цель так же, а его итоги показывают по каждой цели освобождённые и сохранённые байты.
  • Очистка кэша npm учитывает порог простоя, а не всегда запускает npm cache clean --force, который полностью игнорировал возраст.
  • Баннер перед запуском показывает действующую стратегию — «prune ≥Nd» или «FULL PURGE».

Добавлено​

  • --purge-all возвращает поведение до 1.2.0 — стереть всё; компромисс описан в документации.
  • prune_stale <root> <days> — общедоступная вспомогательная функция для модулей: отклоняет защищённые пути, удаляет только там, где обе отметки времени старше порога, убирает пустые каталоги и сообщает освобождённые байты.

Зачем​

По умолчанию 1.1.0 после подтверждения удалял деревья кэша целиком. Для быстро восстанавливаемого ~/.cache/yarn это было правильно, а для ~/.gradle/wrapper/dists/ — нет: это загрузка на 230 МБ, которая вполне может понадобиться в следующем месяце.

Порог в 100 дней чётко отделяет «трогал недавно и пожалею» от «не открывал три месяца». Опытные пользователи по-прежнему могут вернуть старое поведение или ужесточить порог через -d 30.

1.1.0 — 2026-05-10​

Выпуск для усиления безопасности. Закрывает возможность затронуть глобально установленные пакеты и файлы инициализации оболочки.

Исправлено​

  • Глобальные пакеты pnpm стирались. Очистка хранилища содержимого pnpm была нацелена на ~/.local/share/pnpm (PNPM_HOME), где лежат глобально установленные пакеты, ярлыки bin и сам бинарный файл pnpm из pnpm setup. Теперь цель — только ~/.local/share/pnpm/store, восстанавливаемый кэш с адресацией по содержимому.

    Затрагивало --all-safe, пункт меню 3, сканирование, пошаговый сценарий и --list-targets.

Добавлено — защитные барьеры​

  • PROTECTED_EXACT — блок по точному совпадению для каталогов установки менеджеров пакетов и домашних каталогов сред выполнения: pnpm, npm, yarn, bun, deno, volta, nvm, fnm, cargo, rustup и Go.
  • PROTECTED_BASENAMES — отклоняет любой путь, имя которого — файл инициализации или истории оболочки, где бы он ни лежал.
  • Проверка при запуске --all-safe, которая прерывается с сообщением BUG:, если защищённый каталог среды выполнения попадёт в список целей, чтобы не допустить незаметной регрессии.

Добавлено — поддержка bun и deno​

  • bun: очистка кэша в ~/.bun/install/cache; ~/.bun/install/global защищён.
  • deno: очистка кэша в ~/.cache/deno; ~/.deno/bin защищён.
  • Оба подключены к --all-safe, --scan и новой проверке глобальных пакетов.

Добавлено — режимы​

  • --globals — проверка только для чтения: перечисляет глобальные пакеты, установленные напрямую через npm, pnpm, yarn, bun и deno, помечает каждый как recently used, needed by: <pkg> или STALE — safe to uninstall и печатает готовые к копированию команды удаления. Никогда ничего не удаляет. Работает, даже если CLI менеджера пакетов нет в PATH.
  • --doctor — находит среду выполнения, которая есть на диске, но не подключена в инициализации оболочки (nvm, pnpm, bun, deno, cargo), и предлагает дописать стандартный блок. Только дописывает, с подтверждением. Существующие строки никогда не удаляет и не меняет.

Изменено​

  • --all-safe явно печатает уведомления «globals are PRESERVED» и «shell-init files are NEVER touched».

1.0.0 — 2026-05-09​

Первый публичный выпуск.

Распространение​

  • Опубликован в npm — запускается через npx linux-cleanup или npm install -g linux-cleanup. В пакете — тонкий запускатель на Node, который находит точку входа bash и направляет журналы и записи в ~/.linux-cleanup/, чтобы они пережили очистку временного каталога npx.
  • Поддерживается и прямой git clone, вывод тогда остаётся внутри клона.

Возможности​

  • Пошаговый сценарий из десяти шагов как режим по умолчанию: заголовки прогресса, вопросы a / s / q, освобождённые байты на каждом шаге и нарастающий итог.
  • Безопасность на основе списка разрешённых путей — отклоняется любой путь из тщательно составленного защищённого списка, а также голые $HOME и /.
  • Личные данные — только интерактивно: никогда пакетом, никогда через --yes.
  • Категории очистки — кэши менеджеров пакетов (yarn, npm, pnpm, pip, composer); кэши приложений (Chrome, Firefox, Brave, Chromium, Edge, Vivaldi, Gradle, Cypress, Playwright, TypeScript, Zoom); инструменты разработчика (Android AVD, pub-cache, Dart, flatpak); расширения редакторов; давно не используемые node_modules; недокачанные загрузки и давно не используемые личные файлы; очистка системы через sudo.
  • Записи сеансов — стандартный JSON при каждом запуске, экспорт в Markdown и HTML по запросу. HTML использует встроенный CSS с поддержкой тёмной темы.
  • Менеджер отчётов (--reports) и неинтерактивный --export FMT ID.
  • Самопроверка (--self-test): зависимости, синтаксис каждого файла оболочки и исправность защитных барьеров — с проверкой, что защита возвращает true для /, $HOME, ~/Documents и /etc.
  • --feedback и --debug-bundle для структурированных отчётов об ошибках.
  • Конфиденциальность — ноль сетевых запросов. Никакой телеметрии, аналитики или отправки сбоев. Единственные данные, которые покидают вашу машину, — те, что вы сами решите отправить по почте.
  • Указание авторства в каждом файле — журналы начинаются с заголовка о происхождении, в записях есть блок credits верхнего уровня, в HTML — подпись в подвале.
  • Помощники настройки — --install-alias, --install-cron и парные команды удаления.
  • Поддержка NO_COLOR и --no-color.

Безопасность и защита​

  • HTML-вывод экранирует все значения из JSON фильтром @html из jq, чтобы повреждённая запись не могла вызвать внедрение.
  • Проверки command -v для каждой необязательной зависимости (snap, crontab, xdg-open, jq).
  • realpath -m разрешает символические ссылки перед любой проверкой защищённых путей, так что ссылка не может обойти список разрешённых.
