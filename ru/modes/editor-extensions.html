Расширения редакторов

--editor-ext удаляет вытесненные версии расширений VS Code и Cursor. После обновления расширения каталог старой версии часто остаётся на диске. На машине с большим количеством расширений и несколькими годами обновлений это набирает сотни мегабайт.

linux-cleanup --editor-ext

Два условия​

Каталог версии становится кандидатом, только если выполнены оба условия:

  1. Есть более новая версия того же расширения — текущая версия кандидатом не бывает никогда
  2. Старая версия простаивает --days дней или дольше (по умолчанию 100)

Второе условие появилось в 1.2.1. До этого хватало одного вытеснения, и удалялись старые версии, которые вы недавно загружали. В выводе указано число дней простоя по каждой версии, так что видно, почему что-то оставлено.

Что он не трогает​

  • Текущую версию любого расширения
  • Настройки расширений, сочетания клавиш и состояние рабочей области
  • Ничего в ~/.config — всё это дерево защищено
  • Расширения редакторов, кроме VS Code и Cursor

После запуска​

Если VS Code показывает уведомление об отсутствующем расширении, перезагрузите окно: Ctrl+Shift+P → Developer: Reload Window. Редактор держит ссылку на каталог, которого больше нет.

Если расширение действительно пропало — это значит, что определение «самой новой версии» ошиблось с текущей, — переустановите его и, пожалуйста, сообщите об ошибке:

code --install-extension <publisher>.<name>

Сколько можно освободить​

Размер зависит от вытесненных версий, установленных на этой машине. Прежде чем решать, очищать ли каталог, посмотрите его текущее состояние сканированием.

В пошаговом сценарии и полностью безопасном режиме​

Выполняется на шаге 4 пошагового сценария и входит в --all-safe, поскольку удаляет только вытесненные копии, которые можно создать заново.
